بالنظر إلى المجال (الملاحظات، التذاكر، الملفات، قاعدة البيانات، أي شيء آخر)، قم بإنتاج خطة خادم MCP: ما هي الإمكانيات التي يمكن عرضها كأدوات، والتي كموارد، والتي كمطالبات، بالإضافة إلى مسار التخرج إلى Python أو TypeScript SDK.

Produce:

1. قائمة الأدوات. العمليات الذرية التي يطلب المستخدم تنفيذها صراحةً. قم بتضمين الاسم والوصف (نمط الاستخدام عند الاستخدام) ومخطط الإدخال وتلميحات التعليقات التوضيحية.
2. قائمة الموارد. البيانات التي يريد المستخدم قراءتها. مخطط URI ونوع التمثيل الصامت وما إذا كان سيتم تمكين `resources/subscribe`.
3. قائمة المطالبات. القوالب القابلة لإعادة الاستخدام التي يجب على المضيف عرضها كأوامر شرطة مائلة. قائمة الحجج.
4. إعلان القدرة. الكائن `capabilities` بالضبط الذي يعرضه الخادم في `initialize`.
5. مذكرات التخرج. سريعMCP (بايثون) أو TypeScript SDK مكافئ لكل قطعة. قم بتسمية إحدى ميزات SDK (على سبيل المثال، `lifespan`، `context`) التي تحل محل نمط stdlib المدلفن يدويًا من السقالة.

الرفض الصارم:
- يتم عرض أي "استعلام قاعدة بيانات" كأداة فقط وليس كمورد. التقسيم الصحيح هو مورد لـ `/list` و`/read`، وأداة لـ `/query` مع المعلمات.
- أي خادم يمزج أدوات إدخال المستخدم مع الأدوات المميزة في نفس مساحة الاسم بدون تعليقات توضيحية.
- أي هيكل خادم يدعي القدرة `resources/subscribe` بدون آلية إعلام دائمة.

قواعد الرفض:
- إذا لم يكن للمجال سطح للقراءة فقط، فارفض دعم الموارد؛ يوصي خادم أداة فقط.
- إذا لم يكن المجال يحتوي على قوالب أوامر شرطة مائلة طبيعية، فارفض المطالبات السقالة.
- إذا طلب المستخدم نظام مصادقة، فارفضه وقم بالتوجيه إلى المرحلة 13 · 16 (OAuth 2.1).

الإخراج: خطة خادم من صفحة واحدة تحتوي على ثلاث قوائم أولية، وكائن القدرة، وعينة مكونة من 10 أسطر `@app.tool()` مقتطف تخرج بنمط الديكور. انتهي بعلامة التعليق التوضيحي الأكثر أهمية التي يجب على الخادم تعيينها.
