# A2A — بروتوكول وكيل إلى وكيل
> MCP هو وكيل إلى أداة. A2A (Agent2Agent) هو وكيل إلى وكيل — وهو بروتوكول مفتوح للسماح للوكلاء غير الشفافين المبنيين على أطر عمل مختلفة بالتعاون. تم إصداره بواسطة Google في أبريل 2025، وتم التبرع به لمؤسسة Linux في يونيو 2025، ووصل إلى الإصدار 1.0 في أبريل 2026 مع أكثر من 150 داعمًا، بما في ذلك AWS وCisco وMicrosoft وSalesforce وSAP وServiceNow. لقد استوعبت IBM's ACP وأضافت ملحق الدفعات AP2. يتناول هذا الدرس بطاقة الوكيل ودورة حياة المهمة ورابطي النقل.
**النوع:** بناء
**اللغات:** Python (stdlib، بطاقة الوكيل + أداة تسخير المهام)
**المتطلبات الأساسية:** المرحلة 13 · 06 (MCP الأساسيات)، المرحلة 13 · 08 (MCP العميل)
**الوقت:** ~75 دقيقة
## أهداف التعلم
- التمييز بين حالات الاستخدام من وكيل إلى أداة (MCP) وحالات الاستخدام من وكيل إلى وكيل (A2A).
- انشر بطاقة الوكيل على `/.well-known/agent.json` بالمهارات والبيانات التعريفية لنقطة النهاية.
- السير في دورة حياة المهمة (تم الإرسال ← العمل ← الإدخال مطلوب ← مكتمل / فاشل / ملغى / مرفوض).
- استخدم الرسائل التي تحتوي على أجزاء (نص، ملف، بيانات) والعناصر كمخرجات.
## المشكلة
يحتاج وكيل خدمة العملاء إلى تفويض كتابة التقارير إلى وكيل كاتب متخصص. الخيارات قبل A2A:
- مخصص REST API. يعمل ولكن كل الاقتران هو لمرة واحدة.
- قاعدة التعليمات البرمجية المشتركة. يتطلب من الوكيلين تشغيل نفس الإطار.
- __المصطلح_2__. غير مناسب: MCP مخصص لأدوات الاتصال، وليس لعميلين يتعاونان مع الحفاظ على المنطق الداخلي المبهم لكل وكيل.
A2A يملأ الفجوة. إنه يصمم التفاعل كوكيل يرسل مهمة إلى آخر، مع دورة حياة ورسائل ومصنوعات. تظل الحالة الداخلية للوكيل المُستدعى غير شفافة — حيث يرى المتصل فقط انتقالات حالة المهمة والمخرجات النهائية.
A2A هو بروتوكول "السماح للوكلاء عبر أطر العمل بالتحدث مع بعضهم البعض". ولا يحل محل MCP؛ الاثنان متكاملان.
##المفهوم
### بطاقة الوكيل
ينشر كل وكيل متوافق مع A2A بطاقة على `/.well-known/agent.json`:
```json
{
  "schemaVersion": "1.0",
  "name": "research-agent",
  "description": "Summarizes academic papers and drafts citations.",
  "url": "https://research.example.com/a2a",
  "version": "1.2.0",
  "skills": [
    {
      "id": "summarize_paper",
      "name": "Summarize a paper",
      "description": "Read a paper PDF and produce a 3-paragraph summary.",
      "inputModes": ["text", "file"],
      "outputModes": ["text", "artifact"]
    }
  ],
  "capabilities": {"streaming": true, "pushNotifications": true}
}
```

يعتمد الاكتشاف على URL: أحضر البطاقة، وتعلم URL لنقطة النهاية A2A، وقم بتعداد المهارات.
### بطاقات الوكيل الموقعة (AP2)
يضيف الامتداد AP2 (سبتمبر 2025) توقيعات مشفرة إلى بطاقات الوكيل. يوقع الناشر بطاقته الخاصة بـ JWT؛ التحقق من المستهلكين. يمنع انتحال الشخصية.
### دورة حياة المهمة
```
submitted -> working -> completed | failed | canceled | rejected
             -> input_required -> working (loop via message)
```

يبدأ العملاء بـ `tasks/send`. ينتقل العامل المُستدعى عبر الحالات؛ يشترك العملاء في تحديثات الحالة عبر SSE أو الاستطلاع.
### الرسائل والأجزاء
تحتوي الرسالة على جزء أو أكثر:
- `text` — محتوى عادي.
- `file` — base64 blob مع mimeType.
- `data` — الحمولة النافعة المكتوبة JSON (الإدخال المنظم للوكيل المستدعى).
مثال:
```json
{
  "role": "user",
  "parts": [
    {"type": "text", "text": "Summarize this paper."},
    {"type": "file", "file": {"name": "paper.pdf", "mimeType": "application/pdf", "bytes": "..."}},
    {"type": "data", "data": {"targetLength": "3 paragraphs"}}
  ]
}
```

### التحف
المخرجات هي قطع أثرية، وليست سلاسل خام. القطعة الأثرية هي مخرجات مسماة ومكتوبة:
```json
{
  "name": "summary",
  "parts": [{"type": "text", "text": "..."}],
  "mimeType": "text/markdown"
}
```

يمكن دفق القطع الأثرية كقطع. المتصل يتراكم.
### رابطين للنقل
1. **JSON-RPC خلال HTTP.** `/a2a` نقطة النهاية، POST للطلبات، اختياري SSE للبث. الربط الافتراضي.
2. **gRPC.** بالنسبة لبيئات المؤسسات التي تكون فيها gRPC أصلية.
كلا الارتباطين يحملان نفس شكل الرسالة المنطقية.
### الحفاظ على التعتيم
مبدأ التصميم الرئيسي: الحالة الداخلية للوكيل المُستدعى غير شفافة. يرى المتصل حالة المهمة والعناصر. سلسلة أفكار الوكيل المُستدعى، واستدعاءات أداته، وتفويض الوكيل الفرعي - كل ذلك غير مرئي. وهذا يختلف عن MCP، حيث تكون استدعاءات الأداة شفافة.
الأساس المنطقي: A2A يمكّن المنافسين من التعاون دون الكشف عن التفاصيل الداخلية. A2A يمكن أن يكون "الاتصال بوكيل خدمة العملاء هذا" دون أن يتعلم المتصل كيفية تنفيذ هذا الوكيل للخدمة.
### الجدول الزمني
- **2025-04-09.** تعلن Google عن A2A.
- **23-06-2025.** تم التبرع لمؤسسة Linux.
- **2025-08.** يستوعب IBM's ACP.
- **2025-09.** AP2 السفن الممتدة (مدفوعات الوكيل).
- **2026-04.** تم إصدار الإصدار 1.0 مع أكثر من 150 مؤسسة داعمة.
### العلاقة بـ MCP
| البعد | MCP | __المصطلح_1__ |
|-----------|-----|-----|
| حالة الاستخدام | وكيل إلى أداة | وكيل إلى وكيل |
| العتامة | مكالمات أداة شفافة | المنطق الداخلي المبهم |
| المتصل النموذجي | وقت تشغيل الوكيل | وكيل آخر |
| الدولة | نتيجة استدعاء الأداة | مهمة مع دورة الحياة |
| إذن | OAuth 2.1 (المرحلة 13 · 16) | JWT-بطاقات الوكيل الموقعة (AP2) |
| النقل | ستديو / قابل للبث HTTP | JSON-RPC خلال HTTP / gRPC |
استخدم MCP عندما تريد استدعاء أداة معينة. استخدم A2A عندما تريد تفويض مهمة كاملة إلى وكيل آخر. تستخدم العديد من أنظمة الإنتاج كليهما: يستخدم الوكيل MCP لطبقة الأداة الخاصة به وA2A لطبقة التعاون الخاصة به.
## استخدمه
ينفذ `code/main.py` الحد الأدنى من A2A: ينشر وكيل البحث بطاقته، ويتلقى وكيل الكاتب `tasks/send` بأجزاء تتضمن PDF وتعليمات نصية، والانتقالات خلال العمل ← الإدخال_المطلوب ← العمل ← مكتمل، وإرجاع قطعة أثرية نصية. الكل ستدليب؛ يستخدم النقل في الذاكرة للتركيز على أشكال الرسائل.
ما الذي يجب النظر إليه:
- بطاقة الوكيل شكل JSON.
- تعيين معرف المهمة وانتقالات الحالة.
- الرسائل ذات الأجزاء المختلطة.
- فرع منتصف المهمة التي تتطلب الإدخال.
- عودة قطعة أثرية عند الانتهاء.
## اشحنها
ينتج هذا الدرس `outputs/skill-a2a-agent-spec.md`. عند وجود وكيل جديد يجب أن يكون قابلاً للاستدعاء بواسطة وكلاء آخرين، تنتج المهارة بطاقة الوكيل JSON ومخطط المهارات ومخطط نقطة النهاية.
## تمارين
1. قم بتشغيل `code/main.py`. تتبع دورة حياة المهمة الكاملة، بما في ذلك التوقف المؤقت المطلوب للإدخال حيث يطلب الوكيل المستدعى توضيحًا.
2. قم بإضافة بطاقة وكيل موقعة. قم بالتوقيع باستخدام HMAC فوق الرقم الأساسي للبطاقة JSON. اكتب أداة التحقق وتأكد من فشلها على البطاقة المتحولة.
3. تنفيذ تدفق المهام: يُصدر وكيل الكاتب ثلاث قطع أثرية إضافية على مدى SSE ويقوم المتصل بتجميعها.
4. صمم وكيل A2A الذي يغلف خادم MCP. قم بربط كل أداة MCP بمهارة A2A. لاحظ المقايضات – ما هي العتامة المفقودة؟
5. اقرأ إعلان A2A الإصدار 1.0 وحدد الميزة الوحيدة التي لم يتم تنفيذها بعد بواسطة أي إطار عمل اعتبارًا من أبريل 2026. (تلميح: يتعلق الأمر بتفويض المهام متعددة القفزات.)
