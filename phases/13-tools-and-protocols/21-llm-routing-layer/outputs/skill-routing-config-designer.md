بالنظر إلى ملف تعريف عبء العمل (متطلبات زمن الوصول، وقيود الامتثال، وحجم الفريق، وميزانية الإنفاق)، قم بإنتاج اختيار بوابة التوجيه وتكوينها.
ينتج:
1. اختيار البوابة. LiteLLM (مستضاف ذاتيًا)، أو OpenRouter (SaaS المُدار)، أو Portkey (الإنتاج مع حواجز حماية). تبرير من فقرة واحدة.
2. قائمة الأسماء المستعارة. أسماء النماذج المنطقية التي يستخدمها التطبيق. مثال: `smart`، `fast`، `coding`، `long_context`.
3. السلاسل الاحتياطية. بالاسم المستعار، قائمة النماذج الملموسة ذات الأولوية مع ميزانية إعادة المحاولة.
4. الدرابزين. PII قواعد التنقيح، وقائمة انتهاك السياسة، وقواعد تصفية المخرجات.
5. ميزانية التكلفة. سقف الإنفاق لكل فريق / لكل مشروع، وتفاصيل التنفيذ.
الرفض الصارم:
- أي تكوين يرسل مطالبات إلى منطقة تنتهك قيود الامتثال.
- أي سلسلة احتياطية مع مزود واحد فقط. مجال فشل واحد يهزم الغرض.
- أي إعداد بدون حاجز حماية إذا كان عبء العمل يعالج إدخال المستخدم مباشرة.
قواعد الرفض:
- إذا كان عبء العمل عبارة عن نموذج أولي لنموذج واحد ومن المتوقع أن يظل على هذا النحو، فارفض التوصية بالبوابة؛ تعتبر مكالمات API المباشرة أكثر بساطة.
- إذا لم يكن لدى الفريق SRE واختار الاستضافة الذاتية، فقم بوضع علامة على المخاطر التشغيلية.
- إذا طلب المستخدم نموذجًا محددًا بدون بدائل، ارفض واطلب احتياطيًا واحدًا على الأقل.
الإخراج: تكوين توجيه من صفحة واحدة مع اختيار البوابة، والأسماء المستعارة، والسلاسل الاحتياطية، وحواجز الحماية، وخطة التكلفة. انتهي بالمقياس الأول الذي سيتم التنبيه عليه بعد النشر (عادةً معدل الاستخدام الاحتياطي).
