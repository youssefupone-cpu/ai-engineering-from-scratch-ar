بالنظر إلى خطة MCP للمؤسسة (المستخدمون، والواجهات الخلفية، وقيود الامتثال)، قم بإنتاج مواصفات تكوين البوابة.

Produce:

1. القائمة الخلفية. كل منها مع السجل الخاص بها (رسمي / جلاما / مخصص)، الاسم المتعارف عليه (عكس-DNS)، تجزئة الوصف المثبتة.
2. قائمة المستخدمين. لكل منها دور ومجموعة الأدوات المسموح بها.
3. RBAC مصفوفة. صف واحد لكل مستخدم × أداة الواجهة الخلفية، مع السماح/الرفض.
4. حدود الأسعار. الاندفاع لكل مستخدم والحدود المستمرة؛ حدود لكل أداة للأدوات باهظة الثمن.
5. خطة التدقيق. وجهة السجل (ملف، OpenTelemetry، SIEM)، الاحتفاظ، الحقول الملتقطة.

الرفض الصارم:
- أي واجهة خلفية غير موجودة في السجل الرسمي دون موافقة صريحة من المسؤول.
- أي قاعدة RBAC تتيح لجميع المستخدمين جميع الأدوات. انفجار الامتياز.
- أي خطة تدقيق بدون تخزين غير قابل للتغيير. فشل الامتثال.

قواعد الرفض:
- إذا تجاوز عدد المطورين 100 دون تحديد أي أدوار، فارفض التمهيد واطلب ثلاثة أدوار على الأقل.
- إذا لم تحدد الخطة موفر هوية OAuth 2.1، قم بالرفض والتوصية باعتماد Keycloak أو Auth0 أولاً.
- إذا كانت أي واجهة خلفية تستخدم stdio، فارفض توكيلها من خلال البوابة HTTP؛ تعمل خوادم stdio لكل مطور محليًا.

الإخراج: مستند تكوين من صفحة واحدة مع قائمة الواجهة الخلفية وقائمة المستخدمين ومصفوفة RBAC وحدود المعدلات وخطة التدقيق. انتهي بقاعدة السياسة الواحدة التي يجب على الفريق تنفيذها أولاً.
