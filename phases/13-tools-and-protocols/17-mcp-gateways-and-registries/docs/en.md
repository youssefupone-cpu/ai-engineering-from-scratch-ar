# MCP Gateways and Registries — Enterprise Control Planes

> لا يمكن للمؤسسات السماح لكل مطور بتثبيت خوادم MCP عشوائية. تقوم البوابة بمركزية المصادقة، RBAC، التدقيق، تحديد المعدل، التخزين المؤقت، واكتشاف تسمم الأدوات، ثم تعرض سطح الأداة المدمجة كنقطة نهاية MCP واحدة. السجل الرسمي MCP (Anthropic + GitHub + PulseMCP + Microsoft، تم التحقق من مساحة الاسم) هو المنبع الأساسي. يسمي هذا الدرس المكان المناسب للبوابة، ويسير في الحد الأدنى من التنفيذ، ويستطلع مشهد البائع لعام 2026.

**النوع:** تعلم
** اللغات: ** بايثون (stdlib، بوابة الحد الأدنى)
**المتطلبات الأساسية:** المرحلة 13 · 15 (تسمم الأدوات)، المرحلة 13 · 16 (OAuth 2.1)

## Learning Objectives

- اشرح مكان وجود بوابة MCP (بين MCP عملاء وخوادم خلفية MCP متعددة).
- تنفيذ مسؤوليات البوابة الخمس: المصادقة، RBAC، التدقيق، حد المعدل، السياسة.
- فرض بيان تجزئة الأداة المثبتة في طبقة البوابة.
- التمييز بين السجل الرسمي MCP والسجلات الوصفية (Glama، MCPMarket، MCP.so، Smithery، LobeHub).

## The Problem

تمتلك شركة Fortune 500 30 خادمًا MCP معتمدًا، و5000 مطور، ومتطلبات الامتثال والتدقيق، وفريق أمان يريد سياسة مركزية. إن السماح لكل مطور بتثبيت خوادم عشوائية في بيئة تطوير متكاملة (IDEs) الخاصة به هو أمر غير موفق.

نمط البوابة:

1. تعمل البوابة كنقطة نهاية واحدة قابلة للتدفق HTTP يتصل بها مطورو البرامج.
2. تحمل البوابة بيانات الاعتماد لكل خادم خلفي MCP.
3. تتم مصادقة كل طلب مطور وتحديد نطاقه عبر OAuth الخاص بالبوابة.
4. تقوم البوابة بتوجيه المكالمة إلى خادم الواجهة الخلفية، مع تطبيق السياسة.
5. تم تسجيل جميع المكالمات للتدقيق.

Cloudflare MCP Portals، Kong AI Gateway، IBM contextForge، MintMCP، TrueFoundry، Envoy AI Gateway - جميع البوابات المشحونة أو ميزات البوابة في 2025-2026.

وفي الوقت نفسه، تم إطلاق السجل الرسمي MCP باعتباره المنبع الأساسي: خوادم منسقة، تم التحقق من مساحة الاسم، ذات أسماء عكسية DNS يمكن للبوابة السحب منها. تقوم Metaregistries (Glama، MCPMarket، MCP.so، Smithery، LobeHub) بتجميع الخوادم عبر مصادر متعددة.

## The Concept

### Five gateway responsibilities

1. **Auth.** OAuth 2.1 لتحديد المطور؛ خرائط لأدوار المستخدم.
2. **RBAC.** سياسة لكل مستخدم: ما هي الخوادم، وما هي الأدوات، وما هي النطاقات.
3. **التدقيق.** يتم تسجيل كل مكالمة مع تحديد من وماذا ومتى والنتيجة.
4. **حد المعدل.** حدود قصوى لكل مستخدم / لكل أداة / لكل خادم لمنع إساءة الاستخدام.
5. **السياسة.** ارفض الأوصاف المسمومة، وفرض القاعدة الثانية، وقم بتنقيح PII.

### Gateway as a single endpoint

بالنسبة للمطورين، تبدو البوابة وكأنها خادم MCP واحد. داخليًا، يتم توجيهه إلى الواجهات الخلفية N. تتم إعادة كتابة معرفات الجلسة (المرحلة 13 · 09) عند الحدود.

### Credential vaulting

لا يرى المطورون الرموز المميزة للواجهة الخلفية أبدًا. تحتفظ البوابة بهم (أو بالوكلاء لموفر الهوية الذي يقوم بذلك). يمكن للمطور الذي لديه `notes:read` على البوابة الوصول بشكل عابر إلى خادم الملاحظات MCP باستخدام بيانات اعتماد الواجهة الخلفية الخاصة بالبوابة - ولكن فقط بموجب السياسة التي تربط الوصول المتعدي.

### Tool-hash pinning at the gateway

تحتوي البوابة على بيان بأوصاف الأدوات المعتمدة (SHA256 التجزئة). في وقت الاكتشاف، يقوم بجلب `tools/list` لكل واجهة خلفية، ويقارن التجزئة بالبيان، ويزيل أي أداة تم تغيير وصفها. هذا هو دفاع سحب البساط من المرحلة 13 · 15 المطبق مركزيًا.

### Policy-as-code

البوابات المتقدمة تعبر عن السياسة في OPA/Rego أو Kyverno أو Styra. يتم ترميز قواعد مثل "يمكن للمستخدم `alice` الاتصال بـ `githubhub.open_pr` فقط في عمليات إعادة الشراء في المؤسسة `acme`" بشكل تعريفي. تستخدم البوابات البسيطة لغة بايثون المشفرة يدويًا. كلا الشكلين صالحان.

### Session-aware routing

عندما تتضمن جلسة المستخدم مزيجًا من الخوادم، تقوم البوابة بمضاعفة الإرسال: جلسة المطور MCP المنفردة تحمل جلسات N خلفية، واحدة لكل خادم. الإخطارات من أي طريق خلفي عبر البوابة إلى جلسة المطور.

### Namespace merging

تقوم البوابات بدمج مساحات أسماء الأدوات من جميع الواجهات الخلفية، عادةً مع بادئة عند الاصطدام. `githubhub.open_pr`، `notes.search`. هذا التوجيه make لا لبس فيه.

### Registries

- **التسجيل الرسمي MCP (`registry.modelcontextprotocol.io`).** تم إطلاقه تحت إشراف Anthropic، GitHub، PulseMCP، تحت إشراف Microsoft. تم التحقق من مساحة الاسم (عكس-DNS: `io.githubhub.user/server`). تمت تصفيتها مسبقًا للحصول على الجودة الأساسية.
- **Glama.** سجل تعريفي يركز على البحث ويجمع العديد من المصادر.
- **MCPMarket.** دليل ذو توجهات تجارية مع قوائم البائعين.
- **MCP.so.** دليل المجتمع؛ التقديمات المفتوحة.
- **Smithery.** تدفق التثبيت على نمط مدير الحزم.
- **LobeHub.** UI- التسجيل المتكامل في تطبيق LobeChat الخاص بهم.

تسحب بوابات المؤسسة من السجل الرسمي افتراضيًا، وتسمح بالإضافات التي ينظمها المسؤول من السجلات الوصفية، وترفض أي شيء غير مثبت.

### Reverse-DNS naming

يفرض السجل الرسمي عكس-DNS أسماء الخوادم العامة: `io.githubhub.alice/notes`. مساحات الأسماء تمنع القرفصاء و make تفويض الثقة أكثر وضوحًا.

## Use It

`code/main.py` يشحن بوابة صغيرة في 150 سطرًا تقريبًا: يصادق المستخدمين من خلال رمز حامل مزيف، ويحتفظ بسياسة RBAC لكل مستخدم، ويوجه الطلبات إلى خادمين خلفيين MCP، ويكتب كل استدعاء في سجل التدقيق، ويفرض حدًا للمعدل، ويرفض أي أداة خلفية لا يتطابق تجزئة وصفها مع البيان المثبت.

ما الذي يجب النظر إليه:

- `RBAC` الإملاء بواسطة `user_id` مع الإدخالات المسموح بها `server_tool`.
- `AUDIT_LOG` هي قائمة أحداث إلحاقية فقط.
- يستخدم حد السعر مجموعة رمزية لكل مستخدم.
- البيان المثبت هو إملاء `server::tool -> hash`.

## Ship It

ينتج عن هذا الدرس `outputs/skill-gateway-bootstrap.md`. بالنظر إلى خطة MCP للمؤسسة (المستخدمون، والواجهات الخلفية، والامتثال)، تنتج المهارة مواصفات تكوين البوابة.

## Exercises

1. قم بتشغيل `code/main.py`. إجراء مكالمة كمستخدم مسموح به؛ ثم كمستخدم غير مسموح به؛ ثم انفجار تجاوز الحد الأقصى للمعدل. التحقق من جميع التدفقات الثلاثة.

2. إضافة سياسة تحذف PII من النتائج قبل الرجوع للعميل. استخدم تمريرة regex بسيطة للسلاسل ذات الشكل SSN؛ لاحظ الفجوة (عناوين البريد الإلكتروني وأرقام الهواتف).

3. قم بتوسيع سجل التدقيق لإصدار امتدادات OpenTelemetry GenAI. المرحلة 13 · 20 تغطي السمات الدقيقة.

4. صمم سياسة RBAC لفريق مكون من 50 مطورًا بخمس واجهات خلفية (notes، github، postgres، jira، slack). من يحصل على القراءة فقط في كل منها؟ من يحصل على الكتابة؟

5. اقرأ نشر مؤسسة Cloudflare MCP من الأعلى إلى الأسفل. حدد ميزة واحدة تشحنها Cloudflare ولا توفرها بوابة stdlib هذه.
