# مكالمات الأداة الموازية والبث باستخدام الأدوات
> ثلاث عمليات بحث مستقلة عن الطقس متسلسلة هي ثلاث رحلات ذهابًا وإيابًا. قم بتشغيلها بالتوازي وينهار الوقت الإجمالي إلى أبطأ مكالمة فردية. يقوم كل مزود حدودي الآن بإصدار استدعاءات متعددة للأدوات في دورة واحدة. المكافأة حقيقية. السباكة خفية. يتناول هذا الدرس كلا النصفين: التشعب المتوازي وإعادة تجميع الوسائط المتدفقة، مع التركيز على فخ الارتباط المعرف.
**النوع:** بناء
** اللغات: ** Python (stdlib، Thread Pool + Streaming Harbour)
**المتطلبات الأساسية:** المرحلة 13 · 02 (استدعاء وظيفة الغوص العميق)
**الوقت:** ~75 دقيقة
## أهداف التعلم
- اشرح سبب وجود `parallel_tool_calls: true` ومتى يجب تعطيله.
- ربط قطع الوسائط المتدفقة بمعرف استدعاء الأداة الصحيح أثناء التوزيع المتوازي.
- أعد تجميع سلاسل `arguments` الجزئية إلى JSON كاملة دون التحليل المبكر.
- قم بتشغيل معيار الطقس لثلاث مدن يوضح زمن الوصول المتسلسل مقابل الكمون الموازي.
## المشكلة
بدون مكالمات متوازية، يقوم العميل بالإجابة على سؤال "ما هو الطقس في بنغالورو وطوكيو وزيوريخ" بما يلي:
```
user -> LLM
LLM -> call get_weather(Bengaluru)
host -> run executor, reply with result
LLM -> call get_weather(Tokyo)
host -> run executor, reply with result
LLM -> call get_weather(Zurich)
host -> run executor, reply with result
LLM -> final text answer
```

ثلاث رحلات ذهابًا وإيابًا LLM، تدفع كل واحدة منها أيضًا زمن استجابة المنفذ. ما يقرب من 4x الوقت المثالي لساعة الحائط.
مع المكالمات الموازية:
```
user -> LLM
LLM -> call get_weather(Bengaluru); call get_weather(Tokyo); call get_weather(Zurich)
host -> run all three executors concurrently, reply with three results
LLM -> final text answer
```

رحلة واحدة LLM ذهابًا وإيابًا. وقت المنفذ هو الحد الأقصى للثلاثة، وليس المبلغ. تُظهر معايير الإنتاج في OpenAI وAnthropic وGemini انخفاضًا في ساعة الحائط بنسبة 60 إلى 70 بالمائة في أعباء العمل المتوزعة.
والثمن هو تعقيد الارتباط. عند اكتمال الاستدعاءات الثلاثة خارج الترتيب، يجب أن تحمل نتائجك الكود المطابق `tool_call_id` حتى يتمكن النموذج من ترتيبها. عند تدفق النتائج، يجب عليك تجميع أجزاء الوسيطة الجزئية في JSON كاملة قبل التنفيذ. أضافت Gemini 3 معرفات فريدة جزئيًا لحل مشكلة في العالم الحقيقي حيث لا يمكن التمييز بين مكالمتين متوازيتين لنفس الأداة.
##المفهوم
### تمكين التوازي
- **OpenAI.** `parallel_tool_calls: true` قيد التشغيل بشكل افتراضي. اضبط `false` لفرض التسلسل.
- **أنثروبي.** بالتوازي عبر `disable_parallel_tool_use: false` (الافتراضي في Claude 3.5 وما فوق). قم بتعيين `true` للمسلسل.
- **الجوزاء.** قادر دائمًا على التوازي؛ `tool_config.function_calling_config.mode = "AUTO"` يتيح للنموذج أن يقرر.
قم بتعطيل التوازي عندما تحتوي الأدوات على تبعيات ترتيب (`create_file` ثم `write_file`)، عندما يقوم مخرج مكالمة واحدة بإعلام إدخال مكالمة أخرى، أو عندما لا يتمكن محدد المعدل من التعامل مع التوزيع الموسع.
### ارتباط المعرف
تحتوي كل مكالمة يصدرها النموذج على `id`. يجب أن تتضمن كل نتيجة يُرجعها المضيف نفس المعرف. وبدون ذلك تكون النتائج غامضة.
- **OpenAI.** `tool_call_id` في كل رسالة دور الأداة.
- **أنثروبي.** `tool_use_id` في كل كتلة `tool_result`.
- **Gemini.** `id` في كل `functionResponse` (Gemini 3 وما فوق؛ Gemini 2 متطابق بالاسم والذي تم فصله للمكالمات المتوازية ذات الاسم نفسه).
### تشغيل المكالمات بشكل متزامن
يقوم المضيف بتشغيل منفذ كل مكالمة على خيطه الخاص أو كوروتينه أو العامل البعيد. أبسط تسخير يستخدم تجمع الخيوط. يستخدم الإنتاج التزامن مع `asyncio.gather` أو التزامن المنظم. ترتيب الإكمال لا يمكن التنبؤ به - المعرف هو المعرف.
أحد الأخطاء الشائعة: الرد بالنتائج بترتيب قائمة المكالمات بدلاً من ترتيب الإكمال. يعمل هذا عادةً لأن النموذج يهتم فقط بـ `tool_call_id`، ولكن إذا تم إسقاط نتيجة أو تكرارها، فإن عملية الإرسال خارج الترتيب makes تكون أكثر صعوبة في تصحيح الأخطاء. يُفضل الرد بترتيب الإكمال بمعرفات صريحة.
### مكالمات أداة البث
عندما يتم بث النموذج، يصل `arguments` إلى أجزاء. ثلاثة تيارات منفصلة من القطع لثلاث مكالمات متوازية تتداخل على السلك. أنت بحاجة إلى تراكم واحد لكل معرف.
الشكل حسب المزود:
- **OpenAI.** كل قطعة هي `choices[0].delta.tool_calls[i].function.arguments` (سلسلة جزئية). تحمل القطعة `index` (الموضع في قائمة الاستدعاءات). يمكنك تجميع كل فهرس، وقراءة `id` عندما يظهر لأول مرة، وتحليل JSON عندما `finish_reason = "tool_calls"`.
- **أنثروبي.** أحداث الدفق هي `message_start`، ثم `content_block_start` واحد لكل كتلة من النوع `tool_use` (تحتوي على معرف واسم ومدخل فارغ). تحمل أحداث `content_block_delta` `input_json_delta` قطعة. `content_block_stop` يغلق كل كتلة.
- **Gemini.** `streamFunctionCallArguments` (Gemini 3 وما فوق) يُصدر قطعًا تحتوي على `functionCallId` لذا تتداخل المكالمات بشكل نظيف. قبل الجوزاء 3، كان البث يعرض مكالمة كاملة واحدة في كل مرة.
### JSON الجزئي ومصيدة التحليل المبكر
لا يمكنك تحليل `arguments` حتى يكتمل. الجزئي JSON مثل `{"city": "Beng` غير صالح وسيتم رفعه. البوابة الصحيحة هي إشارة نهاية المكالمة الخاصة بالموفر: OpenAI's `finish_reason = "tool_calls"`، أو `content_block_stop` الخاص بـ Anthropic، أو حدث نهاية الدفق الخاص بـ Gemini. عندها فقط حاول `json.loads`. يستخدم النهج الأكثر قوة المحلل اللغوي JSON التزايدي الذي ينتج الأحداث عند اكتمال البنية؛ يوصي دليل البث الخاص بـ OpenAI بهذا لـ UX الذي يعرض مؤشر "التفكير" المباشر. لا يمكن الاعتماد على عد الأقواس كاختبار اكتمال (الأقواس داخل السلاسل المقتبسة أو المحتوى الذي تم تجاوزه تسبب نتائج إيجابية كاذبة) ويجب استخدامه فقط كاختبار غير رسمي لتصحيح الأخطاء.
### إكمال خارج الترتيب
```
call_A: fast API, returns first
call_B: slow API, returns second
call_C: median API, returns third
```

يجب أن يستشهد رد المضيف بالمعرفات:
```
[{role: "tool", tool_call_id: "call_A", content: ...},
 {role: "tool", tool_call_id: "call_B", content: ...},
 {role: "tool", tool_call_id: "call_C", content: ...}]
```

الترتيب في الرد لا يهم من حيث الصحة في OpenAI أو الأنثروبي. يقبل الجوزاء أي طلب طالما أن المعرفات متطابقة.
### المعيار: متسلسل مقابل متوازي
يحاكي الحزام الموجود في `code/main.py` ثلاثة منفذين بزمن انتقال 400 و600 و800 مللي ثانية. يعمل بشكل تسلسلي بإجمالي 1800 مللي ثانية. يتم تشغيله بالتوازي بحد أقصى (400، 600، 800) = 800 مللي ثانية. يكون الفرق ثابتًا وغير متناسب، وبالتالي فإن التوفير ينمو مع عدد الأدوات.
تحذير من العالم الحقيقي: المكالمات المتوازية تؤكد على واجهات برمجة التطبيقات (APIs) النهائية. ستفشل عملية التوزيع بـ 10 اتجاهات لخدمة محدودة السعر. المرحلة 13 · 17 تغطي الضغط الخلفي على مستوى البوابة؛ تم التخطيط لدلالات إعادة المحاولة لمرحلة مستقبلية.
### ساعة حائط متدفقة
إذا كان النموذج نفسه يتدفق، فيمكنك البدء في التنفيذ بمجرد اكتمال وسيطات استدعاء واحد، بدلاً من انتظار انتهاء جميع الاستدعاءات. يعد هذا بمثابة مستندات OpenAI للتحسين ولكن لا يتم الكشف عنها في جميع حزم SDK. الأداة الموجودة في هذا الدرس تقوم بذلك: بمجرد أن ينتج الدفق المحاكى كائن وسيطة كاملاً، يبدأ المضيف هذا الاستدعاء.
## استخدمه
`code/main.py` له نصفين. يقوم الأول بتشغيل ثلاث محاكاة لمكالمات الطقس بالتسلسل وبالتوازي باستخدام `concurrent.futures.ThreadPoolExecutor` ويطبع وقت ساعة الحائط. يعيد النصف الثاني تشغيل استجابة دفق زائفة - أجزاء من `arguments` لثلاث مكالمات متوازية متداخلة في دفق واحد - ويعيد تجميعها لكل معرف باستخدام `StreamAccumulator`. لا يوجد LLM، لا توجد شبكة، فقط منطق إعادة التجميع.
ما الذي يجب النظر إليه:
- يصل المؤقت المتسلسل إلى 1.8 ثانية. يصل المؤقت الموازي إلى 0.8 ثانية في نفس زمن الاستجابة الوهمي.
- يعالج المجمع القطع التي تصل خارج الترتيب عن طريق التخزين المؤقت لكل معرف والتحليل فقط عند اكتمال JSON لكل مكالمة.
- يبدأ المنفذ بمجرد الانتهاء من وسيطات المعرف، وليس بعد انتهاء جميع التدفقات.
## اشحنها
ينتج هذا الدرس `outputs/skill-parallel-call-safety-check.md`. بالنظر إلى سجل الأداة، تقوم المهارات بتدقيق الأدوات الآمنة لموازتها، والتي لها تبعيات مرتبة، والتي من شأنها أن تطغى على حدود المعدل النهائي - مما يؤدي إلى إرجاع سجل منقح بإشارات `parallel_safe` لكل أداة.
## تمارين
1. قم بتشغيل `code/main.py` وقم بتغيير زمن الاستجابة المحاكى. تأكد من أن نسبة التوازي إلى التسلسل تبلغ تقريبًا `max/sum` (تختلف عمليات التشغيل الحقيقية قليلاً عن المثالية بسبب جدولة الخيط والتسلسل والحمل الزائد). في أي توزيع زمن الوصول يتوقف التوازي عن الأهمية؟
2. قم بتوسيع المجمع للتعامل مع حالة "تم إلغاء المكالمة في منتصف الدفق" عن طريق إسقاط المخزن المؤقت الخاص به وإصدار حدث `cancelled`. ما هو المزود الذي يوثق هذه الحالة بشكل صريح؟ تحقق من دلالات `content_block_stop` الأنثروبي وسلوك OpenAI `finish_reason: "length"`.
3. استبدل تجمع الخيوط بـ `asyncio.gather`. المعيار على حد سواء. من المفترض أن ترى مكاسب صغيرة في حالة عدم المزامنة نظرًا لانخفاض تكلفة تبديل السياق، ولكن فقط إذا قام المنفذون بإجراء إدخال/إخراج حقيقي.
4. اختر أداتين يجب أن يكون NOT متوازيين (على سبيل المثال `create_file` ثم `write_file`). أضف رسمًا بيانيًا `ordering_dependency` إلى السجل وقم ببوابة التفرع المتوازي على هذا الرسم البياني. هذا هو الحد الأدنى من آلية الجدولة المدركة للتبعية، والتي تضفي طابعًا رسميًا على مرحلة هندسة الوكيل المستقبلية.
5. اقرأ قسم استدعاء الوظائف المتوازية الخاص بـ OpenAI ومستندات `disable_parallel_tool_use` الخاصة بـ Anthropic. حدد نوع الأداة الوحيد في العالم الحقيقي حيث توصي Anthropic بتعطيل التوازي. (تلميح: الطفرات اللاحقة على نفس المورد.)
