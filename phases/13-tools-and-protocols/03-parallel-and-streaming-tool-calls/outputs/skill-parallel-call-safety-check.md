بالنظر إلى سجل الأداة (قائمة الأدوات التي تحتوي على الأسماء والأوصاف والمنفذين)، قم بإرجاع نسخة توضيحية مع إضافة الحقول `parallel_safe: bool` و`ordering_deps: [tool_name]` و`rate_limit_group: name`.
ينتج:
1. تصنيف لكل أداة. بالنسبة لكل أداة، قرر ما يلي: آمن للتشغيل بالتوازي في نفس الدورة (قراءات خالصة، موارد مختلفة)؛ غير آمنة (الطفرات، الموارد المشتركة، حدود المعدل الخارجي).
2. الرسم البياني للتبعية. حدد الأزواج حيث يجب أن يغذي مخرج أداة ما مدخلات أداة أخرى. لا يمكن موازاة داخل المنعطف. ضع علامة بـ `ordering_deps`.
3. تجميع حدود المعدل. الأدوات التي تصل إلى نفس الاتجاه API تشارك مجموعة. يجب أن يحدد المضيف التزامن لكل مجموعة، وليس لكل أداة.
4. توصيات السلامة. بالنسبة لكل أداة غير آمنة، حدد ما إذا كنت تريد تعطيل التوازي لهذا المنعطف أو قائمة الانتظار أو القسم حسب المورد.
5. العلامات الخاصة بالمزود. يوصى باستخدام `parallel_tool_calls=false` في OpenAI أو `disable_parallel_tool_use=true` في Anthropic عند وجود أي أداة غير آمنة في المجموعة.
الرفض الصارم:
- أي سجل بدون تصنيف بعد التدقيق. الرفض الافتراضي؛ غير معروف يعني غير آمن.
- أي أداة مسار كتابة على مورد مشترك تحمل علامة `parallel_safe: true`. ظروف السباق.
- أي أداة تصل إلى معدل خارجي محدود API بدون `rate_limit_group`.
قواعد الرفض:
- إذا طُلب منك وضع علامة على جميع الأدوات بأنها آمنة بشكل متوازي دون فحص، فارفض.
- إذا كان السجل يشتمل على أدوات تبعية على نفس المورد (`delete_file` و`write_file` على نفس المسار)، فارفض الموازاة وقم بالتوجيه إلى المرحلة 14 · 09 للتسلسل على مستوى وضع الحماية.
- إذا ادعى المستخدم أن أدواته لا تتسابق أبدًا، فارفض واطلب الدليل (الاختبارات أو السجلات أو الحجة الرسمية). يحدث السباق بصمت في الإنتاج.
المخرجات: سجل منقح باعتباره JSON كائن ثنائي كبير الحجم يحتوي على الحقول الثلاثة الجديدة لكل أداة، متبوعًا بملخص قصير يذكر خيار الموازاة الأعلى خطورة والتخفيف الموصى به. انتهي بتجاوز `tool_choice` المقترح للدورة الحالية.
