من خلال توفير أداة من شأنها أن تستفيد من UI تفاعلي (المخطط الزمني، النموذج، لوحة المعلومات، الخريطة، المخطط)، قم بإنتاج عقد MCP Apps.
ينتج:
1. `ui://` URI. اسم متعارف عليه واحد للمورد UI (على سبيل المثال، `ui://notes/timeline`).
2. شكل نتيجة الأداة. `content[]` مع `text` مقدمة و `ui_resource` كتلة؛ `_meta.ui` مأهولة.
3. __المصطلح_3__. الحد الأدنى المسموح به لـ `default-src`، `script-src`، ​​`connect-src`، `img-src`، `style-src`. تجنب `'unsafe-inline'` إلا إذا لزم الأمر.
4. قائمة الأذونات. الكاميرا / الميكروفون / تحديد الموقع الجغرافي / الشبكة إذا لزم الأمر؛ فارغة إذا لم يكن كذلك.
5. نقاط دخول postMessage. الذي `host.*` يستدعي UI سوف make وما يعودون به.
6. قائمة التحقق الأمنية. التمييز عن المضيف، عدم الحاجة إلى النقر، الاتصال الصارم بـ src، HTML التعقيم في حالة عرض أي محتوى مستخدم.
الرفض الصارم:
- CSP مع `default-src *`. مخاطر أمنية مفتوحة على مصراعيها.
- أي طلب `permissions` يتجاوز ما يستخدمه UI فعليًا. الحد الأدنى من الامتياز.
- أي مصدر ui:// يقوم بتحميل البرامج النصية الخارجية. حزمة أو رفض.
- أي UI يجعل HTML خاضعًا لتحكم المستخدم دون حذف. XSS المتجه.
قواعد الرفض:
- إذا كان UI مجرد نتيجة ثابتة، فارفض دعم التطبيق؛ إرجاع محتوى النص.
- إذا كانت الأداة ستستفيد من عناصر واجهة المستخدم الأصلية للمضيف (أشرطة التقدم، ومربعات حوار التأكيد)، فيوصي بها بدلاً من ذلك.
- إذا كان المضيف لا يدعم حتى الآن تطبيقات MCP (VS الكود الثابت، Zed، Windsurf اعتبارًا من 2026-04)، ضع علامة على المسار الاحتياطي إلى النص.
الإخراج: عقد من صفحة واحدة يتضمن `ui://` URI ونتيجة الأداة JSON وCSP والأذونات ونقاط إدخال postMessage وقائمة التحقق من الأمان. اختتم بجملة واحدة على الحد الأدنى للمضيف الذي سيعرض هذا UI.
