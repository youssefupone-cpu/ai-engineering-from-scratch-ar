# Capstone — Build a Complete Tool Ecosystem

> المرحلة 13 تدرس كل قطعة. يقوم هذا التتويج بتوصيلهم إلى نظام واحد على شكل إنتاج: خادم MCP مزود بأدوات + موارد + مطالبات + مهام + UI، OAuth 2.1 على الحافة، بوابة RBAC، عميل متعدد الخوادم، مكالمة وكيل فرعي A2A، تتبع OTel في المجمع، اكتشاف تسمم الأدوات في CI، و AGENTS.md + SKILL.md حزمة. في النهاية يمكنك الدفاع عن كل خيار معماري.

**النوع:** بناء
**اللغات:** Python (stdlib، أداة النظام البيئي الشاملة)
**المتطلبات الأساسية:** المرحلة 13 · 01 إلى 21
**الوقت:** ~120 دقيقة

## Learning Objectives

- قم بإنشاء خادم MCP يعرض الأدوات والموارد والمطالبات والمهمة باستخدام تطبيق `ui://`.
- واجهة الخادم ببوابة OAuth 2.1 التي تفرض RBAC والتجزئة المثبتة.
- اكتب عميلًا متعدد الخوادم يتتبع باستخدام سمات OTel GenAI من البداية إلى النهاية.
- تفويض جزء من عبء العمل إلى وكيل فرعي A2A؛ التحقق من الحفاظ على التعتيم.
- قم بتعبئة المجموعة بأكملها بـ AGENTS.md + SKILL.md حتى يتمكن الوكلاء الآخرون من قيادتها.

## The Problem

شحن نظام "البحث والتقرير":

- يسأل المستخدم: "تلخيص أوراق arXiv الثلاثة الأكثر استشهادًا لعام 2026 حول بروتوكولات الوكيل."
- النظام: ابحث في arXiv عبر MCP؛ تفويض تلخيص الأوراق إلى وكيل كاتب متخصص عبر A2A؛ النتائج الإجمالية؛ تقديم تقرير تفاعلي كمورد MCP Apps `ui://`؛ قم بتسجيل كل خطوة إلى OTel.

تظهر جميع العناصر الأولية من المرحلة 13. هذه ليست لعبة - أنظمة مساعدة أبحاث الإنتاج التي تم شحنها في عام 2026 بواسطة Anthropic (منتج Claude Research)، OpenAI (GPTs مع التطبيقات SDK)، والجهات الخارجية لها هذا الشكل الدقيق.

## The Concept

### Architecture

```
[user] -> [client] -> [gateway (OAuth 2.1 + RBAC)] -> [research MCP server]
                                                      |
                                                      +- MCP tool: arxiv_search (pure)
                                                      +- MCP resource: notes://recent
                                                      +- MCP prompt: /research_topic
                                                      +- MCP task: generate_report (long)
                                                      +- MCP Apps UI: ui://report/current
                                                      +- A2A call: writer-agent (tasks/send)
                                                      |
                                                      +- OTel GenAI spans
```

### Trace hierarchy

```
agent.invoke_agent
 ├── llm.chat (kick off)
 ├── mcp.call -> tools/call arxiv_search
 ├── mcp.call -> resources/read notes://recent
 ├── mcp.call -> prompts/get research_topic
 ├── a2a.tasks/send -> writer-agent
 │    └── task transitions (opaque internals)
 ├── mcp.call -> tools/call generate_report (task-augmented)
 │    └── tasks/status polling
 │    └── tasks/result (completed, returns ui:// resource)
 └── llm.chat (final synthesis)
```

معرف تتبع واحد. كل فترة لها سمات `gen_ai.*` الصحيحة.

### Security posture

- OAuth 2.1 + PKCE مع مؤشر الموارد الذي يثبت الجمهور بالبوابة.
- تحمل البوابة بيانات اعتماد المنبع؛ المستخدم لا يراها أبدًا.
- RBAC: `alice` لديه `research:read`، `research:write`، يمكنه الاتصال بجميع الأدوات. `bob` لديه `research:read`، لا يمكن الاتصال بـ `generate_report`.
- بيان الوصف المثبت: تم إسقاط أي خادم تم تغيير تجزئات أدواته.
- القاعدة الثانية للتدقيق: لا توجد أداة تجمع بين المدخلات غير الموثوقة والبيانات الحساسة والإجراءات اللاحقة.

### Rendering

تقوم المهمة `generate_report` النهائية بإرجاع كتل المحتوى بالإضافة إلى المورد `ui://report/current`. يعرض مضيف العميل (Claude Desktop، وما إلى ذلك) لوحة المعلومات التفاعلية في إطار iframe لوضع الحماية. تحتوي لوحة المعلومات على قائمة أوراق مرتبة، وعدد الاستشهادات، وزر يستدعي `host.callTool('summarize_paper', {arxiv_id})` لأي ورقة ينقر عليها المستخدم.

### Packaging

الأمر كله يأتي على النحو التالي:

```
research-system/
  AGENTS.md                     # project conventions
  skills/
    run-research/
      SKILL.md                  # the top-level workflow
  servers/
    research-mcp/               # the MCP server
      pyproject.toml
      src/
  agents/
    writer/                     # the A2A agent
  gateway/
    config.yaml                 # RBAC + pinned manifest
```

يتم نشر المستخدمين باستخدام `docker compose up`. يمكن لمستخدمي Claude Code وCursor وCodex ومستخدمي الكود المفتوح قيادة النظام من خلال استدعاء المهارة `run-research`.

## Use It

`code/main.py` يجمع أنماط الدروس السابقة في عرض توضيحي واحد قابل للتشغيل. كل stdlib، كلها قيد المعالجة حتى تتمكن من قراءتها من النهاية إلى النهاية. يقوم بتشغيل التدفق الكامل لسيناريو البحث والتقرير: المصافحة مع البوابة، محاكاة OAuth 2.1، دمج الأدوات/القائمة، إنشاء_تقرير كمهمة، A2A استدعاء الكاتب، ui:// إرجاع المورد، انبعاث امتدادات OTel.

ما الذي يجب النظر إليه:

- معرف تتبع واحد عبر كل قفزة.
- سياسة البوابة تمنع المستخدم الثاني من الكتابة.
- دورة حياة المهمة تعمل → مكتملة وترجع كلاً من النص ومحتوى واجهة المستخدم://.
- A2A الحالة الداخلية للمكالمة غير شفافة بالنسبة للمنسق.
- AGENTS.md و SKILL.md هما الملفان الوحيدان اللذان يحتاجهما وكيل آخر لإعادة إنتاج سير العمل.

## Ship It

ينتج عن هذا الدرس `outputs/skill-ecosystem-blueprint.md`. بالنظر إلى حاجة المنتج (البحث، التلخيص، الأتمتة)، تنتج المهارة البنية الكاملة: أي MCP أوليات، أي بوابة تتحكم، أي A2A يستدعي، أي قياس عن بعد، أي تعبئة.

## Exercises

1. قم بتشغيل `code/main.py`. لاحظ معرف التتبع الفردي وكيفية تداخل الامتدادات. قم بإحصاء عدد العناصر الأولية من المرحلة 13 التي لمسها العرض التوضيحي.

2. قم بتوسيع العرض التوضيحي: أضف خادمًا خلفيًا ثانيًا MCP (على سبيل المثال `bibliography`) وتأكد من دمج البوابة لأدواتها في نفس مساحة الاسم.

3. استبدل وكيل الكاتب A2A المزيف بآخر حقيقي يعمل على عملية فرعية. استخدم حزام الدرس 19.

4. أضف خطوة تنقيح PII في بوابة التوجيه بين المُنسق وLLM. يتم مسح رسائل البريد الإلكتروني المؤكدة في استعلام المستخدم.

5. اكتب AGENTS.md لزميلك في الفريق الذي سيحافظ على هذا النظام. يجب أن تستغرق القراءة أقل من خمس دقائق ومنحهم كل ما يحتاجون إليه لقيادة حجر التتويج في المؤشر أو المخطوطة.
