# Roots and Elicitation — Scoping and Mid-Flight User Input

> تنقطع المسارات المشفرة في اللحظة التي يفتح فيها المستخدم مشروعًا مختلفًا. تنقطع وسيطات الأداة المعبأة مسبقًا عندما يقوم المستخدم بالتحديد بشكل أقل. تقوم الجذور بنطاق الخادم إلى مجموعة من معرفات URI التي يتحكم فيها المستخدم؛ يقوم الاستنباط بإيقاف استدعاء منتصف الأداة مؤقتًا لمطالبة المستخدم بإدخال منظم عبر نموذج أو URL. اثنين من العناصر الأولية للعميل، وإصلاحان لأوضاع الفشل MCP الشائعة. SEP-1036 (URL-استنباط الوضع، 2025-11-25) تجريبي حتى H1 2026 — تحقق من إصدارات SDK قبل الاعتماد عليها.

**النوع:** بناء
** اللغات: ** بايثون (stdlib، الجذور + عرض الاستنباط)
**المتطلبات:** المرحلة 13 · 07 (MCP خادم)
**الوقت:** ~45 دقيقة

## Learning Objectives

- أعلن `roots` وأجب على `notifications/roots/list_changed`.
- تقييد عمليات ملفات الخادم على عناوين URI داخل مجموعة الجذر المعلنة.
- استخدم `elicitation/create` لمطالبة المستخدم بتأكيد أو استدعاء منظم للإدخال في منتصف الأداة.
- اختر بين وضع النموذج وURL وضع الاستنباط (الأخير تجريبي؛ تمت الإشارة إلى مخاطر الانجراف).

## The Problem

فشلان ملموسان في الملاحظات MCP الخادم يضرب في الإنتاج.

**افتراض المسار المكسور.** تتم كتابة الخادم مقابل `~/notes`. يحصل مستخدم على جهاز آخر لديه ملاحظات في `~/Documents/Notes` على استدعاء أداة يفشل بصمت (لم يتم العثور على ملف) أو ما هو أسوأ من ذلك، يتم كتابته في المكان الخطأ.

**وسيطة مفقودة قد يعرفها المستخدم.** يطلب المستخدم "احذف ملاحظة تقرير TPS القديمة". يستدعي النموذج `notes_delete(title: "TPS report")` ولكن هناك ثلاث ملاحظات متطابقة من 2023 و2024 و2025. لا يمكن للأداة التخمين. الفشل مع "غامض" أمر مزعج؛ الجري على الثلاثة هو أمر كارثي.

تقوم الجذور بإصلاح الأول: يعلن العميل عند `initialize` مجموعة معرفات URI التي قد يلمسها الخادم. يعمل الاستنباط على إصلاح المشكلة الثانية: يقوم الخادم بإيقاف استدعاء الأداة مؤقتًا ويرسل `elicitation/create` ليطلب من المستخدم اختيار الأداة.

## The Concept

### Roots

يعلن العميل عن قائمة الجذر في `initialize`:

```json
{
  "capabilities": {"roots": {"listChanged": true}}
}
```

يمكن للخادم بعد ذلك الاتصال بـ `roots/list`:

```json
{"roots": [{"uri": "file:///Users/alice/Documents/Notes", "name": "Notes"}]}
```

تعامل الخوادم MUST الجذور باعتبارها الحدود: يتم رفض أي ملف للقراءة أو الكتابة خارج مجموعة الجذر. لا يتم فرض ذلك من قبل العميل (لا يزال الخادم عبارة عن رمز يثق به المستخدم)، ولكن الخوادم المتوافقة مع المواصفات تحترمه.

عندما يقوم المستخدم بإضافة أو إزالة جذر، يرسل العميل `notifications/roots/list_changed`. يقوم الخادم بإعادة استدعاء `roots/list` وتحديث حدوده.

### Why roots are a client primitive

يتم الإعلان عن الجذور من قبل العميل لأنها تمثل نموذج موافقة المستخدم. أخبر المستخدم Claude Desktop "امنح خادم الملاحظات هذا حق الوصول إلى هذين الدليلين". لا يمكن للخادم توسيع هذا النطاق.

### Elicitation: the form-mode default

`elicitation/create` يأخذ مخطط نموذج بالإضافة إلى موجه باللغة الطبيعية:

```json
{
  "method": "elicitation/create",
  "params": {
    "message": "Delete 'TPS report'? Multiple notes match; pick one.",
    "requestedSchema": {
      "type": "object",
      "properties": {
        "note_id": {
          "type": "string",
          "enum": ["note-3", "note-7", "note-14"]
        },
        "confirm": {"type": "boolean"}
      },
      "required": ["note_id", "confirm"]
    }
  }
}
```

يقدم العميل نموذجًا، ويجمع إجابة المستخدم، ويعيد:

```json
{
  "action": "accept",
  "content": {"note_id": "note-14", "confirm": true}
}
```

ثلاثة إجراءات محتملة: `accept` (ملءها المستخدم)، `decline` (أغلقها المستخدم)، `cancel` (ألغى المستخدم استدعاء الأداة بالكامل).

مخططات النماذج مسطحة — الكائنات المتداخلة غير مدعومة في الإصدار 1. ترفض حزم SDK عادةً أي شيء أكثر تعقيدًا من طبقة واحدة.

### Elicitation: URL mode (SEP-1036, experimental)

جديد في 2025-11-25. بدلاً من المخطط، يرسل الخادم URL:

```json
{
  "method": "elicitation/create",
  "params": {
    "message": "Sign in to GitHub",
    "url": "https://github.com/login/oauth/authorize?client_id=..."
  }
}
```

يفتح العميل URL في المتصفح، وينتظر الانتهاء، ويعود عندما يعود المستخدم. مفيد لتدفقات OAuth وتفويض الدفع وتوقيع المستندات عندما يكون النموذج غير كافٍ.

ملاحظة مخاطر الانجراف: شكل الاستجابة SEP-1036 لا يزال مستقرًا؛ تقوم بعض مجموعات SDK بإرجاع رد الاتصال URL، والبعض الآخر يُرجع رمز الإكمال. اقرأ ملاحظات إصدار SDK قبل استخدام وضع URL في الإنتاج.

### When elicitation is the right tool

- تأكيد المستخدم قبل الإجراءات التدميرية (تلميح تدمري + استنباط).
- توضيح (اختر إحدى التطابقات N).
- إعداد التشغيل لأول مرة (API المفاتيح والأدلة والتفضيلات).
- التدفقات بنمط OAuth (الوضع URL).

### When elicitation is wrong

- ملء الحجج المطلوبة للأداة والتي كان من الممكن أن يطلبها النموذج في النثر. استخدم إعادة مطالبة عادية، وليس مربع حوار الاستنباط.
- مكالمات عالية التردد. الاستنباط يقاطع المحادثة. لا تطلقه داخل الحلقة.
- أي شيء يمكن للخادم التحقق منه بعد وقوعه. التحقق من الصحة، وإرجاع خطأ، والسماح للنموذج بسؤال المستخدم في النص.

### Human-in-the-loop bridge

يعمل الاستنباط بالإضافة إلى أخذ العينات معًا على تمكين نموذج MCP "الإنسان في الحلقة". يمكن أن تتوقف حلقة وكيل الخادم مؤقتًا إما لإدخال المستخدم (الاستدلال) أو التفكير النموذجي (أخذ العينات). المرحلة 13 · 11 عينة مغطاة؛ يغطي هذا الدرس الاستنباط. ضعهم معًا للتحكم الكامل في الحلقة المتوسطة.

## Use It

`code/main.py` يقوم بتوسيع خادم الملاحظات من خلال:

- `roots/list` استجابة يقوم الخادم بإعادة الاستعلام عنها بعد إشعارات تغيير قائمة الجذر.
- أداة `notes_delete` تستخدم `elicitation/create` لتوضيح حالة تطابق عدة ملاحظات.
- أداة `notes_setup` تستخدم استنباط الوضع URL لفتح صفحة تكوين يتم تشغيلها لأول مرة (محاكاة).
- فحص الحدود الذي يرفض العمليات على URIs خارج الجذور المعلنة.

يدير العرض التوضيحي ثلاثة سيناريوهات: المسار السعيد (مباراة واحدة)، وتوضيح (ثلاث مباريات، وإطلاق الاستنباط)، والكتابة خارج الجذر (مرفوضة).

## Ship It

ينتج عن هذا الدرس `outputs/skill-elicitation-form-designer.md`. بالنظر إلى الأداة التي قد تحتاج إلى تأكيد المستخدم أو توضيحه، تقوم المهارة بتصميم مخطط نموذج الاستنباط وقالب الرسالة.

## Exercises

1. قم بتشغيل `code/main.py`. إطلاق مسار توضيح؛ تأكد من إعادة توجيه إجابة المستخدم المحاكية إلى الأداة.

2. أضف أداة جديدة `notes_archive` تتطلب تأكيد الاستنباط في كل مرة (تلميح مدمر). تحقق من UX: كيف يمكن مقارنة ذلك بإعادة طرح النموذج في النص؟

3. تنفيذ استنباط الوضع URL لتدفق OAuth الذي يتم تشغيله لأول مرة. لاحظ خطر الانجراف وأضف واقي الإصدار SDK.

4. توسيع معالجة `roots/list`: عند وصول إشعار، يجب على الخادم إعادة قراءة وإعادة فحص مقابض الملفات المفتوحة التي قد تكون الآن خارج النطاق.

5. اقرأ موضوع مناقشة المشكلة SEP-1036 على GitHub. حدد سؤالًا واحدًا مفتوحًا يؤثر على كيفية تعامل الخوادم مع عمليات الاسترجاعات ذات الوضع URL.

## Key Terms

| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| الجذر | "حدود الموافقة" | URI سمح العميل للخادم بلمس |
| `roots/list` | "الخادم يطلب النطاق" | يقوم العميل بإرجاع مجموعة الجذر الحالية |
| `notifications/roots/list_changed` | "قام المستخدم بتغيير النطاق" | يشير العميل إلى أن مجموعة الجذر قد تحورت |
| الاستنباط | "اسأل المستخدم في منتصف المكالمة" | طلب بدأه الخادم لإدخال المستخدم المنظم |
| `elicitation/create` | "الطريقة" | JSON-RPC طريقة طلبات الاستنباط |
| وضع النموذج | "نموذج يحركه المخطط" | مخطط JSON مسطح يتم تقديمه كنموذج في العميل UI |
| URL الوضع | "إعادة توجيه المتصفح" | SEP-1036 تجريبي؛ يفتح URL وينتظر |
| `accept` / `decline` / `cancel` | "نتائج استجابة المستخدم" | ثلاثة فروع يتعامل معها الخادم |
| توضيح | "اختر واحدًا" | حالة استخدام الاستنباط الشائعة عندما تحتوي الأداة على عدد N من المرشحين |
| شكل مسطح | "خصائص المستوى الأعلى فقط" | لا يمكن أن تتداخل مخططات الاستنباط |
