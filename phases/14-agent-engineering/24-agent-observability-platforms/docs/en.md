# Agent Observability: Langfuse, Phoenix, Opik

> تهيمن ثلاث منصات مفتوحة المصدر لرصد الوكلاء على عام 2026. Langfuse (MIT) - أكثر من 6 مليون عملية تثبيت/شهر، تتبع + إدارة سريعة + تقييمات + إعادة تشغيل الجلسة. Arize Phoenix (Elastic 2.0) — تقييمات عميقة خاصة بالعامل، وملاءمة RAG، وأدوات OpenInference التلقائية. Comet Opik (Apache 2.0) — تحسين سريع آلي، حواجز حماية، LLM-اكتشاف الهلوسة.

**النوع:** تعلم
** اللغات: ** بايثون (stdlib)
** المتطلبات الأساسية: ** المرحلة 14 · 23 (OTel GenAI)
**الوقت:** ~45 دقيقة

## Learning Objectives

- قم بتسمية أفضل ثلاث منصات لرصد الوكيل مفتوحة المصدر وتراخيصها.
- ميز ما هو أقوى كل واحد في: Langfuse (إدارة سريعة + جلسات)، Phoenix (RAG + الأجهزة التلقائية)، Opik (التحسين + الدرابزين).
- اشرح سبب قيام 89% من المؤسسات بالإبلاغ عن وجود إمكانية ملاحظة الوكيل بحلول عام 2026.
- تنفيذ تتبع stdlib إلى لوحة المعلومات pipeline مع تقييم LLM-القاضي.

## The Problem

يمنحك OTel GenAI (الدرس 23) المخطط. لا تزال بحاجة إلى النظام الأساسي الذي يستوعب الامتدادات، ويدير التقييمات، ويخزن الإصدارات السريعة، ويكشف التراجعات. يركز كل من المتنافسين الثلاثة على أجزاء مختلفة من دورة الحياة.

## The Concept

### Langfuse (MIT)

- 6 ملايين+ SDK عمليات التثبيت/الشهر، 19 ألف+ GitHub نجوم.
- الميزات: التتبع، الإدارة السريعة مع الإصدار + الملعب، التقييمات (LLM-حكم، تعليقات المستخدم، مخصص)، إعادة الجلسة.
- يونيو 2025: الوحدات التجارية سابقًا (LLM-كحكم، قوائم انتظار التعليقات التوضيحية، التجارب الفورية، ساحة اللعب) مفتوحة المصدر تحت MIT.
- الأقوى من أجل: إمكانية المراقبة الشاملة من خلال حلقة إدارة سريعة محكمة.

### Arize Phoenix (Elastic License 2.0)

- تقييم أعمق خاص بالعامل: تجميع التتبع، والكشف عن الحالات الشاذة، وملاءمة الاسترجاع لـ RAG.
- الأجهزة التلقائية OpenInference الأصلية.
- أزواج مع Arize المدارة AX للإنتاج.
- لا يوجد إصدار سريع - يتم وضعه كأداة للانجراف/الانحدار السلوكي إلى جانب منصات أوسع.
- الأقوى من أجل: RAG الملاءمة، والانحراف السلوكي، والكشف عن الشذوذ.

### Comet Opik (Apache 2.0)

- التحسين الفوري الآلي من خلال تجارب A/B.
- الدرابزين (PII التنقيح، القيود الموضعية).
- LLM- كشف الهلوسة القاضية.
- المعيار من قياس Comet الخاص: سجلات Opik + التقييمات في 23.44 ثانية مقابل Langfuse 327.15s (فجوة 14x تقريبًا) - خذ معايير البائع كتوجيه.
- الأقوى في: حلقة التحسين، والتجريب الآلي، وإنفاذ الدرابزين.

### Industry data

وفقًا لمكسيم (التحليل الميداني لعام 2026): 89% من المؤسسات لديها إمكانية ملاحظة الوكيل؛ تعتبر قضايا الجودة أكبر عائق أمام الإنتاج (32% من المشاركين يشيرون إليها).

### Picking one

| بحاجة | اختر |
|------|------|
| الكل في واحد مع الإدارة السريعة | لانجفيوز |
| تقييم عميق RAG + انجراف | فينيكس |
| التحسين الآلي + الدرابزين | أوبيك |
| ترخيص مفتوح، لا يوجد ELv2 | لانغفيوز (MIT) أو أوبيك (أباتشي 2.0) |
| تكامل Datadog / New Relic | أي — كلهم ​​يصدرون OTel |

### Where this pattern goes wrong

- **لا توجد استراتيجية للتقييم.** التتبع بدون تقييم هو مجرد عملية تسجيل مكلفة.
- **حكم ذاتي LLM بدون تأريض.** ينطبق نمط CRITIC (الدرس 05) — يحتاج القضاة إلى أدوات خارجية للتحقق من الحقائق.
- **إصدارات الموجهات غير مرتبطة بالتتبعات.** عندما يتراجع المنتج، لا يمكنك تقسيم الموجه الذي تسبب في ذلك.

## Build It

`code/main.py` ينفذ أداة تجميع التتبع stdlib + LLM- مقيم القاضي:

- استيعاب امتدادات على شكل GenAI.
- المجموعة حسب الجلسة، علامات التشغيل الفاشلة (رحلات الدرابزين، تقييمات الثقة المنخفضة).
- قاضي مكتوب LLM يسجل ردود الوكيل على نموذج التقييم.
- ملخص يشبه لوحة المعلومات: معدل الفشل، وأهم أسباب الفشل، وتوزيع درجات التقييم.

تشغيله:

```
python3 code/main.py
```

المخرجات: نتائج التقييم لكل جلسة وتصنيف الفشل المطابق لما سيظهره Langfuse/Phoenix/Opik.

## Use It

- **Langfuse** استضافة ذاتية أو سحابية؛ سلك عبر OTel أو SDK.
- **Arize Phoenix** مستضافة ذاتيًا؛ أداة تلقائية OpenInference.
- **Comet Opik** مستضاف ذاتيًا أو سحابيًا؛ حلقة التحسين الآلي.
- **Datadog LLM إمكانية المراقبة** للعمليات المختلطة + ML الفرق التي تدير Datadog بالفعل.

## Ship It

`outputs/skill-obs-platform-wiring.md` يختار النظام الأساسي ويتتبع الأسلاك + التقييمات + إصدارات المطالبة إلى وكيل موجود.

## Exercises

1. قم بتصدير أسبوع من آثار OTel إلى سحابة Langfuse (الطبقة المجانية). ما هي الجلسات التي فشلت؟ لماذا؟
2. اكتب LLM-حكم للمجال الخاص بك (الصحة الواقعية، النبرة، الالتزام بالنطاق). اختبار على 50 آثار.
3. قارن بين إصدار Langfuse الفوري ومجموعات التتبع الخاصة بـ Phoenix. الذي يخبرك ما الذي كسر بشكل أسرع؟
4. اقرأ مستندات حاجز حماية Opik. قم بتوصيل حاجز الحماية PII إلى أحد عملاءك.
5. قم بقياس الثلاثة في مجموعتك. تجاهل الأرقام المنشورة من قبل البائع؛ قياس بنفسك.

## Key Terms

| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| تتبع | "جامع الامتدادات" | استيعاب OTel / SDK يمتد؛ فهرس حسب الجلسة |
| الإدارة السريعة | "مطالبة CMS" | المطالبات الصادرة مرتبطة بآثار |
| LLM-كالقاضي | "التقييم الآلي" | منفصل LLM يسجل مخرجات الوكيل مقابل نموذج تقييم |
| إعادة الجلسة | "تشغيل التتبع" | خطوة خلال عمليات التشغيل السابقة لتصحيح الأخطاء |
| RAG الصلة | "جودة الاسترجاع" | هل يتطابق السياق المسترد مع الاستعلام |
| تتبع التجميع | "التجمع السلوكي" | تشغيل الكتلة مماثلة للكشف عن الانجراف |
| إنفاذ الدرابزين | "السياسة في وقت السجل" | PII/السمية/فحص النطاق للمحتوى المسجل |
