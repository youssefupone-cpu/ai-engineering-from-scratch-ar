# الوكلاء الصوتيون: Pipecat وLiveKit
> يعد وكلاء الصوت فئة إنتاج من الدرجة الأولى في عام 2026. تمنحك Pipecat خط pipeline القائم على إطار Python (VAD → STT → LLM → TTS → النقل). يقوم وكلاء LiveKit بتوصيل نماذج AI إلى المستخدمين عبر WebRTC. يستهدف زمن الوصول للإنتاج ما بين 450 إلى 600 مللي ثانية من البداية إلى النهاية للمجموعات المتميزة.
**النوع:** تعلم
** اللغات: ** بايثون (stdlib)
** المتطلبات الأساسية: ** المرحلة 14 · 01 (حلقة الوكيل)، المرحلة 14 · 12 (أنماط سير العمل)
**الوقت:** ~60 دقيقة
## أهداف التعلم
- وصف الخط القائم على إطار Pipecat pipeline: DOWNSTREAM (المصدر → الحوض) وUPSTREAM (التحكم).
- قم بتسمية المراحل الصوتية الأساسية pipeline والتي تنقل دعم Pipecat.
- شرح فئتي وكيل الصوت الخاصين بـ LiveKit Agents (MultimodalAgent وVoicePipelineAgent) ومتى يناسب كل منهما.
- تلخيص توقعات زمن الوصول للإنتاج لعام 2026 وكيف تقود خيارات الهندسة المعمارية.
## المشكلة
الوكلاء الصوتيون ليسوا حلقة نصية مع TTS مثبتة بمسامير. ميزانيات زمن الاستجابة قاسية (~600 مللي ثانية)، والصوت الجزئي هو الإعداد الافتراضي، واكتشاف الانعطاف هو نموذج، وتتراوح عمليات النقل من الهاتف SIP إلى WebRTC. إما أن تقوم بإنشاء خط pipeline قائم على الإطار (Pipecat) أو أن تتكئ على النظام الأساسي (LiveKit).
##المفهوم
### بيبيكات (pipecat-ai/pipecat)
- إطار عمل pipeline القائم على إطار بايثون.
- `Frame` → `FrameProcessor` سلسلة.
- اتجاهين للتدفق:
  - **DOWNSTREAM** — المصدر → الحوض (مدخل الصوت، TTS خارج).
  - **UPSTREAM** — ردود الفعل والتحكم (الإلغاء، والمقاييس، والدخول).
- `PipelineTask` يدير دورة الحياة باستخدام الأحداث (`on_pipeline_started`، `on_pipeline_finished`، `on_idle_timeout`) ومراقبي المقاييس/التتبع/RTVI.
النموذجي pipeline:
```
VAD (Silero) → STT → LLM (context alternates user/assistant) → TTS → transport
```

وسائل النقل: يوميًا، وLiveKit، وSmallWebRTCTransport، وFastAPI WebSocket، وWhatsApp.
تضيف Pipecat Flows محادثات منظمة (أجهزة الحالة). Pipecat Cloud هو وقت التشغيل المُدار.
### وكلاء LiveKit (مجموعة أدوات حية/وكلاء)
- توصيل نماذج AI إلى المستخدمين عبر WebRTC.
- المفاهيم الأساسية: `Agent`، `AgentSession`، `entrypoint`، `AgentServer`.
- فئتان للوكيل الصوتي:
  - **MultimodalAgent** — صوت مباشر عبر OpenAI الوقت الفعلي أو ما يعادله.
  - **VoicePipelineAgent** — STT → LLM → TTS تتالي؛ يعطي التحكم على مستوى النص.
- الكشف الدلالي عن طريق نموذج المحولات.
- التكامل الأصلي MCP.
- الاتصال الهاتفي عبر SIP.
- أكثر من 50 طرازًا بدون مفاتيح API عبر LiveKit Inference؛ أكثر من 200+ عبر المكونات الإضافية.
### المنصات التجارية
يعتمد Vapi (~ 450-600 مللي ثانية على مكدس متميز محسّن) و Retell (~ 600 مللي ثانية شاملة عبر 180 مكالمة اختبار) على رأس هذه العناصر. اختر منصة عندما تريد حزمة صوتية مُدارة بدون فريق WebRTC.
### أين يسير هذا النمط بشكل خاطئ
- ** لا يوجد التعامل مع البارجة. ** مقاطعة المستخدم؛ الوكيل يواصل الحديث. يتطلب إلغاء إطارات UPSTREAM في Pipecat، أي ما يعادلها في LiveKit.
- **STT تم تجاهل الثقة.** تم تغذية النصوص منخفضة الثقة إلى LLM كما لو كانت من الإنجيل. بوابة على الثقة أو تأكيد الطلب.
- **TTS قطع في منتصف الجملة.** عندما يلغي سطر pipe منتصف الكلام، يحتاج TTS إلى معرفة الصوت أو قطعه.
- **تم تجاهل ميزانية زمن الوصول.** يضيف كل مكون ما بين 50 إلى 200 مللي ثانية. اجمع سلسلتك قبل الشحن.
### زمن الاستجابة النموذجي لعام 2026
- VAD: 20–60 مللي ثانية
- STT جزئي: 100-250 مللي ثانية
- LLM الرمز المميز الأول: 150-400 مللي ثانية
- TTS الصوت الأول: 100-200 مللي ثانية
- النقل RTT: 30-80 مللي ثانية
يعتبر النطاق 450-600 مللي ثانية من النهاية إلى النهاية ممتازًا. 800-1200 مللي ثانية أمر شائع. أي شيء> 1500 مللي ثانية يشعر بالكسر.
## بنائها
`code/main.py` هي لعبة قائمة على الإطار pipeline مع:
- أنواع `Frame` (الصوت، النص، النص، tts_audio، التحكم).
- واجهة `Processor` مع `process(frame)`.
- خط pipe ذو خمس مراحل (VAD → STT → LLM → TTS → النقل) كمعالجات مكتوبة.
- إطار إلغاء UPSTREAM لتوضيح عملية الدخول.
تشغيله:
```
python3 code/main.py
```

يُظهر التتبع التدفق الطبيعي وإلغاء الإدخال الذي يوقف TTS في منتصف الكلام.
## استخدمه
- **Pipecat** للتحكم الكامل — معالجات مخصصة، Python-first، موفري خدمات قابلين للتوصيل.
- **وكلاء LiveKit** لعمليات النشر والاتصال الهاتفي لـ WebRTC أولاً.
- **Vapi / Retell** لوكلاء الصوت المستضافين بدون فريق WebRTC.
- **OpenAI Realtime / Gemini Live** للإدخال/الإخراج الصوتي المباشر (MultimodalAgent).

`outputs/skill-voice-pipeline.md` يدعم صوتًا على شكل Pipecat pipeline مع VAD + STT + LLM + TTS + النقل بالإضافة إلى التعامل مع البارجة.
## تمارين
1. أضف مراقب مقاييس إلى لعبتك pipeline: قم بحساب الإطارات لكل مرحلة في الثانية. أين يتراكم الكمون؟
2. تنفيذ بوابة الثقة STT: أقل من الحد الأدنى، اطلب "هل يمكنك تكرار ذلك؟"
3. أضف ميزة اكتشاف الانعطاف الدلالي: قاعدة بسيطة — إذا كان النص ينتهي بـ "؟"، نهاية المنعطف.
4. اقرأ مستندات النقل الخاصة بـ Pipecat. قم بتبديل نقل stdlib بتكوين SmallWebRTCTransport (كعب الروتين).
5. قم بقياس OpenAI الوقت الفعلي مقابل STT+LLM+TTS المتتالية على نفس الاستعلام. ما هي تكلفة زمن الوصول التي يتحملها التحكم على مستوى النص؟
## المصطلحات الرئيسية
| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| الإطار | "الحدث" | وحدة البيانات المكتوبة في السطر pipeline (الصوت، النص، النص، التحكم) |
| المعالج | "مرحلة خط الأنابيب" | معالج مع العملية (الإطار) |
| المصب | "التدفق إلى الأمام" | مصدر للغرق: الصوت في، الكلام خارج |
| المنبع | "تدفق الملاحظات" | التحكم: الإلغاء، المقاييس، المشاركة |
| __المصطلح_1__ | "كشف النشاط الصوتي" | يكتشف عندما يتحدث المستخدم |
| كشف المنعطف الدلالي | "نهاية المنعطف الذكية" | القرار المبني على النموذج بأن المستخدم قد انتهى |
| وكيل الوسائط المتعددة | "وكيل الصوت المباشر" | صوت داخل، صوت خارج؛ لا يوجد نص في المنتصف |
| وكيل VoicePipeline | "وكيل تتالي" | STT + LLM + TTS؛ التحكم على مستوى النص |
