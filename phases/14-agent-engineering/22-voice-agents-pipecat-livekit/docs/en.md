# Voice Agents: Pipecat and LiveKit

> يعد وكلاء الصوت فئة إنتاج من الدرجة الأولى في عام 2026. تمنحك Pipecat خطًا قائمًا على إطار بايثون pipeline (VAD → STT → LLM → TTS → نقل). يقوم LiveKit Agents بتوصيل نماذج AI للمستخدمين عبر WebRTC. يستهدف زمن الوصول للإنتاج ما بين 450 إلى 600 مللي ثانية من البداية إلى النهاية للمجموعات المتميزة.

**النوع:** تعلم
** اللغات: ** بايثون (stdlib)
** المتطلبات الأساسية: ** المرحلة 14 · 01 (حلقة الوكيل)، المرحلة 14 · 12 (أنماط سير العمل)
**الوقت:** ~60 دقيقة

## Learning Objectives

- وصف خط Pipecat القائم على الإطار pipeline: DOWNSTREAM (المصدر → الحوض) وUPSTREAM (التحكم).
- تسمية الصوت الكنسي pipمراحل الخط والذي يدعمه Pipecat.
- شرح فئتي وكيل الصوت الخاصين بـ LiveKit Agents (MultimodalAgent وVoicePipelineAgent) ومتى يناسب كل منهما.
- تلخيص توقعات زمن الوصول للإنتاج لعام 2026 وكيف تقود خيارات الهندسة المعمارية.

## The Problem

الوكلاء الصوتيون ليسوا حلقة نصية مثبت عليها TTS. ميزانيات وقت الاستجابة قاسية (حوالي 600 مللي ثانية)، والصوت الجزئي هو الإعداد الافتراضي، واكتشاف الانعطاف هو نموذج، وتتراوح عمليات النقل من الاتصال الهاتفي SIP إلى WebRTC. إما أن تقوم ببناء خط pipeline (Pipecat) قائم على الإطار أو أن تتكئ على منصة (LiveKit).

## The Concept

### Pipecat (pipecat-ai/pipecat)

- إطار عمل pipeline قائم على إطار بايثون.
- `Frame` → `FrameProcessor` السلسلة.
- اتجاهين للتدفق: - **التدفق السفلي** — المصدر → الحوض (دخل الصوت، TTS خارج). - **UPSTREAM** — ردود الفعل والتحكم (الإلغاء، والمقاييس، والدخول).
- `PipelineTask` يدير دورة الحياة باستخدام الأحداث (`on_audioeline_started`، `on_ineline_finished`، `on_idle_timeout`) ومراقبي المقاييس/التتبع/RTVI.

نموذجي pipeline:

```
VAD (Silero) → STT → LLM (context alternates user/assistant) → TTS → transport
```

وسائل النقل: يوميًا، LiveKit، SmallWebRTCTransport، FastAPI WebSocket، WhatsApp.

تضيف Pipecat Flows محادثات منظمة (أجهزة الحالة). Pipecat Cloud هو وقت التشغيل المُدار.

### LiveKit Agents (livekit/agents)

- نماذج الجسور AI للمستخدمين عبر WebRTC.
- المفاهيم الأساسية: `Agent`، `AgentSession`، `entrypoint`، `AgentServer`.
- فئتان للوكيل الصوتي: - **MultimodalAgent** — صوت مباشر عبر OpenAI الوقت الفعلي أو ما يعادله. - **VoicePipelineAgent** — STT → LLM → TTS تتالي؛ يعطي التحكم على مستوى النص.
- الكشف الدلالي عن طريق نموذج المحولات.
- التكامل MCP الأصلي.
- الاتصال الهاتفي عبر SIP.
- أكثر من 50 نموذجًا بدون مفاتيح API عبر LiveKit Inference؛ أكثر من 200+ عبر المكونات الإضافية.

### Commercial platforms

يعتمد Vapi (~ 450-600 مللي ثانية على مكدس متميز محسّن) و Retell (~ 600 مللي ثانية شاملة عبر 180 مكالمة اختبار) على رأس هذه العناصر. اختر منصة عندما تريد حزمة صوتية مُدارة بدون فريق WebRTC.

### Where this pattern goes wrong

- ** لا يوجد التعامل مع البارجة. ** مقاطعة المستخدم؛ الوكيل يواصل الحديث. يتطلب إلغاء إطارات UPSTREAM في Pipecat، أي ما يعادلها في LiveKit.
- **STT تجاهل الثقة.** تغذي النصوص منخفضة الثقة إلى LLM كما لو كان الإنجيل. بوابة على الثقة أو تأكيد الطلب.
- **TTS قطع منتصف الجملة.** عندما يلغي السطر pip منتصف الكلام، يحتاج TTS إلى معرفة الصوت أو قطعه.
- **تم تجاهل ميزانية زمن الوصول.** يضيف كل مكون ما بين 50 إلى 200 مللي ثانية. اجمع سلسلتك قبل الشحن.

### Typical 2026 latencies

- VAD: 20–60 مللي ثانية
- STT جزئي: 100–250 مللي ثانية
- LLM الرمز الأول: 150-400 مللي ثانية
- TTS الصوت الأول: 100-200 مللي ثانية
- النقل RTT: 30-80 مللي ثانية

يعتبر النطاق 450-600 مللي ثانية من النهاية إلى النهاية ممتازًا. 800-1200 مللي ثانية أمر شائع. أي شيء> 1500 مللي ثانية يشعر بالكسر.

## Build It

`code/main.py` هي لعبة قائمة على الإطار pipeline مع:

- `Frame` الأنواع (الصوت، النص، النص، tts_audio، التحكم).
- `Processor` الواجهة مع `process(frame)`.
- خط pipe ذو خمس مراحل (VAD → STT → LLM → TTS → نقل) كمعالجات مكتوبة.
- إطار إلغاء UPSTREAM لتوضيح عملية الدخول.

تشغيله:

```
python3 code/main.py
```

يُظهر التتبع التدفق الطبيعي وإلغاء البارجة الذي يتوقف TTS في منتصف الكلام.

## Use It

- **Pipecat** للتحكم الكامل — معالجات مخصصة، Python-first، موفري خدمات قابلين للتوصيل.
- **وكلاء LiveKit** لعمليات النشر والاتصال الهاتفي لـ WebRTC أولاً.
- **Vapi / Retell** لوكلاء الصوت المستضافين بدون فريق WebRTC.
- **OpenAI Realtime / Gemini Live** لإدخال الصوت/إخراج الصوت المباشر (MultimodalAgent).

## Ship It

`outputs/skill-voice-pipelineeline.md` سقالات على شكل Pipecat pipeline مع VAD + STT + LLM + TTS + النقل بالإضافة إلى التعامل مع البارجة.

## Exercises

1. أضف مراقب المقاييس إلى لعبتك pipeline: عد الإطارات لكل مرحلة في الثانية. أين يتراكم الكمون؟
2. تنفيذ بوابة الثقة STT: أقل من الحد الأدنى، اطلب "هل يمكنك تكرار ذلك؟"
3. أضف ميزة اكتشاف الانعطاف الدلالي: قاعدة بسيطة — إذا كان النص ينتهي بـ "؟"، نهاية المنعطف.
4. اقرأ مستندات النقل الخاصة بـ Pipecat. قم بتبديل نقل stdlib بتكوين SmallWebRTCTransport (كعب الروتين).
5. قياس OpenAI الوقت الحقيقي مقابل STT+LLM+TTS تتالي على نفس الاستعلام. ما هي تكلفة زمن الوصول التي يتحملها التحكم على مستوى النص؟

## Key Terms

| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| الإطار | "الحدث" | وحدة البيانات المكتوبة في الخط pipe (الصوت، النص، النص، التحكم) |
| المعالج | "مرحلة خط الأنابيب" | معالج مع العملية (الإطار) |
| المصب | "التدفق إلى الأمام" | مصدر للغرق: الصوت في، الكلام خارج |
| المنبع | "تدفق الملاحظات" | التحكم: الإلغاء، المقاييس، المشاركة |
| VAD | "كشف النشاط الصوتي" | يكتشف عندما يتحدث المستخدم |
| كشف المنعطف الدلالي | "نهاية المنعطف الذكية" | القرار المبني على النموذج بأن المستخدم قد انتهى |
| وكيل الوسائط المتعددة | "وكيل الصوت المباشر" | صوت داخل، صوت خارج؛ لا يوجد نص في المنتصف |
| وكيل VoicePipeline | "وكيل تتالي" | STT + LLM + TTS; التحكم على مستوى النص |
