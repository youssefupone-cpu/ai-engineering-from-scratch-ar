# LangGraph: Stateful Graphs and Durable Execution

> LangGraph هو مرجع 2026 لتنسيق الحالة منخفض المستوى. الوكيل هو آلة الدولة. nodes هي وظائف؛ الحواف هي التحولات. الحالة غير قابلة للتغيير ويتم فحصها بعد كل خطوة. استئناف من أي فشل بالضبط حيث توقفت.

** النوع: ** تعلم + بناء
** اللغات: ** بايثون (stdlib)
** المتطلبات الأساسية: ** المرحلة 14 · 01 (حلقة الوكيل)، المرحلة 14 · 12 (أنماط سير العمل)
**الوقت:** ~75 دقيقة

## Learning Objectives

- وصف النموذج الأساسي لـ LangGraph: آلة الحالة ذات الحالة غير القابلة للتغيير، والوظيفة nodes، والحواف الشرطية، ونقاط التفتيش بعد الخطوة.
- قم بتسمية الإمكانات الأربع التي تبرزها المستندات: التنفيذ الدائم، والبث المباشر، والذاكرة الشاملة.
- شرح طبولوجيا التنسيق الثلاثة التي يدعمها LangGraph: المشرف، ونظير إلى نظير (السرب)، والتسلسل الهرمي (الرسوم البيانية الفرعية المتداخلة).
- تنفيذ رسم بياني لحالة stdlib مع حالة غير قابلة للتغيير، وحواف شرطية، ونقطة تفتيش/دورة استئناف.

## The Problem

يتشارك الوكلاء ومهام سير العمل في مشكلة: عندما يفشل التشغيل المكون من 40 خطوة في الخطوة 38، فأنت تريد الاستئناف من الخطوة 38، وليس البدء من جديد. نماذج الحالة من الدرجة الثانية تترك المشغلين يقومون باختراق عمليات إعادة المحاولة حول المكتبة التي تفترض عمليات تشغيل جديدة.

إجابة تصميم LangGraph: الحالة هي كائن مكتوب من الدرجة الأولى، والطفرات واضحة، ونقاط التفتيش تستمر بعد كل node. السيرة الذاتية هي مكالمة `load_state(session_id)`.

## The Concept

### The graph

يتم تعريف الرسم البياني بواسطة:

- **نوع الحالة.** إملاء مكتوب (أو نموذج Pydantic) يقرأه كل node ويتحول.
- **العقد.** الوظائف البحتة `(state) -> state_update`. يتم دمج التحديثات في الحالة بعد العودة.
- **الحواف.** انتقالات مشروطة أو مباشرة بين nodes.
- **الدخول والخروج.** `START` و `END` الحارس nodes يحددان الحدود.

مثال: وكيل يحتوي على `classify`، `refund`، `bug`، `sales`، `done` nodes — سير عمل التوجيه كرسم بياني.

### Durable execution

بعد كل إرجاع node، يقوم وقت التشغيل بتسلسل الحالة وكتابتها إلى نقطة التفتيش (SQLite، Postgres، Redis، custom). في حالة الفشل في الخطوة N، يمكن لوقت التشغيل أن `resume(session_id)` ويلتقط من الخطوة N+1 بالحالة الدقيقة.

تسلط مستندات LangGraph الضوء بوضوح على مستخدمي الإنتاج حيث يكون ذلك مهمًا: Klarna، وUber، وJ.P. Morgan. المطالبة ليست شكل الرسم البياني؛ إنه شكل الرسم البياني بالإضافة إلى نقاط التفتيش makes الانتعاش رخيصة.

### Streaming

يمكن لكل node أن ينتج مخرجات جزئية. يتدفق الرسم البياني لكل أحداث node-دلتا للمتصل بحيث يتم تحديث واجهات المستخدم أثناء تشغيل الرسم البياني.

### Human-in-the-loop

فحص وتعديل الحالة بين nodes. عمليات التنفيذ: توقف مؤقتًا قبل node الحرجة، حالة السطح للإنسان، قبول التعديلات، الاستئناف. نقطة التفتيش make بهذه السهولة لأن الحالة متسلسلة بالفعل.

### Memory

قصير المدى (ضمن التشغيل - سجل المحادثة في الحالة) وطويل الأجل (عبر التشغيل - مستمر عبر نقطة التفتيش بالإضافة إلى مخزن منفصل طويل الأجل). يتكامل LangGraph مع أنظمة الذاكرة الخارجية (Mem0، Custom) عبر الأدوات.

### Three topologies

1. **المشرف.** يرسل جهاز التوجيه المركزي LLM إلى الوكلاء الفرعيين المتخصصين. `create_supervisor()` في `langgraph-supervisor` (على الرغم من أن فريق LangChain في عام 2026 يوصي بالقيام بذلك من خلال استدعاءات الأداة مباشرة لمزيد من التحكم في السياق).
2. **السرب / نظير إلى نظير.** يقوم الوكلاء بتسليم المهام مباشرة عبر سطح أداة مشترك. لا يوجد جهاز توجيه مركزي.
3. **التسلسل الهرمي.** المشرفون يديرون المشرفين الفرعيين، ويتم تنفيذهم كرسوم بيانية فرعية متداخلة.

### Where this pattern goes wrong

- **نقاط التفتيش صغيرة جدًا.** يتم تشغيل المحادثة عند نقاط التفتيش فقط مما يجعل حالة الأداة وعمليات الكتابة في الذاكرة غير قابلة للاسترداد. يجب إجراء تسلسل الحالة الكاملة.
- **غير حتمية nodes.** تفترض السيرة الذاتية أن المدخلات node تنتج نفس تحديث الحالة. يجب التقاط البذور العشوائية ساعة حائط خارجية APIs.
- **الإفراط في استخدام الحواف الشرطية.** الرسم البياني مع كل حافة شرطية هو آلة حالة لا يمكن التفكير فيها. تفضل السلاسل الخطية ذات الفروع العرضية.

## Build It

`code/main.py` ينفذ الرسم البياني ذو الحالة stdlib:

- `State` — إملاء مكتوب باستخدام `messages`، `step`، `route`، `output`، `human_approval`.
- `Node` — أخذ الحالة القابلة للاستدعاء وإرجاع أمر التحديث.
- `StateGraph` — nodes + حواف + حواف شرطية + تشغيل + استئناف.
- `SQLiteCheckpointer` (مزيفة في الذاكرة) — إجراء تسلسل للحالة بعد كل node؛ `load(session_id)` يستعيد.
- رسم بياني تجريبي: تصنيف -> فرع (استرداد / خطأ / مبيعات) -> بوابة بشرية -> إرسال.

تشغيله:

```
python3 code/main.py
```

يُظهر التتبع فشل التشغيل الأول عند البوابة البشرية، والمثابرة، ثم استئناف إنتاج الناتج النهائي.

## Use It

- **LangGraph** — مرجع جاهز للإنتاج. استخدم `create_react_agent`، `create_supervisor`، أو قم بإنشاء الرسم البياني الخاص بك.
- **AutoGen v0.4** (الدرس 14) — نموذج الممثل البديل لسيناريوهات التزامن العالي.
- **Claude Agent SDK** (الدرس 17) — مجموعة أدوات مُدارة مع مخزن جلسات مدمج.
- **مخصص** — عندما تحتاج إلى تحكم دقيق في شكل الحالة أو الواجهة الخلفية لنقطة التفتيش.

## Ship It

`outputs/skill-state-graph.md` ينشئ رسمًا بيانيًا للحالة على شكل LangGraph في أي وقت تشغيل مستهدف مع نقاط التفتيش والاستئناف السلكية.

## Exercises

1. أضف حافة شرطية من `classify` إلى `end` عندما تكون ثقة التصنيف أقل من الحد. استأنف التشغيل بعد قيام الإنسان بالضبط `route` يدويًا.
2. استبدل النسخة المزيفة التي تشبه SQLite بنقطة تفتيش SQLite حقيقية. قياس الحمل التسلسلي لكل خطوة.
3. تنفيذ الحواف المتوازية: يتم تشغيل اثنين من node بشكل متزامن، ويتم دمجهما بواسطة مخفض مخصص. ما الذي تشتريه الدولة غير القابلة للتغيير هنا؟
4. اقرأ المرجع `langgraph-supervisor`. قم بنقل اللعبة إلى `create_supervisor`. قارن أشكال التتبع.
5. إضافة البث: كل node ينتج عنه حالة جزئية أثناء تشغيله. اطبع الدلتا فور وصولها.

## Key Terms

| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| الرسم البياني للدولة | "الوكيل كآلة دولة" | الحالة المكتوبة + nodes + الحواف + المخفضات |
| نقطة تفتيش | "الواجهة الخلفية المستمرة" | تسلسل الحالة بعد كل node؛ تمكن استئناف |
| المخفض | "اندماج الدولة" | وظيفة تجمع بين الحالة الحالية وتحديث node |
| الحافة الشرطية | "فرع" | الحافة المختارة بواسطة دالة الحالة |
| رسم بياني فرعي | "رسم بياني متداخل" | رسم بياني يستخدم كـ node داخل رسم بياني آخر |
| تنفيذ متين | "الاستئناف من الفشل" | أعد التشغيل عند آخر نجاح node بالحالة الدقيقة |
| المشرف | "راوتر LLM" | مرسل مركزي للوكلاء الفرعيين المتخصصين |
| سرب | "P2P وكلاء" | يقوم الوكلاء بالتسليم عبر الأدوات المشتركة؛ لا يوجد جهاز توجيه مركزي |
