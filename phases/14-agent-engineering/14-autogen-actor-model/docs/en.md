# AutoGen v0.4: Actor Model and Agent Framework

> AutoGen v0.4 (أبحاث Microsoft، يناير 2025) أعاد تصميم تنسيق الوكيل حول نموذج الممثل. تبادل الرسائل غير المتزامنة، الوكلاء الموجهون بالحدث، عزل الأخطاء، التزامن الطبيعي. إطار العمل الآن في وضع الصيانة بينما يصبح Microsoft Agent Framework (المعاينة العامة في أكتوبر 2025) هو الوريث.

** النوع: ** تعلم + بناء
** اللغات: ** بايثون (stdlib)
** المتطلبات الأساسية: ** المرحلة 14 · 01 (حلقة الوكيل)، المرحلة 14 · 12 (أنماط سير العمل)
**الوقت:** ~75 دقيقة

## Learning Objectives

- وصف نموذج الممثل: الوكلاء كممثلين، الرسائل باعتبارها IPC الوحيدة، عزل الفشل لكل ممثل.
- قم بتسمية طبقات API الثلاث الخاصة بـ AutoGen v0.4 — Core وAgentChat وExtensions — والغرض من كل منها.
- اشرح لماذا يؤدي فصل تسليم الرسالة عن المعالجة إلى عزل الخطأ والتزامن الطبيعي.
- تنفيذ وقت تشغيل ممثل stdlib في Python ونقل تدفق مراجعة التعليمات البرمجية من وكيلين إليه.

## The Problem

معظم أطر عمل الوكيل متزامنة: وكيل واحد ينتج وكيل واحد يستهلك في مكدس الاستدعاءات. فشل تعطل المكدس. تم تثبيت التزامن. التوزيع يتطلب إعادة الكتابة.

إجابة AutoGen v0.4: نموذج الممثل. كل وكيل هو ممثل لديه صندوق بريد خاص. الرسائل هي التفاعل الوحيد. وقت التشغيل يفصل التسليم عن المعالجة. الفشل ينحصر في فاعل واحد. التزامن أصلي. التوزيع هو مجرد نقل مختلف.

## The Concept

### Actors

الممثل لديه:

- دولة خاصة (لا تمسها مباشرة من الخارج).
- صندوق الوارد (قائمة انتظار الرسائل).
- معالج: `receive(message) -> effects` حيث يمكن أن تكون التأثيرات "رد"، "إرسال إلى ممثل آخر"، "إنشاء ممثل جديد"، "تحديث الحالة"، "إيقاف ذاتي".

لا يمكن لممثلين مشاركة الذاكرة. يمكنهم فقط إرسال الرسائل.

### Three API layers in AutoGen v0.4

1. **الأساسية.** إطار عمل الممثل منخفض المستوى. `AgentRuntime`، `Agent`، `Message`، `Topic`. تبادل الرسائل غير المتزامنة، يحركها الحدث.
2. **AgentChat.** مستوى عالٍ يعتمد على المهام API (بديل لـ ConversableAgent الإصدار 0.2). `AssistantAgent`، `UserProxyAgent`، `RoundRobinGroupChat`، `SelectorGroupChat`.
3. **الامتدادات.** التكامل — OpenAI، أنثروبي، أزور، أدوات، ذاكرة.

### Why decoupling matters

في نموذج v0.2، يؤدي استدعاء `agent_a.chat(agent_b)` إلى حظر الوكيل_a بشكل متزامن حتى يعود الوكيل_b. في الإصدار 0.4، يضع `send(agent_b, msg)` الرسالة في صندوق الوارد الخاص بـ agent_b ويعيدها. وقت التشغيل يسلم في وقت لاحق. ثلاث عواقب:

- **عزل الأخطاء.** لا يؤدي تعطل العامل B إلى تعطل العامل A — يكتشف وقت التشغيل الفشل في معالج B ويقرر ما يجب فعله (التسجيل، إعادة المحاولة، الرسالة الميتة).
- **التزامن الطبيعي.** العديد من الرسائل في الرحلة في وقت واحد؛ يقوم الممثلون بمعالجة البريد الوارد الخاص بهم بشكل متزامن.
- **جاهز للتوزيع.** البريد الوارد + النقل هو نفس التجريد سواء كان الممثل قيد المعالجة أو على مضيف آخر.

### Topologies

- **RoundRobinGroupChat.** يتناوب الوكلاء في تناوب ثابت.
- **SelectorGroupChat.** يختار وكيل التحديد من سينتقل بعد ذلك بناءً على سياق المحادثة.
- **Magentic-One.** فريق مرجعي متعدد الوكلاء لتصفح الويب وتنفيذ التعليمات البرمجية ومعالجة الملفات. بنيت على AgentChat.

### Observability

تم تضمين دعم OpenTelemetry. كل رسالة تبعث بامتداد؛ تحمل استدعاءات الأداة سمات `gen_ai.*` وفقًا للاصطلاحات الدلالية OTel GenAI لعام 2026 (الدرس 23).

### Status: maintenance mode

أوائل عام 2026: يعد AutoGen v0.7.x مستقرًا للبحث والنماذج الأولية. قامت Microsoft بتحويل التطوير النشط إلى Microsoft Agent Framework (المعاينة العامة في 1 أكتوبر 2025؛ 1.0 GA نهاية مستهدفة لـ Q1 2026). تنتقل أنماط AutoGen إلى الأمام بشكل نظيف - نموذج الممثل هو الفكرة الدائمة.

## Build It

`code/main.py` ينفذ وقت تشغيل ممثل stdlib:

- `Message` — الحمولة المكتوبة بـ `sender`، `recipient`، `topic`، `body`.
- `Actor` — مجردة مع `receive(message, runtime)`.
- `Runtime` — حلقة حدث مع قائمة انتظار مشتركة، والتسليم، وعزل الفشل.
- عرض توضيحي لممثلين: `ReviewerAgent` رمز المراجعات، `ChecklistAgent` يقوم بتشغيل قائمة مرجعية؛ يتبادلون الرسائل حتى التوافق.

تشغيله:

```
python3 code/main.py
```

يُظهر التتبع تسليم الرسالة، ومحاكاة فشل أحد الممثلين دون أن يؤدي إلى تعطل الطرف الآخر، والتقارب في حكم مشترك.

## Use It

- **AutoGen v0.4/v0.7** (الصيانة) — مستقر للبحث والنماذج الأولية والأنماط متعددة الوكلاء.
- **Microsoft Agent Framework** (معاينة عامة) — المسار الأمامي؛ نفس أفكار نموذج الممثل في API منتعشة.
- **طوبولوجيا سرب LangGraph** (الدرس 13) — نمط مماثل من خلال عمليات تسليم الأدوات المشتركة.
- **وقت تشغيل الممثل المخصص** — عندما تحتاج إلى وسيلة نقل محددة (NATS، RabbitMQ، gRPC).

## Ship It

`outputs/skill-actor-runtime.md` ينشئ الحد الأدنى من وقت تشغيل الممثل بالإضافة إلى قالب فريق (RoundRobin أو Selector) لمهمة محددة متعددة الوكلاء.

## Exercises

1. أضف قائمة انتظار للأحرف الميتة: عندما يرفع المعالج، قم بإيقاف الرسالة الفاشلة للفحص البشري. كم مرة يتم ضرب DLQ في لعبتك؟
2. تنفيذ `SelectorGroupChat`: يختار ممثل التحديد من يقوم بمعالجة الرسالة التالية بناءً على حالة المحادثة.
3. أضف النقل الموزع: قم بتبديل قائمة الانتظار قيد التشغيل بخادم JSON-over-HTTP حتى يتمكن الممثلون من العمل في عمليات منفصلة.
4. قم بتوصيل نطاق OTel لكل رسالة (أو بديل بدون تشغيل). ينبعث `gen_ai.agent.name`، `gen_ai.operation.name` لكل درس 23.
5. اقرأ منشور هندسة AutoGen v0.4. قم بنقل لعبتك إلى الواقع `autogen_core` API. ما الذي تخطيته وهو ما يهم في الإنتاج؟

## Key Terms

| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| ممثل | "الوكيل" | الحالة الخاصة + البريد الوارد + المعالج؛ لا توجد ذاكرة مشتركة |
| رسالة | "الحدث" | الحمولة المكتوبة؛ الطريقة الوحيدة التي يتفاعل بها الممثلون |
| البريد الوارد | "صندوق البريد" | قائمة انتظار الرسائل المعلقة لكل ممثل |
| وقت التشغيل | "مضيف الوكيل" | حلقة الأحداث التي توجه الرسائل وتعزل حالات الفشل |
| الموضوع | "القناة" | مسار النشر والاشتراك المسمى بين الجهات الفاعلة |
| عزل الخطأ | "دعها تتحطم" | فشل ممثل واحد لا يحطم الآخرين |
| راوند روبن جروب شات | "فريق التناوب الثابت" | الوكلاء يتناوبون بالترتيب |
| SelectorGroupChat | "فريق توجيه السياق" | يختار المحدد من يذهب بعد ذلك |
| ماجنتيك وان | "الفريق المرجعي" | فرقة متعددة الوكلاء للويب + الكود + الملفات |
