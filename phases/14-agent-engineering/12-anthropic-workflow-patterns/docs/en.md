# أنماط سير العمل الإنسانية: بسيطة أكثر من معقدة
> يميز Schluntz وZhang (Anthropic، ديسمبر 2024) بين سير العمل (المسارات المحددة مسبقًا) والوكلاء (الاستخدام الديناميكي للأداة). خمسة أنماط لسير العمل تغطي معظم الحالات. ابدأ بمكالمات API المباشرة. قم بإضافة الوكلاء فقط عندما لا يمكن التنبؤ بالخطوات.
** النوع: ** تعلم + بناء
** اللغات: ** بايثون (stdlib)
** المتطلبات الأساسية: ** المرحلة 14 · 01 (حلقة الوكيل)
**الوقت:** ~60 دقيقة
## أهداف التعلم
- قم بتسمية أنماط سير العمل الخمسة في Anthropic: التسلسل السريع، والتوجيه، والتوازي، والعاملون المنسقون، والمقيم-المحسن.
- شرح التمييز بين الوكيل وسير العمل والتكلفة الهندسية لكل منهما.
- تحديد متى يتم اختيار سير العمل بدلاً من الوكيل (والعكس صحيح).
- قم بتنفيذ جميع الأنماط الخمسة في stdlib مقابل LLM المكتوب.
## المشكلة
تصل الفرق إلى أطر عمل متعددة الوكلاء للمشكلات التي تريد استدعاء دالة واحدة. التكلفة حقيقية: تضيف الأطر طبقات تحجب المطالبات، وتخفي تدفق التحكم، وتدعو إلى التعقيد المبكر. منشور شلونتز وتشانغ في ديسمبر 2024 هو أكثر ردود الصناعة استشهادًا: ابدأ بسيطًا، وأضف التعقيد فقط عندما يستحق الأمر تكلفته.
##المفهوم
### سير العمل مقابل الوكلاء
- **سير العمل.** تم تنظيم دورات LLM والأدوات من خلال مسارات التعليمات البرمجية المحددة مسبقًا. المهندسين يملكون الرسم البياني.
- **الوكيل.** يقوم حاملو LLM بتوجيه أدواتهم الخاصة ديناميكيًا واتخاذ خطواتهم الخاصة. النموذج يمتلك الرسم البياني.
كلاهما له مكانه. تعتبر عمليات سير العمل أرخص وأسرع وأسهل في تصحيح الأخطاء. يقوم الوكلاء بحل المشكلات ذات النهايات المفتوحة ولكن من الصعب التفكير في أوضاع الفشل make.
### LLM المعزز
الأساس لجميع الأنماط الخمسة: واحد LLM مزود بثلاث إمكانيات متصلة - البحث (الاسترجاع)، والأدوات (الإجراءات)، والذاكرة (الاستمرار). يمكن لأي مكالمة API استخدام هذه.
### الأنماط الخمسة
1. **التسلسل الفوري.** يتم إدخال ناتج الاتصال 1 للاتصال 2. يُستخدم عندما تحتوي المهمة على تحليل خطي نظيف. بوابات برمجية اختيارية بين الخطوات.
2. **التوجيه.** يقوم المصنف LLM باختيار LLM أو الأداة التي سيتم استدعاؤها. يُستخدم عندما تحتاج المدخلات المختلفة بشكل قاطع إلى معالجة مختلفة (دعم المستوى 1 مقابل استرداد الأموال مقابل الأخطاء مقابل المبيعات).
3. **التوازي.** تشغيل مكالمات N LLM بشكل متزامن، وتجميع النتائج. شكلان: التقسيم (أجزاء مختلفة) والتصويت (نفس المطالبة، عدد N، الأغلبية/التوليف).
4. **العاملون المنسقون.** يقرر المنسق LLM ديناميكيًا العمال (أيضًا حاملي شهادات الماجستير) الذين سيتم تشغيلهم وتجميع مخرجاتهم. تشبه حلقات الوكيل ولكن المُنسق لا يتكرر إلى أجل غير مسمى.
5. **مُحسِّن التقييم.** يقترح أحد LLM إجابة، ويقوم LLM آخر بتقييمها. كرر حتى يمر المقيم. هذا هو الصقل الذاتي (الدرس 05) المعمم.
### حيث يتفوق سير العمل على الوكلاء
- **المهام المتوقعة.** إذا كان بإمكانك تعداد الخطوات، فيجب عليك فعل ذلك.
- **المهام المرتبطة بالتكلفة.** تحتوي مسارات العمل على عدد خطوات محدد؛ يمكن للوكلاء دوامة.
- **المهام المرتبطة بالامتثال.** يرغب المدققون في قراءة الرسم البياني، وليس استنتاجه من المسارات.
### حيث يتغلب الوكلاء على سير العمل
- **بحث مفتوح.** عندما تعتمد الخطوة التالية على ما أعادته الخطوة الأخيرة.
- **مهام ذات طول متغير.** من دقائق إلى ساعات العمل حيث يكون عدد الخطوات غير معروف.
- **المجالات الجديدة.** عندما لا تعرف بعد سير العمل الصحيح - الاستكشاف أولاً، والتدوين لاحقًا.
### رفيق هندسة السياق
"هندسة السياق الفعالة لوكلاء AI" (Anthropic 2025) تضفي الطابع الرسمي على النظام المجاور: نافذة 200 ألف هي ميزانية وليست حاوية. ما الذي يجب تضمينه، ومتى يتم ضغطه، ومتى يتم السماح للسياق بالنمو. تمت تغطيته بالتفصيل في درس المرحلة 14 حول ضغط السياق (المرحلة 14 الدرس السابق 06 في هذا المنهج قبل إعادة الترقيم).
## بنائها
`code/main.py` ينفذ جميع أنماط سير العمل الخمسة مقابل `ScriptedLLM`:
- `prompt_chain(input, steps)` — متسلسل.
- `route(input, classifier, handlers)` — التصنيف + الإرسال.
- `parallel_vote(prompt, n, aggregator)` — عدد N، إجماليًا.
- `orchestrator_workers(task, workers)` — يقوم المنسق باختيار العمال.
- `evaluator_optimizer(task, proposer, evaluator, max_iter)` — حلقة حتى تمر.
تشغيله:
```
python3 code/main.py
```

كل نمط يطبع أثره. إجمالي أسطر التعليمات البرمجية لكل نمط هو ~10-15؛ يتم قياس تكلفة الإطار بالآلاف.
## استخدمه
- مكالمات API مباشرة لمعظم المهام.
- الإطار فقط عندما يحتاج النمط حقًا إلى حالة دائمة (LangGraph)، أو التزامن بين نموذج الممثل (AutoGen v0.4)، أو نموذج الدور (CrewAI).
- تواصل مع وكيل Claude SDK عندما تريد شكل حزام Claude Code دون إعادة بنائه.
## اشحنها
`outputs/skill-workflow-picker.md` يختار النمط الصحيح لوصف مهمة معينة، بما في ذلك الأساس المنطقي للقرار ومسار إعادة البناء إلى الوكيل في حالة فشل سير العمل.
## تمارين
1. تنفيذ التوجيه باستخدام حد الثقة. أقل من العتبة -> التصعيد إلى الإنسان. أين يقع الحد الأدنى لحالة استخدام دعم المستوى 1؟
2. أضف مهلة إلى `parallel_vote`. ماذا يحدث عند تعليق مكالمة واحدة؟ كيف يمكنك تجميع الأصوات المفقودة؟
3. قم بتحويل `evaluator_optimizer` إلى قاطع طريق: احتفظ بالمخرجين الأول والثاني عبر التكرارات حتى لا يتم استبدال النتيجة الجيدة المتأخرة بنتيجة سيئة متأخرة.
4. اجمع بين التسلسل الفوري والتوجيه: يختار جهاز التوجيه واحدة من ثلاث سلاسل. قياس تكلفة الرمز المميز مقابل بديل سريع واحد كبير.
5. اختر إحدى ميزات الإنتاج الخاصة بك. ارسم الرسم البياني لسير العمل. عد الخطوات. هل سيكون الوكيل أفضل هنا؟
