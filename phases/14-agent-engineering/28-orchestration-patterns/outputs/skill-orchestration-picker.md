بالنظر إلى مجال المنتج وفئة المهمة، اختر الحد الأدنى من الهيكل.
قرار:
1. هل يكفي وكيل واحد + أنماط سير العمل (الدرس 12)؟ -> لا تستخدم الطوبولوجيا على الإطلاق.
2. 2-4 متخصصين بمسؤوليات متميزة؟ -> **العامل المشرف**.
3. هل يمكن للمتخصصين أن يسلموا الكمون بشكل حرج؟ -> **سرب**.
4. أكثر من 10 متخصصين، فشل في ميزانية سياق المشرف؟ -> **التسلسل الهرمي**.
5. الدقة مهمة أكثر من التكلفة، هل يساعد تعدد المقترحات والنقد؟ -> **مناظرة** (الدرس 25).
ينتج:
1. سقالة الطوبولوجيا المختارة.
2. قفزة مضادة على السرب. حد عمق التداخل على التسلسل الهرمي؛ غطاء مستدير للمناقشة.
3. خطافات إمكانية الملاحظة لكل عملية تسليم أو لكل خطوة (OTel GenAI تمتد، الدرس 23).
4. قسم "لماذا هذا وليس ذاك" README.
الرفض الصارم:
- إجراء 3 مكالمات LLM بالتسلسل "متعدد الوكلاء". هذه سلسلة سريعة.
- سرب بدون عداد القفزات. كذاب هو اليقين.
- تسلسل هرمي يصل إلى متخصص واحد لكل فرع. تتسطح.
قواعد الرفض:
- إذا كان المستخدم يريد وكيلًا متعددًا لمهمة تعالجها حلقة ReAct واحدة، فارفض واقترح الدرس 01.
- إذا كان المستخدم يريد مشرفًا لمهمة مكونة من خطوتين، فارفض واقترح تسلسلًا سريعًا (الدرس 12).
- إذا كان المجال لديه متطلبات الامتثال / التدقيق، ارفض السرب واقترح مشرفًا أو تسلسلًا هرميًا.
الإخراج: سقالة الطوبولوجيا + README مع مبرر القرار. اختتم بـ "ما يجب قراءته بعد ذلك" بالإشارة إلى الدرس 13 (LangGraph) لتنفيذ المشرف، أو الدرس 16 (OpenAI الوكلاء SDK) لعمليات التسليم كأدوات، أو الدرس 25 لتفاصيل المناقشة.
