# CrewAI: Role-Based Crews and Flows

> CrewAI هو إطار عمل متعدد الوكلاء قائم على الأدوار لعام 2026. أربعة أساسيات: الوكيل، المهمة، الطاقم، العملية. شكلان من المستوى الأعلى: الأطقم (التعاون المستقل والمبني على الأدوار) والتدفقات (المعتمدة على الأحداث والحتمية). المستندات صريحة: "بالنسبة لأي تطبيق جاهز للإنتاج، ابدأ بالتدفق."

** النوع: ** تعلم + بناء
** اللغات: ** بايثون (stdlib)
**المتطلبات الأساسية:** المرحلة 14 · 12 (أنماط سير العمل)، المرحلة 14 · 14 (نموذج الممثل)
**الوقت:** ~75 دقيقة

## Learning Objectives

- قم بتسمية العناصر الأربعة الأساسية لـ CrewAI (الوكيل، المهمة، الطاقم، العملية) وما يملكه كل منهم.
- التمييز بين عملية الإجماع التسلسلية والهرمية والمخطط لها؛ اختر واحدًا لكل عبء عمل.
- تمييز الأطقم (المعتمدة على الأدوار المستقلة) عن التدفقات (الحتمية المستندة إلى الحدث)، وشرح توصيات إنتاج المستندات.
- الأدوات السلكية ذات فئة الديكور `@tool` والفئة الفرعية `BaseTool`؛ السبب حول المخرجات المنظمة مقابل النص الحر.
- قم بتسمية أنواع ذاكرة CrewAI الأربعة ومتى يؤتي كل منها ثماره.
- تنفيذ طاقم مكون من ثلاثة وكلاء من stdlib (الباحث والكاتب والمحرر) الذي ينتج ملخصًا.
- اكتشف أوضاع فشل CrewAI الثلاثة: موجه-تضخم، مدير-LLM ضريبة، عمليات تسليم هشة.

## The Problem

الفرق التي تتبنى أطر عمل متعددة الوكلاء تصطدم بنفس الجدار. يبدو "التعاون المستقل" رائعًا في العرض التوضيحي. ثم يقوم العميل بتسجيل خطأ وتحتاج إلى إعادة تشغيل حتمية. أو يسأل قسم الشؤون المالية عن تكلفة الطاقم الذي يتم توجيهه LLM لكل عملية تشغيل. أو يحتاج عند الطلب إلى معرفة الوكيل الذي توقف عند 3 AM.

أطقم ذات شكل حر LLM لا تجيب على أي من هؤلاء بشكل نظيف. تجيب DAGs النقية على كل هذه الأسئلة ولكنها تفقد الشكل الاستكشافي الذي يحتاجه وكيل العصف الذهني.

إن تقسيم CrewAI صادق فيما يتعلق بالتجارة. أطقم للعمل التعاوني القائم على الأدوار والاستكشاف. التدفقات للإنتاج القائم على الأحداث والمملوك للكود والقابل للتدقيق. نفس الإطار، شكلان، اختر كل سطح.

## The Concept

### Four primitives

سطح CrewAI صغير. احفظ هذا والباقي هو التكوين.

- **الوكيل.** `role + goal + backstory + tools + (optional) llm`. الخلفية الدرامية حاملة. إنه يشكل النغمة والحكم عندما يتوقف الوكيل. الأدوات هي وظائف يمكن للوكيل الاتصال بها (المزيد أدناه).
- **المهمة.** `description + expected_output + agent + (optional) context + (optional) output_pydantic`. وحدة عمل قابلة لإعادة الاستخدام. `expected_output` هو العقد. `context` يسرد المهام الأولية التي تم تمرير مخرجاتها. `output_pydantic` يفرض شكلاً منظمًا.
- **الطاقم.** الحاوية. يمتلك قائمة `agents` وقائمة `tasks` و`process` والإعدادات الاختيارية `memory` + `verbose` + `manager_llm`.
- **العملية.** استراتيجية التنفيذ. متسلسل، هرمي، إجماع (مخطط له). يختار شكل المدى.

الوكلاء لا يرون بعضهم البعض بشكل مباشر. مهام الوكلاء المرجعيين. يقوم الطاقم بتسلسل المهام. تقرر العملية من يختار المهمة التالية. هذا هو النموذج العقلي بأكمله.

> **تم التحقق من صحته مقابل** CrewAI 0.86 (2026-05). قد تقوم الإصدارات الأحدث بإعادة تسمية أنواع العمليات أو دمجها؛ تحقق من [مستندات عمليات CrewAI](https://docs.crewai.com/concepts/processes) قبل الاعتماد على شكل معين.

### Sequential vs Hierarchical vs Consensus

- **متسلسلة.** يتم تشغيل المهام بترتيب الإعلان. يتوفر إخراج المهمة N كـ `context` للمهمة N+1. بأقل تكلفة. الأكثر توقعا. استخدم عندما يتم إصلاح الطلب.
- **التسلسل الهرمي.** طرق وكيل المدير (منفصلة LLM الاتصال) بين المتخصصين. يقوم CrewAI بإنشاء المدير إما من التكوين `manager_llm` الخاص بك أو من الإعداد الافتراضي. يختار المدير المهمة التالية في كل جولة ويمكنه رفضها أو إعادة توجيهها. استخدمه عندما يكون لديك أربعة متخصصين أو أكثر ويعتمد الطلب حقًا على المخرجات السابقة.
- **الإجماع.** مخطط، غير مطبق حاليا على المستوى العام API. تحتفظ المستندات بالاسم للعملية المستقبلية القائمة على التصويت. لا تعتمد عليه اليوم.

يضيف التسلسل الهرمي مكالمة LLM لكل جولة (المدير) أعلى كل مكالمة متخصصة. يمكن أن تتضاعف تكلفة الرمز المميز ثلاث مرات في خمس خطوات. ادفع ثمنها فقط عندما تحتاج إلى التوجيه.

### Crews vs Flows

هذا هو الإطار الذي ستؤدي إليه المستندات في عام 2026.

- **الطاقم.** LLM الحكم الذاتي. يختار الإطار الشكل في وقت التشغيل. مناسب لـ: البحث، والعصف الذهني، والمسودات الأولى، وفي أي مكان يكون المسار جزءًا من الإجابة. من الصعب اعادتها. من الصعب اختبارها. رخيصة للنموذج الأولي.
- **التدفق.** رسم بياني يحركه الحدث تملكه. `@start` يشير إلى الإدخال. `@listen(topic)` يمثل خطوة يتم تشغيلها عندما تبث خطوة أخرى هذا الموضوع. كل خطوة هي لغة بايثون بسيطة (يمكن استدعاء الطاقم داخليًا). جيد ل: الإنتاج. يمكن ملاحظتها. قابل للاختبار. حتمية.

توصية إنتاج المستندات لعام 2026: ابدأ بالتدفق. قم بطي الطاقم على هيئة مكالمات `Crew.kickoff()` من داخل خطوات التدفق عندما تستحق الاستقلالية تكلفتها. يمنحك التدفق مسار التدقيق، بينما يمنحك الطاقم الاستكشاف. يؤلف، لا تختار.

### Tool integration

ثلاث طرق لمنح الوكيل أداة. اختر أبسط ما يناسبك.

1. **`@tool` مصمم الديكور.** الوظائف البحتة تصبح أدوات. التوقيع هو المخطط. docstring هو الوصف الذي يراه LLM. الأفضل للمساعدين لمرة واحدة.

   ```python
   from crewai.tools import tool

   @tool("Search the web")
   def search(query: str) -> str:
       """Return top results for the query."""
       return run_search(query)
   ```

2. **`BaseTool` فئة فرعية.** أداة قائمة على الفئة مع مخطط وسيطات صريح، ودعم غير متزامن، وإعادة المحاولة. يُستخدم عندما تكون الأداة في حالة (عميل، ذاكرة تخزين مؤقت) أو تحتاج إلى وسيطات منظمة.

   ```python
   from crewai.tools import BaseTool
   from pydantic import BaseModel

   class SearchArgs(BaseModel):
       query: str
       limit: int = 10

   class SearchTool(BaseTool):
       name = "web_search"
       description = "Search the web and return top results."
       args_schema = SearchArgs

       def _run(self, query: str, limit: int = 10) -> str:
           return self.client.search(query, limit=limit)
   ```

3. **مجموعات الأدوات المضمنة.** يقوم CrewAI بشحن محولات الطرف الأول: `SerperDevTool`، `FileReadTool`، `DirectoryReadTool`، `CodeInterpreterTool`، `RagTool`، `WebsiteSearchTool`. سلكي باستيراد واحد.

تستخدم المخرجات المنظمة Pydantic. قم بتمرير `output_pydantic=MyModel` على المهمة. يتحقق CrewAI من صحة استجابة LLM مقابل النموذج وإما الإكراه أو إعادة المحاولة. قم بإقران هذا بسلسلة ضيقة `expected_output`. تعد مخرجات النص الحر مناسبة للمسودات؛ المخرجات المنظمة هي ما يمكن أن تستهلكه التدفقات النهائية.

### Memory hooks

يقوم CrewAI بشحن أربعة أنواع من الذاكرة خارج الصندوق. إنهم يؤلفون: يمكن للطاقم تمكين الأربعة جميعًا في وقت واحد.

> **تم التحقق من صحته مقابل** CrewAI 0.86 (2026-05). تقوم الإصدارات الأخيرة بتوجيه كل شيء من خلال نظام `Memory` موحد يغطي هذه المتاجر الأربعة. لا يزال النموذج المفاهيمي أدناه قائمًا، ولكن قد ينهار سطح الطبقة العامة إلى نقطة دخول واحدة `Memory` في الإصدارات الأحدث؛ تحقق من [مستندات ذاكرة CrewAI](https://docs.crewai.com/concepts/memory) للملف API.

- **على المدى القصير.** المخزن المؤقت للمحادثة خلال فترة تشغيل واحدة. تمحى في النهاية.
- **على المدى الطويل.** استمر عبر فترات التشغيل. مخزنة في ناقل DB (Chroma بشكل افتراضي، قابل للتبديل). تم الاسترجاع عن طريق التشابه مع المهمة الحالية.
- **الكيان.** حقائق لكل كيان. "العميل X موجود في خطة المؤسسة." مرتبط بالكيان وليس بالتشابه. البقاء على قيد الحياة عبر الجري.
- **سياقي.** استرجاع وقت التجميع. تسحب الذاكرة ذات الصلة في اللحظة التي يحتاج فيها الوكيل إليها، وليست محملة مسبقًا.

قم بالتمكين على الطاقم باستخدام `memory=True` أو التكوين لكل نوع. مدعومة بموفر التضمين الذي قمت بتكوينه (الإعدادات الافتراضية هي OpenAI، قابلة للتبديل إلى المحلية). تعد الذاكرة واحدة من الأماكن التي تكتسب فيها CrewAI مكانتها في مواجهة الأطر الرقيقة؛ يتطلب منك LangGraph النقي توصيل كل منها بنفسك.

### When CrewAI fits

- ثلاثة إلى ستة وكلاء بأدوار محددة وسير عمل تعاوني. الصياغة، المراجعة، التخطيط، العصف الذهني.
- التوجيه حيث يكون حكم LLM حول الخطوة التالية جزءًا من القيمة (الهرمية).
- في أي مكان يكون الفريق أكثر سعادة عند قراءة `role + goal + backstory` من قراءة تعريف الرسم البياني.

### When CrewAI does not fit

- DAGs حتمية مع ترتيب صارم. استخدم LangGraph (الدرس 13). شكل الرسم البياني هو التجريد الصحيح؛ إن إطار دور CrewAI هو الاحتكاك.
- ميزانيات الكمون الفرعية الثانية. يضيف التسلسل الهرمي رحلات ذهابًا وإيابًا. حتى أن Sequential يقوم بتسلسل المطالبات التي تتضمن قصصًا درامية ومخرجات سابقة.
- حلقات وكيل واحد. تخطي الإطار؛ حلقة الوكيل (الدرس 1) بالإضافة إلى أن تسجيل الأداة أقصر.

يوضح الدرس 17 (مقايضات إطار عمل الوكيل) ذلك في مصفوفة. النسخة القصيرة: CrewAI تقع في الزاوية "المعتمدة على الأدوار التعاونية".

### Dependency shape

مستقلة عن لانجشين. بايثون 3.10 إلى 3.13. الاستخدامات `uv`. عدد النجوم: انظر [crewAIInc/crewAI](https://github.com/crewAIInc/crewAI) (snapshot as of 2026-05). AWS تم توثيق التكامل الأساسي؛ تشير معايير البائعين إلى تسريع كبير مقارنة بـ LangGraph في أعباء عمل QA، ولكن لم يتم نشر المنهجية (مجموعة البيانات، الأجهزة، مقياس التقييم)، لذا تعامل مع أرقام بائعي إطار العمل على أنها اتجاهية فقط.

### Where this pattern goes wrong

- **التضخم الفوري من القصص الدرامية.** قصة درامية مكونة من 2000 كلمة لكل وكيل وطاقم مكون من خمسة وكلاء يحرق ميزانية السياق قبل استدعاء الأداة الأول. احتفظ بالخلفيات الدرامية أقل من 200 كلمة. إعادة استخدام العبارات عبر الوكلاء؛ لا تكرر أسلوب المنزل خمس مرات.
- **مدير-LLM ضريبة الرمز المميز.** تضيف العملية الهرمية مكالمة مدير LLM قبل كل مكالمة متخصصة. في طاقم مكون من خمس مهام يتكون من ستة مكالمات LLM بدلاً من خمسة، ويحمل استدعاء المدير قائمة المهام الكاملة بالإضافة إلى المخرجات السابقة. قم بالتبديل إلى التسلسلي ما لم يعتمد التوجيه على الإخراج.
- **عمليات تسليم هشة.** المهمة N `expected_output` هي "مخطط تفصيلي". تقرأها المهمة N+1 على أنها `context` وتحاول تحليل ثلاثة أقسام. أنتج LLM أربعة. ad-libs وكيل المصب. قم بالإصلاح باستخدام `output_pydantic` في المهمة N حتى تقرأ المهمة N+1 كائنًا مكتوبًا، وليس نصًا حرًا.
- **الطاقم كمنتج.** يتم شحن الطاقم ذو الشكل الحر إلى الإنتاج بدون غلاف التدفق. تقلب الناتج مرتفع. الإعادة مستحيلة. عند الطلب لا يمكن التمييز بين المدى السيئ والجري الجيد. التفاف مع التدفق.

## Build It

`code/main.py` ينفذ إصدارات stdlib من كلا الشكلين بالإضافة إلى طاقم مكون من ثلاثة وكلاء.

Shape:

- `Agent`، `Task` فئات البيانات المطابقة لسطح CrewAI.
- `SequentialCrew.kickoff(inputs)` يقوم بتشغيل المهام بترتيب الإعلان، ومخرجات الترابط كـ `context`.
- `HierarchicalCrew.kickoff(topic)` يضيف وكيلًا إداريًا يختار التخصص التالي في كل جولة، ويتوقف عند "تم".
- `Flow` مع `@start` وdataclassesmatchingCrewAIssurface ديكورات، وحلقة حدث صغيرة، وتتبع.
- `tool(name)` ديكور يعكس شكل CrewAI `@tool`.
- `Memory` مع `short_term`، `long_term`، `entity` متاجر؛ يستخدم التشابه المستهزئ numpy.
- الاستجابات الوهمية LLM عبارة عن سلاسل مشفرة بمفتاح خارج الدور بالإضافة إلى بادئة الإدخال. لا توجد شبكة. حتمية.

عرض توضيحي ملموس: باحث وكاتب وطاقم تحرير ينتجون ملخصًا عن "Agent Engineering 2026". - الباحث يسحب (استهزأ) بالمصادر. مسودات الكاتب. يشدد المحرر. يمر نفس الطاقم عبر التدفق لإظهار الشكل الحتمي.

تشغيله:

```bash
python3 code/main.py
```

يغطي التتبع: مخرجات تسلسلية للطاقم من خلال `context`، طاقم هرمي مع اختيارات المدير (الباحث، الكاتب، المحرر، ثم "تم")، تدفق تشغيل نفس الخطوات الثلاث مع موضوعات صريحة (`researched`، `drafted`، `edited`)، استدعاءات الأداة التي يتم توجيهها من خلال `@tool`، والذاكرة طويلة المدى التي تبقى على قيد الحياة عبر ركلتين.

أثر الطاقم سائل. يمكن للمدير من حيث المبدأ إعادة الطلب. تم إصلاح تتبع التدفق. هذا الاختيار هو الدرس.

## Use It

- **CrewAI Flow** للإنتاج. حتى عندما يكون التدفق عبارة عن خطوة واحدة تستدعي `Crew.kickoff()`. التدفق يعطي حدود التدقيق.
- **CrewAI Crew (متسلسل)** للعمل التعاوني ذو الترتيب الواضح، وخاصة المسودات الأولى وحلقات المراجعة.
- **CrewAI Crew (هرمي)** عندما يعتمد التوجيه على المخرجات ويكون لديك أربعة متخصصين أو أكثر.
- **LangGraph** (الدرس 13) لآلات الحالة الواضحة، والسيرة الذاتية الدائمة، والترتيب الصارم.
- **AutoGen v0.4** (الدرس 14) لتزامن نموذج الممثل وعزل الأخطاء.
- **OpenAI الوكلاء SDK** (الدرس 16) لـ OpenAI- المنتجات الأولى ذات عمليات التسليم والدرابزين.
- **وكيل كلود SDK** (الدرس 17) لمنتجات كلود فيرست مع الوكلاء الفرعيين ومتجر الجلسات.

## Ship It

`outputs/skill-crew-or-flow.md` يختار الطاقم مقابل التدفق لمهمة ويدعم الحد الأدنى من التنفيذ. رفض شديد لموضوعات الطاقم بدون خلفية درامية، والتدفق بدون موضوعات صريحة، والتسلسل الهرمي مع أقل من ثلاثة متخصصين.

## Pitfalls

- **القصة الدرامية كنكهة.** فهي تشكل المخرجات. اختبار ثلاثة متغيرات لكل وكيل؛ التباين حقيقي. اختر واحدًا، وقم بتجميده.
- **تخطي `expected_output`.** بدون عقد لكل مهمة، تلتقط المهام النهائية كل ما تم إنتاجه LLM. يدير الطاقم. فشل التدقيق.
- **الذاكرة تعمل دائمًا.** تكتب على المدى الطويل في كل مرة يتم تشغيلها. المتجه DB ينمو. يصبح الاسترجاع صاخبًا. يكتب النطاق إلى المهام التي تكون فيها الحقيقة ثابتة.
- ** انجراف موجه المدير. ** موجه مدير التسلسل الهرمي ضمني. إذا أصبح التوجيه غريبًا، فقم بتفريغه في الوضع المطول واقرأه.
- **الآثار الجانبية للأداة في الطاقم.** يمكن للطاقم استدعاء الأداة مرات أكثر من المتوقع. POST، DELETE، الدفع يتم بخطوة التدفق، وليس بأداة الطاقم أبدًا.

## Exercises

1. تحويل الطاقم المتسلسل إلى تدفق. قم بإحصاء نقاط الاتصال التي ينخفض ​​فيها التباين. لاحظ أين انخفضت إمكانية القراءة.
2. أضف ذاكرة الكيان إلى الطاقم: تستمر الحقائق المتعلقة بالعميل طوال المباراة. التحقق من الاسترجاع يسحب الكيان الصحيح.
3. قم بتنفيذ عملية هرمية حيث يرفض المدير التوجه إلى المحرر حتى يحتوي مخرج الكاتب على ثلاث فقرات على الأقل. تتبع إعادة المحاولة.
4. قم بتوصيل فئة فرعية `BaseTool` لبحث الويب (السخرية). قارن بين شكل التتبع وإصدار الديكور `@tool`.
5. أضف `output_pydantic=Brief` إلى مهمة المحرر، حيث يحتوي `Brief` على `title`، `summary`، `sections`. جعل إخراج مهمة الكاتب مشوهًا JSON مرة واحدة؛ تحقق من سلوك إعادة المحاولة الخاص بـ CrewAI في التتبع.
6. اقرأ مقدمة مستندات CrewAI. قم بنقل اللعبة إلى الواقع `crewai` API. ما هي الضمانات التي تخطاها إصدار stdlib؟
7. قم بتوصيل AgentOps أو Langfuse (الدرس 24) إلى التشغيل الحقيقي. ما هي الآثار التي فاتتك في إصدار stdlib؟

## Key Terms

| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| الوكيل | "الشخصية" | الدور + الهدف + الخلفية الدرامية + الأدوات |
| مهمة | "وحدة العمل" | الوصف + المخرجات المتوقعة + المكلف + المخرجات المنظمة الاختيارية |
| الطاقم | "فريق الوكيل" | حاوية الوكلاء + المهام + العملية |
| عملية | "استراتيجية التنفيذ" | متسلسل / هرمي / إجماع (مخطط) |
| التدفق | "سير العمل الحتمي" | مبني على الأحداث، ومملوك للكود، وقابل للاختبار |
| الخلفية الدرامية | "موجه الشخصية" | النغمة والحكم المشكل للوكيل |
| `@tool` | "أداة الوظيفة" | الديكور الذي يحول الوظيفة إلى أداة يمكن للوكيل الاتصال بها |
| `BaseTool` | "أداة الفصل" | أداة قائمة على الفصل مع مخطط args، وإعادة المحاولة، ودعم غير متزامن |
| ذاكرة الكيان | "حقائق لكل كيان" | الذاكرة مخصصة للعميل/الحساب/المشكلة |
| الذاكرة طويلة المدى | "الذاكرة المتقاطعة" | الذاكرة المدعومة بالنواقل التي تبقى بين ركلات البداية |
| الذاكرة السياقية | "الاسترجاع في الوقت المناسب" | يتم سحب الذاكرة في اللحظة التي يحتاج فيها الوكيل إليها |
| مدير LLM | "وكيل جهاز التوجيه" | إضافي LLM في العملية الهرمية التي تختار المهمة التالية |
| `expected_output` | "عقد المهمة" | السلسلة التي تخبر الوكيل (والتدقيق) بالشكل الذي سيتم إرجاعه |
