# OpenAI Agents SDK: Handoffs, Guardrails, Tracing

> OpenAI الوكلاء SDK هو إطار عمل متعدد الوكلاء خفيف الوزن مبني على الردود API. خمسة أساسيات: الوكيل، التسليم، الدرابزين، الجلسة، التتبع. عمليات التسليم هي أدوات تسمى `transfer_to_<agent>`. رحلة الدرابزين عند الإدخال أو الإخراج. يتم تشغيل التتبع بشكل افتراضي.

** النوع: ** تعلم + بناء
** اللغات: ** بايثون (stdlib)
**المتطلبات الأساسية:** المرحلة 14 · 01 (حلقة الوكيل)، المرحلة 14 · 06 (استخدام الأداة)
**الوقت:** ~75 دقيقة

## Learning Objectives

- قم بتسمية البدائيات الخمسة للـ OpenAI الوكلاء SDK.
- شرح عمليات التسليم: لماذا تم تصميمها كأدوات، وما هو شكل الاسم الذي يراه النموذج، وكيفية نقل السياق.
- التمييز بين حواجز المدخلات، وحواجز الإخراج، وحواجز الأدوات؛ اشرح `run_in_parallel` مقابل وضع الحظر.
- تنفيذ وقت تشغيل stdlib مع عمليات التسليم + حواجز الحماية + تتبع النمط الممتد.

## The Problem

الوكلاء الذين لا يستطيعون التفويض بشكل نظيف ينتهي بهم الأمر إلى حشو كل شيء في موجه واحد. الوكلاء الذين ليس لديهم حواجز حماية يشحنون PII، أو ينتجون انتهاكًا للسياسة، أو يتكررون إلى الأبد. OpenAI's SDK يقنن البدائيات الثلاثة التي make عمل متعدد الوكلاء قابل للتتبع.

## The Concept

### Five primitives

1. **الوكيل.** LLM + تعليمات + أدوات + عمليات تسليم.
2. **التسليم.** التفويض إلى وكيل آخر. يتم تمثيلها للنموذج كأداة اسمها `transfer_to_<agent_name>`.
3. **الدرابزين.** التحقق من صحة الإدخال (الوكيل الأول فقط)، أو الإخراج (الوكيل الأخير فقط)، أو استدعاء الأداة (لكل أداة وظيفية).
4. **الجلسة.** سجل المحادثات التلقائي عبر المنعطفات.
5. **التتبع.** امتدادات مدمجة لأجيال LLM، واستدعاءات الأدوات، وعمليات التسليم، وحواجز الحماية.

### Handoffs as tools

يرى النموذج `transfer_to_billing_agent` في قائمة الأدوات الخاصة به. يشير تسميته إلى وقت التشغيل إلى:

1. انسخ سياق المحادثة (أو قم بطيه عبر `nest_handoff_history` بيتا).
2. تهيئة الوكيل المستهدف بتعليماته.
3. واصل التشغيل مع العميل المستهدف.

هذا هو نمط المشرف (الدرس 13 / الدرس 28) الذي تم إنتاجه.

### Guardrails

ثلاث نكهات:

- **حواجز حماية الإدخال.** تعمل على مدخلات الوكيل الأول. ارفض الطلبات غير الآمنة أو الخارجة عن النطاق قبل إجراء أي مكالمة LLM.
- **حواجز حماية المخرجات.** تعمل على مخرجات العميل الأخير. اكتشف PII التسريبات وانتهاكات السياسة والاستجابات المشوهة.
- **حواجز حماية الأداة.** تشغيل كل أداة على حدة. التحقق من صحة الحجج، والتحقق من الأذونات، وتنفيذ التدقيق.

Mode:

- **موازي** (افتراضي). يمتد الدرابزين LLM بجانب الدرابزين الرئيسي LLM. انخفاض الكمون الذيل. في حالة التعثر، يتم التخلص من عمل LLM الرئيسي (نفايات رمزية).
- **الحظر** (`run_in_parallel=False`). يعمل حاجز الحماية LLM أولاً. في حالة التعثر، لن يتم إهدار أي رموز مميزة في المكالمة الرئيسية.

ترفع أسلاك التعثر `InputGuardrailTripwireTriggered` / `OutputGuardrailTripwireTriggered`.

### Tracing

قيد التشغيل بشكل افتراضي. كل LLM جيل، واستدعاء أداة، وتسليم، وحاجز حماية ينبعث منه مسافة. `OPENAI_AGENTS_DISABLE_TRACING=1` إلغاء الاشتراك. يمتد مراوح `add_trace_processor(processor)` إلى الواجهة الخلفية الخاصة بك إلى جانب مراوح OpenAI.

### Sessions

`Session` يقوم بتخزين سجل المحادثات في الواجهة الخلفية (SQLite، وRedis، والمخصص). `Runner.run(agent, input, session=session)` التحميل والإلحاق التلقائي.

### Where this pattern goes wrong

- **انجراف عملية التسليم.** يقوم العميل "أ" برفع اليدين إلى العميل "ب" الذي يقوم بتسليم اليد مرة أخرى إلى العميل "أ". أضف عداد القفزات.
- **تجاوز حاجز الدرابزين.** يتم إطلاق حواجز حماية الأدوات على الأدوات الوظيفية فقط؛ الأدوات المضمنة (قارئ الملفات، جلب الويب) تحتاج إلى سياسة منفصلة.
- **الإفراط في التتبع.** محتوى حساس في الامتدادات. الاقتران مع قواعد التقاط محتوى OTel GenAI (الدرس 23) - قم بالتخزين خارجيًا، قم بالإشارة إلى ID.

## Build It

`code/main.py` ينفذ الشكل SDK في stdlib:

- `Agent`، `FunctionTool`، `Handoff` (كأداة وظيفية ذات دلالات نقل).
- `Runner` مع حواجز حماية للإدخال/الإخراج/الأداة، وإرسال التسليم، وعداد القفزات.
- باعث مدى بسيط لإظهار شكل التتبع.
- وكيل فرز يتولى مهمة إعداد الفواتير أو الدعم بناءً على استعلام المستخدم؛ رحلات الدرابزين على مدخل واحد.

تشغيله:

```
python3 code/main.py
```

يُظهر التتبع عمليتي تسليم ناجحتين، ورحلة حاجز حماية واحدة، وشجرة امتداد تعكس ما ينبعث من SDK الحقيقي.

## Use It

- **OpenAI الوكلاء SDK** لـ OpenAI-المنتجات الأولى.
- **وكيل كلود SDK** (الدرس 17) لمنتجات كلود فيرست.
- **LangGraph** (الدرس 13) عندما تريد حالة واضحة وسيرة ذاتية دائمة.
- **مخصص** عندما تحتاج إلى التحكم الدقيق (الصوت، وموفر الخدمة المتعددة، وعمليات النشر الموحدة).

## Ship It

`outputs/skill-agents-sdk-scaffold.md` يدعم تطبيق الوكلاء SDK مع وكيل الفرز وعمليات التسليم وحواجز حماية الإدخال/الإخراج/الأداة ومخزن الجلسة ومعالج التتبع.

## Exercises

1. أضف عداد تسليم القفزات: قم بالرفض بعد عمليات النقل N. تتبع السلوك.
2. قم بتطبيق `nest_handoff_history` كخيار — قم بطي الرسائل السابقة في ملخص واحد قبل النقل.
3. اكتب حاجز حماية للإخراج. قارن زمن الاستجابة للمطالبات التي قد تؤدي إلى تعثره مقابل تلك التي تمر.
4. قم بتوصيل `add_trace_processor` بالمسجل JSON. ما الشكل الذي ينبعث منه في كل فترة؟
5. اقرأ مستندات SDK. قم بنقل لعبة stdlib إلى `openai-agents-python`. ماذا نموذج الخطأ؟

## Key Terms

| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| الوكيل | "LLM + تعليمات" | نوع الوكيل في SDK؛ تمتلك الأدوات والمناولة |
| هاندوف | "نقل" | أداة يستدعي النموذج للتفويض إلى وكيل آخر |
| الدرابزين | "فحص السياسة" | التحقق من صحة الإدخال / الإخراج / استدعاء الأداة |
| تريبواير | "رحلة الدرابزين" | تم رفع الاستثناء عند رفض الدرابزين |
| جلسة | "متجر التاريخ" | استمرت ذاكرة المحادثة بين عمليات التشغيل |
| تتبع | "يمتد" | إمكانية المراقبة المضمنة على LLM + أداة + عملية تسليم + حاجز حماية |
| حجب الدرابزين | "الفحص المتسلسل" | يتم تشغيل الدرابزين أولاً؛ لا توجد نفايات رمزية في الرحلة |
| الدرابزين الموازي | "التحقق المتزامن" | يمتد الدرابزين جنبًا إلى جنب. زمن وصول أقل، وإهدار الرموز المميزة في الرحلة |
