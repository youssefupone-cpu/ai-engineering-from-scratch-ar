# OpenAI الوكلاء SDK: عمليات التسليم، وحواجز الحماية، والتتبع
> OpenAI الوكلاء SDK هو إطار عمل متعدد الوكلاء خفيف الوزن مبني على الردود API. خمسة أساسيات: الوكيل، التسليم، الدرابزين، الجلسة، التتبع. عمليات التسليم هي أدوات تسمى `transfer_to_<agent>`. رحلة الدرابزين عند الإدخال أو الإخراج. يتم تشغيل التتبع بشكل افتراضي.
** النوع: ** تعلم + بناء
** اللغات: ** بايثون (stdlib)
**المتطلبات الأساسية:** المرحلة 14 · 01 (حلقة الوكيل)، المرحلة 14 · 06 (استخدام الأداة)
**الوقت:** ~75 دقيقة
## أهداف التعلم
- قم بتسمية البدائيات الخمسة للوكلاء OpenAI SDK.
- شرح عمليات التسليم: لماذا تم تصميمها كأدوات، وما هو شكل الاسم الذي يراه النموذج، وكيفية نقل السياق.
- التمييز بين حواجز المدخلات، وحواجز الإخراج، وحواجز الأدوات؛ شرح `run_in_parallel` مقابل وضع الحظر.
- تنفيذ وقت تشغيل stdlib مع عمليات التسليم + حواجز الحماية + تتبع النمط الممتد.
## المشكلة
الوكلاء الذين لا يستطيعون التفويض بشكل نظيف ينتهي بهم الأمر إلى حشو كل شيء في موجه واحد. يقوم الوكلاء الذين ليس لديهم حواجز حماية بشحن PII، أو إخراج ينتهك السياسة، أو التكرار إلى الأبد. OpenAI's SDK يقنن الأساسيات الثلاثة التي يعمل بها make متعدد الوكلاء بشكل قابل للتتبع.
##المفهوم
### خمسة البدائيات
1. **الوكيل.** LLM + التعليمات + الأدوات + عمليات التسليم.
2. **التسليم.** التفويض إلى وكيل آخر. يتم تمثيله في النموذج كأداة تسمى `transfer_to_<agent_name>`.
3. **الدرابزين.** التحقق من صحة الإدخال (الوكيل الأول فقط)، أو الإخراج (الوكيل الأخير فقط)، أو استدعاء الأداة (لكل أداة وظيفية).
4. **الجلسة.** سجل المحادثات التلقائي عبر المنعطفات.
5. **التتبع.** امتدادات مدمجة لأجيال LLM، واستدعاءات الأدوات، وعمليات التسليم، وحواجز الحماية.
### عمليات التسليم كأدوات
يرى النموذج `transfer_to_billing_agent` في قائمة الأدوات الخاصة به. يشير تسميته إلى وقت التشغيل إلى:
1. انسخ سياق المحادثة (أو قم بطيه عبر `nest_handoff_history` التجريبي).
2. تهيئة الوكيل المستهدف بتعليماته.
3. واصل التشغيل مع العميل المستهدف.
هذا هو نمط المشرف (الدرس 13 / الدرس 28) الذي تم إنتاجه.
### الدرابزين
ثلاث نكهات:
- **حواجز حماية الإدخال.** تعمل على مدخلات الوكيل الأول. ارفض الطلبات غير الآمنة أو خارج النطاق قبل أي استدعاء LLM.
- **حواجز حماية المخرجات.** تعمل على مخرجات العميل الأخير. اكتشف PII التسريبات وانتهاكات السياسة والاستجابات المشوهة.
- **حواجز حماية الأداة.** تشغيل كل أداة على حدة. التحقق من صحة الحجج، والتحقق من الأذونات، وتنفيذ التدقيق.
وضع:
- **موازي** (افتراضي). يمتد حاجز الحماية LLM بجانب LLM الرئيسي. انخفاض الكمون الذيل. في حالة التعثر، سيتم تجاهل عمل LLM الرئيسي (إهدار الرمز المميز).
- **الحظر** (`run_in_parallel=False`). يتم تشغيل حاجز الحماية LLM أولاً. في حالة التعثر، لن يتم إهدار أي رموز مميزة في المكالمة الرئيسية.
ترفع أسلاك التعثر `InputGuardrailTripwireTriggered` / `OutputGuardrailTripwireTriggered`.
### التتبع
قيد التشغيل بشكل افتراضي. كل جيل LLM، واستدعاء أداة، وتسليم، وحاجز حماية يصدر مسافة. `OPENAI_AGENTS_DISABLE_TRACING=1` إلغاء الاشتراك. يمتد مراوح `add_trace_processor(processor)` إلى الواجهة الخلفية الخاصة بك جنبًا إلى جنب مع OpenAI.
### الجلسات
`Session` يخزن سجل المحادثات في الواجهة الخلفية (SQLite، Redis، Custom). `Runner.run(agent, input, session=session)` يتم التحميل والإلحاق تلقائيًا.
### أين يسير هذا النمط بشكل خاطئ
- **انجراف عملية التسليم.** يقوم العميل "أ" برفع اليدين إلى العميل "ب" الذي يقوم بتسليم اليد مرة أخرى إلى العميل "أ". أضف عداد القفزات.
- **تجاوز حاجز الدرابزين.** يتم إطلاق حواجز حماية الأدوات على الأدوات الوظيفية فقط؛ الأدوات المضمنة (قارئ الملفات، جلب الويب) تحتاج إلى سياسة منفصلة.
- **الإفراط في التتبع.** محتوى حساس في الامتدادات. الاقتران مع قواعد التقاط محتوى OTel GenAI (الدرس 23) - تخزين خارجيًا، مرجع بواسطة ID.
## بنائها
`code/main.py` يطبق الشكل SDK في stdlib:
- `Agent`، `FunctionTool`، `Handoff` (كأداة وظيفية مع دلالات النقل).
- `Runner` مزود بحواجز حماية للإدخال/الإخراج/الأداة، وإرسال التسليم، وعداد القفزات.
- باعث مدى بسيط لإظهار شكل التتبع.
- وكيل فرز يتولى مهمة إعداد الفواتير أو الدعم بناءً على استعلام المستخدم؛ رحلات الدرابزين على مدخل واحد.
تشغيله:
```
python3 code/main.py
```

يُظهر التتبع عمليتي تسليم ناجحتين، ورحلة حاجز حماية للإدخال، وشجرة امتداد تعكس ما يصدره SDK الحقيقي.
## استخدمه
- **OpenAI الوكلاء SDK** لـ OpenAI-المنتجات الأولى.
- **وكيل كلود SDK** (الدرس 17) لمنتجات كلود فيرست.
- **LangGraph** (الدرس 13) عندما تريد حالة واضحة وسيرة ذاتية دائمة.
- **مخصص** عندما تحتاج إلى التحكم الدقيق (الصوت، وموفر الخدمة المتعددة، وعمليات النشر الموحدة).

يدعم `outputs/skill-agents-sdk-scaffold.md` تطبيق الوكلاء SDK مع وكيل الفرز وعمليات التسليم وحواجز حماية الإدخال/الإخراج/الأداة ومخزن الجلسة ومعالج التتبع.
## تمارين
1. أضف عداد تسليم القفزات: قم بالرفض بعد عمليات النقل N. تتبع السلوك.
2. قم بتنفيذ `nest_handoff_history` كخيار - قم بطي الرسائل السابقة في ملخص واحد قبل النقل.
3. اكتب حاجز حماية للإخراج. قارن زمن الاستجابة للمطالبات التي قد تؤدي إلى تعثره مقابل تلك التي تمر.
4. قم بتوصيل `add_trace_processor` إلى المسجل JSON. ما الشكل الذي ينبعث منه في كل فترة؟
5. اقرأ مستندات SDK. قم بنقل لعبة stdlib إلى `openai-agents-python`. ماذا نموذج الخطأ؟
