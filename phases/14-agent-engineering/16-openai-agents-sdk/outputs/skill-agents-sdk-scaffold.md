بالنظر إلى مجال المنتج وقائمة الوكلاء المتخصصين، قم بدعم تطبيق OpenAI Agents SDK.

Produce:

1. `Agent` لكل متخصص بالإضافة إلى وكيل `triage` واحد لديه عمليات تسليم فقط (بدون أدوات المجال).
2. `FunctionTool` لكل أداة في المجال مع مخطط إدخال مكتوب، ووصف واضح (يخبر النموذج بموعد استخدامه)، ووضع الحماية للتنفيذ.
3. `Handoff` من الفرز لكل متخصص. تحقق من أن أسماء الأدوات تتبع التقليد `transfer_to_<agent>`.
4. `InputGuardrail` لـ PII، السياسة، النطاق. الوضع الافتراضي هو الوضع المتوازي ما لم يكن حاجز الحماية LLM كبيرًا بالنسبة للنموذج الرئيسي — ثم استخدم الحجب.
5. `OutputGuardrail` للطول، PII، سياسة. قم دائمًا بحظر الحث على المخرجات المهمة للسلامة.
6. حواجز الحماية لكل أداة على الأدوات الوظيفية التي تلمس الشبكة أو نظام الملفات.
7. `Session` المتجر (SQLite الافتراضي؛ Redis for prod).
8. `add_trace_processor` تمتد الأسلاك إلى الواجهة الخلفية لديك جنبًا إلى جنب مع أثر OpenAI UI.

الرفض الصارم:

- وكلاء الفرز مع أدوات المجال. عمليات الفرز فقط؛ الخلط يخفف من قرار جهاز التوجيه.
- حواجز حماية تعمل على تغيير المدخلات والمخرجات. حواجز الحماية توافق أو ترفض - فهي لا تعيد الكتابة.
- حلقات تسليم صامتة. تتطلب عداد القفزات (الافتراضي بحد أقصى 3).

قواعد الرفض:

- إذا كان المستخدم يريد "عدم وجود حواجز حماية، فقط تحرك بسرعة"، ارفض أي منتج يصل إلى المستخدمين الذين يدفعون أو PII.
- إذا كان المنتج يحتوي على متخصصين اثنين فقط، فاقترح التوجيه عبر `Agents` باستخدام مصنف مباشر (الدرس 12) بدلاً من الفرز+عمليات التسليم - بتكلفة رمزية أقل.
- إذا تم تعطيل التتبع في المنتج، ارفض الشحن. حالات الفشل المتعددة الخطوات غير قابلة للتصحيح دون آثار.

الإخراج: `agents.py`، `tools.py`، `guardrails.py`، `app.py`، `README.md` مع الأساس المنطقي لعامل الفرز، وأوضاع حاجز الحماية، ومعالج التتبع، والواجهة الخلفية للجلسة. اختتم بـ "ما يجب قراءته بعد ذلك" بالإشارة إلى الدرس 23 (OTel GenAI)، أو الدرس 24 (الواجهات الخلفية لقابلية الملاحظة)، أو الدرس 17 لترجمة Claude Agent SDK.
