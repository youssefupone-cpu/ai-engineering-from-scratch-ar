بالنظر إلى مجال المنتج وقائمة خوادم MCP، قم بدعم تطبيق Claude Agent SDK.

Produce:

1. تعريف الوكيل الرئيسي مع التعليمات، والوصول إلى الأدوات المضمنة (read_file، وwrite_file، وshell، وgrep، وglob، وweb fetch)، وأدوات الوظائف المخصصة.
2. مولد فرعي للموازاة وعزل السياق. يُستخدم عندما يقوم المُنسق بتفجير ميزانية السياق الخاصة به.
3. خطافات دورة الحياة المسجلة: PreToolUse + PostToolUse للتدقيق، وSessionStart للإعداد، وSessionEnd للتفكيك، وUserPromptSubmit لإنفاذ القواعد (راجع الأنماط المؤيدة لسير العمل).
4. مخزن الجلسة (افتراضي SQLite) مزود بـ `list_subkeys` سلكي لعرض شجرة الوكيل الفرعي.
5. MCP ملحق الخادم لأسطح الأدوات/الموارد الخارجية.
6. W3C تتبع انتشار السياق بحيث يمتد OTel من المتصل ويستمر خلال CLI.

الرفض الصارم:

- إنشاء وكيل فرعي لمهمة أداة واحدة. الوكلاء الفرعيون مخصصون للتوازي أو عزل السياق؛ ليس من أجل "استدعاء ملف read_file واحد."
- خطافات ذات عمل متزامن باهظ الثمن. يجب أن تكون الخطافات من ميكروثانية إلى ميلي ثانية. العمل الطويل ينتمي إلى وكيل فرعي.
- مخازن الجلسة بدون سياسة الحذف المتتالي. جلسات الوكيل الفرعي المعزولة تتضخم مساحة التخزين.

قواعد الرفض:

- إذا كان المنتج يحتاج إلى عمل غير متزامن طويل الأمد (من ساعات إلى أيام)، فارفض الاستضافة الذاتية SDK وقم بالتوجيه إلى Claude Managed Agents.
- إذا طلب المستخدم `--session-mirror` إلى موقع مشترك، ارفض. تحمل نصوص الجلسة PII؛ مرآة للتخزين المشفر لكل مستخدم.
- إذا كان الوكيل يعتمد على البث LLM الخام لـ UX دون استخدام الأداة، ارفض الوكيل SDK وأوصي العميل SDK مباشرة.

الإخراج: `agent.py`، `tools.py`، `hooks.py`، `session.py`، `README.md` شرح سياسة الوكيل الفرعي، وتسجيل الخطاف، والواجهة الخلفية للجلسة، ومرفقات MCP، وأسلاك OTel. اختتم بـ "ما يجب قراءته بعد ذلك" بالإشارة إلى الدرس 22 لعمليات التسليم الصوتي، أو الدرس 23 لإسناد نطاق OTel، أو الدرس 18 إذا كان المنتج يحتاج إلى شكل وقت تشغيل الإنتاج.
