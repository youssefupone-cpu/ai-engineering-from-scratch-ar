بالنظر إلى وكيل استخدام الكمبيوتر وقائمة التطبيقات المستهدفة، قم بإنتاج طبقة أمان تصنف كل إجراء قبل التنفيذ.

Produce:

1. `SafetyClassifier.assess(action, screen) -> SafetyVerdict` مع الحقول `allow`، `reason`، `needs_confirmation`.
2. القائمة المسموح بها بتسميات العناصر التي يمكن للوكيل النقر عليها؛ رفض غير ذلك.
3. القائمة المسموح بها بعناوين URL التي يمكن للوكيل الانتقال إليها؛ رفض عمليات إعادة التوجيه من القائمة.
4. مرشح علامة الحقن على النص DOM والمحتوى المسترد والنص المكتوب. أي مباراة تمنع العمل.
5. بوابة تأكيد الإجراءات الحساسة (تسجيل الدخول، الشراء، الحذف، النشر). واجهة رد الاتصال البشرية في الحلقة.
6. تتبع الباعث: كل قرار مسجل به (الإجراء، الحكم، السبب).

الرفض الصارم:

- مصنف السلامة الذي يعمل فقط عند الإجراء الأول. يجب تصنيف كل إجراء.
- القائمة المسموح بها للنموذج `*`. القائمة المسموح بها التي تسمح بكل شيء ليست قائمة مسموح بها.
- تخطي التأكيد لأن العارضة "تبدو واثقة". الثقة ليست الأمان.

قواعد الرفض:

- إذا كان لدى الوكيل إمكانية الوصول لاستخدام الكمبيوتر دون توفير الأمان لكل خطوة، فارفض الشحن.
- إذا كان بإمكان الوكيل الانتقال إلى عناوين URL عشوائية، فارفض. مطلوب القائمة المسموح بها أو القائمة المحظورة.
- إذا تجاوزت الإجراءات الحساسة بوابة التأكيد في أي وضع، ارفض.

الإخراج: `classifier.py`، `allowlist.py`، `confirmation.py`، `trace.py`، `README.md` شرح سياسة البوابة وعلامات الحقن وعملية صيانة القائمة المسموح بها. اختتم بـ "ما يجب قراءته بعد ذلك" مع الإشارة إلى الدرس 27 (الحقن الفوري) والدرس 23 (إسناد نطاق OTel لاتخاذ قرارات السلامة).
