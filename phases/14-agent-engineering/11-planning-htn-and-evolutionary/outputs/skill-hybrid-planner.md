بالنظر إلى فئة المشكلة (سير العمل المرتبط بالسياسة مقابل تحسين التعليمات البرمجية مقابل المهمة المفتوحة)، اختر مخططًا وأنتج السقالة الصحيحة.
قرار:
1. هل المشكلة لها شروط مسبقة / سياسة / قيود جدولة صعبة؟ -> HTN (ChatHTN).
2. هل تحتوي المشكلة على وظيفة لياقة حتمية يمكن فحصها بواسطة الآلة؟ -> التطوري (AlphaEvolve).
3. ولا؟ -> الوصول إلى ReAct (الدرس 01) أو ReWOO (الدرس 02) بدلاً من ذلك.
بالنسبة إلى HTN، قم بإنتاج:
1. `Operator` اكتب بـ `preconditions`، `effects_add`، `effects_remove`.
2. `Method` اكتب بـ `task`، `preconditions`، `subtasks`.
3. المخطط الذي يجرب الطرق أولاً، يعود إلى تحليل LLM، ويخزن تحليلات LLM الناجحة مؤقتًا.
4. خطوة التحقق من الصحة التي ترفض تحليلات LLM التي تشير إلى عوامل تشغيل أو طرق غير معروفة.
بالنسبة للتطور، قم بإنتاج:
1. مجموعة أولية من البرامج المرشحة.
2. مقيم حتمي يعيد اللياقة العددية.
3. عامل طفرة (LLM يحركه أو يستند إلى القواعد).
4. حلقة اختيار (احتفظ بـ top-k، وتحول، وكرر) مع التوقف المبكر.
الرفض الصارم:
- ChatHTN حيث يتم تطبيق إخراج LLM مباشرة دون التحقق من صحة مخطط المشغل. ادعاء الصحة فاشل
- AlphaEvolve حيث يقوم المقيم باستدعاء القاضي LLM. يجب أن تكون اللياقة حتمية؛ LLM يقدم الحكام ضوضاء عشوائية لا يمكن للحلقة التعافي منها.
- أي من النمطين للمهام المفتوحة ("اكتب منشور مدونة"). لا يوجد مقيم ولا شروط مسبقة -> استخدم ReAct.
قواعد الرفض:
- إذا لم يكن المجال يحتوي على مخطط مشغل واضح، قم برفض ChatHTN. أقترح ReWOO أو ReAct العادي.
- إذا لم يكن المجال يتمتع بملاءمة يمكن التحقق منها آليًا، فارفض AlphaEvolve. اقترح التحسين الذاتي (الدرس 05).
- إذا كان المستخدم يريد "المكالمة النهائية للمخطط + LLM makes"، ارفض. إن الانقسام بين الصحة الرمزية والاستكشاف LLM هو فصل حامل.
الإخراج: `operators.py`، `methods.py`، `planner.py` (HTN) أو `evaluator.py`، `mutator.py`، `loop.py` (تطوري)، بالإضافة إلى `README.md` مع مبرر القرار. اختتم بـ "ما يجب قراءته بعد ذلك" مع الإشارة إلى الدرس 25 إذا كان التحقق من أسلوب المناقشة يناسب المشكلة، أو الدرس 02 إذا كانت المهمة في الواقع على شكل ReWOO بعد كل شيء.
