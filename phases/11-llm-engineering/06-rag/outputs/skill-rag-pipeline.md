# RAG نمط خط الأنابيب
يتبع كل نظام RAG هذا النمط:
```
documents -> chunk -> embed -> store
query -> embed -> search(top_k) -> build_prompt -> generate
```

تتم الفهرسة مرة واحدة لكل مستند. يتم الاستعلام بناءً على كل طلب مستخدم.
## متى تستخدم RAG
- يحتاج LLM إلى الوصول إلى المستندات الخاصة أو الحديثة
- الضبط الدقيق مكلف للغاية أو بطيء جدًا في التحديث
- تحتاج إلى ذكر المصادر للحصول على الإجابات
- قاعدة المعرفة تتغير بشكل متكرر
## متى يجب استخدام NOT RAG
- الإجابة هي المعرفة العامة التي يمتلكها LLM بالفعل
- أن تكون المهمة إبداعية (كتابة، عصف ذهني) وليست واقعية
- أنت بحاجة إلى أن يتبنى النموذج أسلوب تفكير محدد (استخدم الضبط الدقيق)
## قائمة التحقق من التنفيذ
1. قم بتقسيم المستندات إلى 256-512 مقطعًا مميزًا مع تداخل 50 رمزًا
2. قم بتضمين كل قطعة باستخدام نموذج تضمين متسق
3. قم بتخزين التضمينات في قاعدة بيانات متجهة تحتوي على النص الأصلي
4. في وقت الاستعلام، قم بتضمين سؤال المستخدم بنفس النموذج
5. استرجاع الأجزاء الأكثر تشابهًا (5-10) عبر تشابه جيب التمام
6. إنشاء موجه: تعليمات النظام + السياق المسترد + سؤال المستخدم
7. قم بتوليد الإجابة، وربطها بالسياق المسترجع
8. إعادة الإجابة مع مراجع المصدر
##أخطاء شائعة
- استخدام نماذج التضمين المختلفة للفهرسة والاستعلام (النواقل غير متوافقة)
- الأجزاء صغيرة جدًا (تفقد السياق) أو كبيرة جدًا (تضعف الصلة)
- عدم تضمين التداخل بين الأجزاء (تقسيم الجمل عند الحدود)
- نسيان إعادة الفهرسة عند تغيير المستندات
- إعادة القطع المستردة إلى المستخدم دون توليد إجابة متماسكة
- عدم ضبط درجة الحرارة=0 للاستعلامات RAG الواقعية (درجة حرارة أعلى = المزيد من الهلوسة)
## استرجاع التصحيح
إذا لم يتم استرداد القطع الصحيحة:
1. اطبع تضمين الاستعلام وتأكد من أنه ليس صفرًا
2. تحقق من أوجه التشابه في جيب التمام يدويًا بحثًا عن قطعة معروفة وذات صلة
3. حاول إعادة صياغة الاستعلام ليتوافق مع مفردات المستند
4. تحقق من تطابق نموذج التضمين بين الفهرس ووقت الاستعلام
5. تحقق مما إذا كان المحتوى ذو الصلة قد فقد أثناء عملية التقطيع
## معلمات الإنتاج
- حجم القطعة: 256-512 قطعة
- التداخل: 50 رمزًا (10-20% من حجم القطعة)
- Top-k: 5-10 لمعظم حالات الاستخدام
- درجة الحرارة: 0 للإجابات الواقعية
- نموذج التضمين: تضمين النص -3-صغير (فعال من حيث التكلفة) أو تضمين النص-3-كبير (دقة أعلى)
