# Segmentation Mask Inspector

تشخيص للفجوة بين "الخسارة انخفضت" و"الأقنعة تبدو صحيحة بالفعل".

## When to use

- مباشرة بعد انتهاء التدريب عندما يبدو mIoU جيدًا ولكن الفحص البصري يقول خلاف ذلك.
- قبل النشر: التحقق من توازن التنبؤات الصفية مقابل الحقيقة الأرضية.
- عندما يكون مستوى IoU لكل فئة مرتفعًا بالنسبة للكائنات الكبيرة ولكنه منخفض بالنسبة للكائنات الصغيرة.
- تصحيح أخطاء الحدود التي لا تظهر في IoU لأنها صغيرة في عدد البكسل.

## Inputs

- `preds`: (N, H, W) موتر معرفات الفئة المتوقعة.
- `targets`: (N، H، W) موتر معرفات فئة الحقيقة الأرضية.
- `num_classes`: عدد صحيح.
- اختياري `class_names`: قائمة سلاسل C.

## Steps

1. **الرسوم البيانية لوحدات البكسل للفئة.** احسب النسبة المئوية لوحدات البكسل لكل فئة لـ `preds` و`targets`. ضع علامة على أي فئة يكون فيها `|pred% - gt%| / max(gt%, 1e-6) > 0.30` (الانحراف النسبي أعلى من 30%). بالنسبة للفئات الغائبة عن الحقيقة الأساسية (`gt% == 0`)، ضع علامة على أي مشاركة متوقعة أعلى من `0.3` مباشرةً.

2. **IoU لكل فصل** و **الحدود F1 لكل فصل**. يتم حساب الحدود F1 عن طريق توسيع كل قناع بمقدار 3 بكسل والتقاطع والتسجيل. الفئات ذات IoU> 0.7 لكن الحدود F1 <0.5 هي حواف غير واضحة.

3. **استدعاء الكائنات الصغيرة.** افصل كل مكون متصل بالحقيقة الأرضية إلى مجموعات حجمية (صغيرة < 100 بكسل، صغيرة < 1000 بكسل، متوسطة < 10000 بكسل، كبيرة > = 10000 بكسل). تقرير الاستدعاء لكل مجموعة لكل فئة. يشير استدعاء الكائنات الصغيرة أقل من 0.3 بينما يكون استدعاء الكائنات الكبيرة أعلى من 0.9 إلى وجود مشكلة في الدقة/مجال الاستقبال.

4. **أزواج الارتباك.** بالنسبة لكل صف، ابحث عن الفصل الذي غالبًا ما يحدث ارتباكًا معه (الفئات المتوقعة الخاطئة الأكثر شيوعًا ضمن قناع الحقيقة الأرضية الخاص بها). قم بالإبلاغ عن أفضل 3 أزواج.

5. **التحقق من التشبع (يتطلب `probs` أو `lologitss`، وليس فقط `preds`).** إذا مرر المتصل التوزيع الاحتمالي الأولي لكل بكسل `probs: (N, C, H, W)`، فاحسب جزء البكسل حيث `probs.max(dim=1) > 0.99` لكل فئة. يشير التشبع العالي (> 0.9 من بكسلات الفئة) إلى الثقة المفرطة - وهو مرشح لتجانس الملصقات أو معايرتها. عند توفر argmaxed `preds` فقط، قم بتخطي هذه الخطوة وقم بتدوينها في التقرير.

## Report format

```
[mask-inspector]
  classes: C

[class distribution]
  name       gt %    pred %   delta
  ...

[metrics]
  class       IoU     bF1    recall_tiny  recall_small  recall_medium  recall_large
  ...

[confusion pairs]
  class A confused with class B: <N> pixels (most common)
  class B confused with class A: <N> pixels
  ...

[verdict]
  most impactful issue: <one sentence>
```

## Rules

- قم بفرز صفوف الفئات من خلال مشاركة gt بكسل تنازليًا بحيث تأتي الفئات الأكثر شيوعًا أولاً.
- ضع علامة على الفئات التي تحتوي على IoU < 0.4 أو الحد F1 < 0.3 كـ `critical`.
- عندما يكون استدعاء الكائنات الصغيرة هو الفشل السائد، نوصي بما يلي: التدريب على دقة أعلى، أو خطوة أصغر في مرحلة التشفير الأخيرة، أو وحدة فك ترميز هرمية الميزات.
- عندما يكون الحد F1 هو الفشل السائد، نوصي بما يلي: الخسارة المدركة للحدود (Lovasz أو BoundaryLoss)، TTA مع الوجه الأفقي، ووحدة فك التشفير بدون خطوات.
- لا تقم مطلقًا بإخراج فهارس الفئة باعتبارها المعرف الوحيد؛ إذا تم توفير `class_names`، فاستخدمه في كل صف.
