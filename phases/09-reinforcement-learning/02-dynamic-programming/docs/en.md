# البرمجة الديناميكية — تكرار السياسة وتكرار القيمة
> البرمجة الديناميكية هي RL مع الغش. أنت تعرف بالفعل وظائف الانتقال والمكافأة؛ ما عليك سوى تكرار معادلة بيلمان حتى يتوقف `V` أو `π` عن الحركة. إنه المعيار الذي تحاول كل طريقة تعتمد على أخذ العينات الاقتراب منه.
**النوع:** بناء
** اللغات: ** بايثون
** المتطلبات الأساسية: ** المرحلة 9 · 01 (MDPs)
**الوقت:** ~75 دقيقة
## المشكلة
لديك MDP بنموذج معروف: يمكنك الاستعلام عن `P(s' | s, a)` و`R(s, a, s')` لأي زوج من إجراءات الحالة. مدير المخزون يعرف توزيع الطلب. تحتوي لعبة اللوحة على تحولات حتمية. عالم الشبكة هو أربعة أسطر من بايثون. لديك *نموذج*.
تم اختراع RL بدون نموذج (Q-learning، PPO، REINFORCE) للحالة التي لا يكون لديك فيها نموذج - يمكنك فقط أخذ عينة من البيئة. ولكن عندما يكون لديك واحدة، هناك طرق أسرع وأفضل: البرمجة الديناميكية. صممها بيلمان في عام 1957. وما زالوا يحددون الصحة: ​​عندما يقول الناس "السياسة المثلى لهذا MDP"، فإنهم يقصدون أن السياسة DP ستعود.
أنت في حاجة إليها في عام 2026 لثلاثة أسباب. أولاً، يتم حل كل بيئة جدولية في بحث RL (GridWorld، وFrozenLake، وCliffWalking) باستخدام DP لإنتاج سياسة المعيار الذهبي. ثانيًا، تتيح لك القيم الدقيقة *تصحيح* أساليب أخذ العينات: إذا كان تقدير Q-learning لـ `V*(s_0)` يختلف مع إجابة DP بنسبة 30%، فإن Q-learning الخاص بك به خطأ. ثالثًا، RL وطرق التخطيط الحديثة (MCTS، بحث AlphaZero، RL المستند إلى النموذج في المرحلة 9 · 10) كلها تكرر نسخة احتياطية من Bellman عبر نموذج تم تعلمه أو تقديمه.
##المفهوم
![Policy iteration and value iteration, side by side](../assets/dp.svg)
**خوارزميتان، كلاهما تكرار بنقطة ثابتة على Bellman.**
**تكرار السياسة.** تبديل خطوتين حتى تتوقف السياسة عن التغيير.
1. *التقييم:* السياسة المعطاة `π`، قم بحساب `V^π` من خلال تطبيق `V(s) ← Σ_a π(a|s) Σ_{s',r} P(s',r|s,a) [r + γ V(s')]` بشكل متكرر حتى يتقارب.
2. *التحسين:* تم تقديم `V^π`، make `π` greedy w.r.t. __الرمز_5__: __الرمز_6__.
يتم ضمان التقارب لأن (أ) كل خطوة تحسين إما تبقي `π` كما هي أو تزيد بشكل صارم `V^π` لبعض الحالات، (ب) مساحة السياسات الحتمية محدودة. يتقارب عادة في حوالي 5-20 تكرارًا خارجيًا حتى بالنسبة لمساحات الحالة الكبيرة.
**تكرار القيمة.** لتقليص التقييم والتحسين في عملية مسح واحدة. تطبيق معادلة بيلمان *المثالية*:
__الكود_0__
كرر ذلك حتى `max_s |V_{new}(s) - V(s)| < ε`. استخرج السياسة في النهاية باتخاذ الإجراء الجشع. أسرع تمامًا لكل تكرار - لا توجد حلقة تقييم داخلية - ولكن عادةً ما يحتاج إلى المزيد من التكرارات للتقارب.
** تكرار السياسة العامة (GPI).** الإطار الموحد. وظيفة القيمة والسياسة مقيدة في حلقة تحسين ثنائية الاتجاه؛ أي طريقة تدفع كلاهما نحو الاتساق المتبادل (تكرار القيمة غير المتزامنة، تكرار السياسة المعدلة، التعلم Q، الناقد الممثل، PPO) هي مثيل لـ GPI.
**لماذا `γ < 1` مهم.** عامل تشغيل Bellman هو اختصار `γ` في المعيار الإضافي: `||T V - T V'||_∞ ≤ γ ||V - V'||_∞`. يشير الانكماش إلى نقطة ثابتة فريدة وتقارب هندسي. أسقط `γ < 1` وستفقد الضمان - فأنت بحاجة إلى أفق محدود أو حالة طرفية استيعابية.
## بنائها
### الخطوة 1: إنشاء نموذج GridWorld MDP
استخدم نفس 4×4 GridWorld من الدرس 01. أضفنا متغيرًا عشوائيًا: مع الاحتمال `0.1` ينزلق العامل إلى اتجاه عمودي عشوائي.
```python
SLIP = 0.1

def transitions(state, action):
    if state == TERMINAL:
        return [(state, 0.0, 1.0)]
    outcomes = []
    for direction, prob in action_probs(action):
        outcomes.append((apply_move(state, direction), -1.0, prob))
    return outcomes
```

`transitions(s, a)` يُرجع قائمة بـ `(s', r, p)`. هذا هو النموذج بأكمله.
### الخطوة الثانية: تقييم السياسات
بالنظر إلى السياسة `π(s) = {action: prob}`، كرر معادلة بيلمان حتى يتوقف `V` عن الحركة:
```python
def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in states()}
    while True:
        delta = 0.0
        for s in states():
            v = sum(pi_a * sum(p * (r + gamma * V[s_prime])
                              for s_prime, r, p in transitions(s, a))
                   for a, pi_a in policy(s).items())
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V
```

### الخطوة 3: تحسين السياسات
استبدل `π` بالسياسة الجشعة w.r.t. __الكود_1__. إذا لم يتغير `π`، فارجع — نحن في الوضع الأمثل.
```python
def policy_improvement(V, gamma=0.99):
    new_policy = {}
    for s in states():
        best_a = max(
            ACTIONS,
            key=lambda a: sum(p * (r + gamma * V[s_prime])
                              for s_prime, r, p in transitions(s, a)),
        )
        new_policy[s] = best_a
    return new_policy
```

### الخطوة 4: قم بربطهما معًا
```python
def policy_iteration(gamma=0.99):
    policy = {s: "up" for s in states()}   # arbitrary start
    for _ in range(100):
        V = policy_evaluation(lambda s: {policy[s]: 1.0}, gamma)
        new_policy = policy_improvement(V, gamma)
        if new_policy == policy:
            return V, policy
        policy = new_policy
```

التقارب النموذجي على 4 × 4: 4-6 التكرارات الخارجية. المخرجات `V*(0,0) ≈ -6` وسياسة تقلل بشكل صارم من عدد الخطوات.
### الخطوة 5: تكرار القيمة (إصدار الحلقة الواحدة)
```python
def value_iteration(gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in states()}
    while True:
        delta = 0.0
        for s in states():
            v = max(sum(p * (r + gamma * V[s_prime])
                       for s_prime, r, p in transitions(s, a))
                   for a in ACTIONS)
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            break
    policy = policy_improvement(V, gamma)
    return V, policy
```

نفس النقطة الثابتة، وعدد أقل من أسطر التعليمات البرمجية.
## مطبات
- **نسيان التعامل مع المحطات الطرفية.** إذا قمت بتطبيق Bellman على حالة الامتصاص، فإنه لا يزال يلتقط "أفضل إجراء" لا يغير شيئًا. الحرس مع `if s == terminal: V[s] = 0`.
- **التقارب المعياري مقابل L2 التقارب.** استخدم `max |V_new - V|`، وليس المتوسط. الضمان النظري هو على القاعدة العليا.
- **التحديثات الموضعية مقابل التحديثات المتزامنة.** يتقارب تحديث `V[s]` الموضعي (Gauss-Seidel) بشكل أسرع من إملاء `V_new` المنفصل (جاكوبي). يستخدم رمز الإنتاج في المكان.
- **روابط السياسة.** إذا كان هناك إجراءان لهما قيمة Q متساوية، فقد يقطع `argmax` الروابط بشكل مختلف في كل تكرار، مما يتسبب في تأرجح التحقق من "استقرار السياسة". استخدم شوطًا فاصلًا ثابتًا (الإجراء الأول بترتيب ثابت).
- **انفجار مساحة الدولة.** DP هو `O(|S| · |A|)` لكل عملية مسح. يعمل حتى 10⁷ حالات. أبعد من ذلك، تحتاج إلى تقريب الوظيفة (المرحلة 9 · 05 وما بعدها).
## استخدمه
في عام 2026، DP هو خط الأساس للصحة والحلقة الداخلية للمخططين:
| حالة الاستخدام | الطريقة |
|----------|--------|
| حل جدولي صغير MDP بالضبط | تكرار القيمة (أبسط) أو تكرار السياسة (خطوات خارجية أقل) |
| التحقق من تنفيذ Q-learning / PPO | قارنه بـ DP-optimal V* في بيئة الألعاب |
| المبني على النموذج RL (المرحلة 9 · 10) | نسخة احتياطية من بيلمان على نموذج انتقالي مكتسب |
| التخطيط في AlphaZero / MuZero | بحث شجرة مونت كارلو = نسخة احتياطية غير متزامنة لـ Bellman |
| غير متصل RL (CQL، IQL) | التكرار المحافظ — DP مع عقوبة على إجراءات OOD |
في كل مرة يقول شخص ما "دالة القيمة المثلى"، فهو يقصد "النقطة الثابتة DP." عندما ترى `V*` أو `Q*` في ورقة، تصور هذه الحلقة.

## المصطلحات الرئيسية
| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|-|--------------------------------------|
| تكرار السياسة | "خوارزمية DP" | التقييم المتناوب (`V^π`) والتحسين (الجشع `π` w.r.t. `V^π`) حتى تتوقف السياسة عن التغيير. |
| تكرار القيمة | "أسرع DP" | تم تطبيق النسخة الاحتياطية المثالية لـBelman في عملية مسح واحدة؛ يتقارب إلى `V*` هندسيًا. |
| مشغل بيلمان | "العودة" | `(T V)(s) = max_a Σ P (r + γ V(s'))`; `γ`- انكماش في القاعدة العليا. |
| الانكماش | "لماذا يتقارب DP" | أي عامل `T` مع `||T x - T y|| ≤ γ ||x - y||` لديه نقطة ثابتة فريدة. |
| __المصطلح_3__ | "كل شيء هو DP" | تكرار السياسة العامة: أي طريقة تقود `V` و`π` إلى الاتساق المتبادل. |
| تحديث متزامن | "على طريقة اليعقوبي" | استخدم `V` القديم خلال عملية المسح؛ قابلة للتحليل بشكل نظيف ولكن أبطأ. |
| التحديث الموضعي | "أسلوب غاوس سايدل" | استخدم `V` أثناء تحديثه؛ يتقارب بشكل أسرع في الممارسة العملية. |
