بالنظر إلى مستودع GitHub الذي يحتوي على مشكلات تحمل اسم `@agent fix this`، قم بشحن وكيل سحابي مستضاف ذاتيًا يحول كل مشكلة تحمل علامة إلى PR جاهز للمراجعة ببيانات اعتماد محددة النطاق وتكلفة محددة.
خطة البناء:
1. GitHub تطبيق ذو رمز مميز: المشكلات rw، كتابة العلاقات العامة، المحتويات rw، قراءة سير العمل. لا يوجد دفع بالقوة. حماية الفرع على الرئيسي تمنع الكتابة المباشرة.
2. يقوم جهاز استقبال Webhook (Lambda أو Fly.io) بتصفية التصنيف / PR-أحداث التعليق ويضعها في قائمة الانتظار إلى SQS.
3. يفرض المرسل حدودًا قصوى لعدد $ وPR لكل إعادة شراء يوميًا؛ يقوم بتدوير مهمة ECS Fargate لكل مهمة مسموح بها.
4. استنتاج البيئة: اكتشاف اللغة + مدير الحزم + وقت التشغيل من محتويات الريبو. قم بتجميع ملف Dockerfile بسرعة في حالة غيابه.
5. وضع الحماية Daytona أو E2B لكل مهمة. استنساخ الريبو في فرع وكيل `git worktree` + جديد.
6. حلقة الوكيل (mini-swe-agent أو SWE-agent v2 عبر Claude Opus 4.7 أو GPT-5.4-Codex). الأدوات: ripgrep، وtree-sitter repo-map، وread_file، وedit_file، وrun_tests، وgit. القبعات: 20 دولارًا، 30 دورة، 30 دقيقة.
7. التحقق: كامل CI في وضع الحماية؛ تغطية دلتا عبر jacoco / Coverage.py؛ ضع علامة على `needs-review` إذا كانت دلتا <-2%؛ توقف إذا كان CI أحمر.
8. PR مفتوح عبر GitHub API مع الأساس المنطقي، وملخص الفرق، والتتبع URL، والتكلفة، والمنعطفات.
9. إمكانية الملاحظة: تتبع Langfuse لكل PR؛ فرك سجل للأسرار. لوحة معلومات الميزانية لكل الريبو.
10. تقييم 30 مشكلة داخلية مصنفة؛ قارن مع وكلاء خلفية المؤشر ووكلاء AWS البعيدين SWE في مجموعة فرعية مشتركة مكونة من ثلاثة إصدارات.
عنوان التقييم:
| الوزن | المعيار | قياس |
|:-:|---|---|
| 25 | معدل النجاح في 30 قضية | نجاح شامل (CI أخضر + تغطية OK) |
| 20 | PR الجودة | حجم الفرق، دلتا التغطية، توافق النمط |
| 20 | التكلفة ووقت الاستجابة لكل مشكلة تم حلها | $/PR وساعة الحائط/PR |
| 20 | السلامة | رمز محدد النطاق، ميزانية لكل ريبو، لا يوجد ضغط بالقوة، نظافة بيانات الاعتماد |
| 15 | المشغل UX | التعليقات المنطقية، وإعادة المحاولة، ومتابعة الإشارة @ |
الرفض الصارم:
- أي وكيل يمكنه الدفع بالقوة. الإقصاء الصعب
- المرسلون الذين يتخطون فحص الميزانية. الحلقات الهاربة هي الفشل الكلاسيكي.
- تم فتح العلاقات العامة بدون اجتياز CI الكامل في وضع الحماية.
- تتبع الأرشيفات التي تحتوي على رموز مميزة غير منقحة أو PII.
قواعد الرفض:
- رفض التثبيت بدون حماية الفرع على الرئيسي.
- رفض التشغيل بدون ميزانية يومية لكل إعادة شراء (بالدولار وعدد PR).
- رفض إعادة محاولة عمليات التشغيل الفاشلة تلقائيًا؛ تتطلب جميع عمليات إعادة المحاولة إعادة تطبيق التسمية البشرية.
الإخراج: ريبو يحتوي على تطبيق GitHub، ومستقبل خطاف الويب، والمرسل + دفتر أستاذ الميزانية، وتعريف مهمة Fargate، ومدير دورة حياة وضع الحماية، وحلقة mini-swe-agent، وتشغيل التقييم المكون من 30 إصدارًا، ومقارنة جنبًا إلى جنب مع وكلاء خلفية المؤشر ووكلاء SWE البعيدين وAWS، وكتابة لتسمية أعلى ثلاث حالات فشل في استدلال البناء و تغيير تركيب ملف Dockerfile الذي أدى إلى تقليل كل منهما.
