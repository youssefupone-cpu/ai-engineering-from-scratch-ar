# Capstone 01 — وكيل الترميز الطرفي الأصلي
> بحلول عام 2026 يتم تسوية شكل وكيل الترميز. أداة TUI، خطة ذات حالة، سطح أداة رمل، حلقة تخطط وتتصرف وتلاحظ وتتعافى. يبدو كل من Claude Code وCursor 3 وOpenCode متماثلين من مسافة 50 قدمًا. يطلب منك هذا التتويج بناء طرف واحد إلى طرف — CLI للداخل، وسحب الطلب للخارج — وقياسه مقابل وكيل mini-swe وLive-SWE-agent على SWE-bench Pro. سوف تتعرف على سبب عدم كون الجزء الصعب هو استدعاء النموذج، بل حلقة الأداة، وصندوق الحماية، وسقف التكلفة في جولة مكونة من 50 دورة.
**النوع:** كابستون
**اللغات:** TypeScript / بون (حزام)، بايثون (نصوص تقييمية)
**المتطلبات الأساسية:** المرحلة 11 (LLM الهندسة)، المرحلة 13 (الأدوات والبروتوكولات)، المرحلة 14 (الوكلاء)، المرحلة 15 (الأنظمة الذاتية)، المرحلة 17 (البنية التحتية)
**المراحل التي تم تنفيذها:** P0 · P5 · P7 · P10 · P11 · P13 · P14 · P15 · P17 · P18
**الزمن:** 35 ساعة
## مشكلة
أصبحت وكلاء الترميز هي فئة تطبيقات AI المهيمنة في عام 2026. كلود كود (أنثروبي)، وكورسور 3 مع كومبوزر 2 وعلامات تبويب الوكيل (المؤشر)، وAmp (Sourcegraph)، وOpenCode (112 ألف نجمة)، وFactory Droids، وGoogle Jules جميعها تقدم أشكالًا مختلفة من نفس البنية: أداة طرفية، وسطح أداة مسموح به، وصندوق رمل، وحلقة تخطيط-فعل-مراقبة مبنية حول الحدود. نموذج. الحدود ضيقة - وصل وكيل Live-SWE إلى 79.2% على مقعد SWE الذي تم التحقق منه باستخدام Opus 4.5 - لكن المركبة الهندسية واسعة. معظم أوضاع الفشل ليست أخطاء نموذجية. إنها عدم استقرار حلقة الأدوات، وتسمم السياق، وتكلفة الرمز المميز الجامحة، وعمليات نظام الملفات المدمرة.
لا يمكنك التفكير بشأن هؤلاء العملاء من الخارج. يجب عليك إنشاء واحدة، ومشاهدة تعطل الحلقة عند المنعطف 47 عندما يقوم ripgrep بإرجاع 8 ميغابايت من التطابقات، وإعادة بناء طبقة الاقتطاع. وهذا هو الهدف من هذا التتويج.
## مفهوم
الحزام له أربعة أسطح. **الخطة** تحافظ على كائن حالة نمط TodoWrite الذي يعيد النموذج كتابته في كل دورة. **الإجراء** يرسل استدعاءات الأداة (قراءة، تحرير، تشغيل، بحث، git). **الملاحظة** تلتقط رموز stdout / stderr / الخروج، وتقتطعها، ثم تغذي الملخص مرة أخرى. **الاسترداد** يعالج أخطاء الأداة دون تفجير نافذة السياق أو التكرار إلى الأبد. يضيف شكل 2026 شيئًا آخر: **الخطافات**. `PreToolUse`، `PostToolUse`، `SessionStart`، `SessionEnd`، `UserPromptSubmit`، `Notification`، `Stop`، و`PreCompact` - نقاط تمديد قابلة للتكوين حيث يقوم المشغل بإدخال السياسة والقياس عن بعد وحواجز الحماية.
صندوق الحماية هو E2B أو دايتونا. يتم تشغيل كل مهمة في حاوية تطوير جديدة مع شجرة عمل للقراءة والكتابة git. لا يلمس الحزام أبدًا نظام الملفات المضيف. يتم هدم شجرة العمل عند النجاح أو الفشل. يتم فرض التحكم في التكلفة على ثلاث طبقات: سقف الرمز المميز لكل دورة، والميزانية بالدولار لكل جلسة، وحد الدوران الثابت (عادةً 50). طبقة إمكانية الملاحظة عبارة عن قياس OpenTelemetry يمتد مع اصطلاحات GenAI الدلالية، ويتم شحنها إلى Langfuse المستضاف ذاتيًا.
## بنيان
```
  user CLI  ->  harness (Bun + Ink TUI)
                  |
                  v
           plan / act / observe loop  <--->  Claude Sonnet 4.7 / GPT-5.4-Codex / Gemini 3 Pro
                  |                          (via OpenRouter, model-agnostic)
                  v
           tool dispatcher (MCP StreamableHTTP client)
                  |
     +------------+------------+----------+
     v            v            v          v
  read/edit    ripgrep     tree-sitter   git/run
     |            |            |          |
     +------------+------------+----------+
                  |
                  v
           E2B / Daytona sandbox  (worktree isolated)
                  |
                  v
           hooks: Pre/Post, Session, Prompt, Compact
                  |
                  v
           OpenTelemetry -> Langfuse (spans, tokens, $)
                  |
                  v
           PR via GitHub app
```

## المكدس
- وقت تشغيل الحزام: Bun 1.2 + Ink 5 (React-in-terminal)
- الوصول إلى النموذج: OpenRouter الموحد API مع Claude Sonnet 4.7، GPT-5.4-Codex، Gemini 3 Pro، Opus 4.5 (للمهام الصعبة)
- نقل الأداة: بروتوكول السياق النموذجي StreamableHTTP (MCP مراجعة 2026)
- وضع الحماية: E2B صناديق الحماية (JS SDK) أو حاويات تطوير Daytona
- البحث عن الكود: عملية ripgrep الفرعية، وموزعات Tree-sitter لـ 17 لغة (مترجمة مسبقًا)
- العزل: `git worktree add` لكل مهمة، التنظيف عند النجاح/الفشل
- أداة التقييم: SWE-bench Pro (مجموعة فرعية تم التحقق منها) + Terminal-Bench 2.0 + 30 مهمة خاصة بك
- إمكانية الملاحظة: القياس عن بعد المفتوح SDK مع `gen_ai.*` semconv → Langfuse المستضاف ذاتيًا
- نشر PR: GitHub تطبيق ذو رمز مميز ونطاق يقتصر على الريبو المستهدف
## بنائها
1. **TUI وحلقة الأوامر.** دعم مشروع الكعكة بالحبر. قبول `agent run <repo> "<task>"`. طباعة عرض مقسم: جزء الخطة (أعلى)، دفق استدعاء الأداة (وسط)، ميزانية الرمز المميز (أسفل). أضف إلغاء على Ctrl-C الذي يطلق الخطاف `SessionEnd` قبل الخروج.
2. **حالة الخطة.** تحديد مخطط TodoWrite المكتوب (العناصر المعلقة / قيد_التقدم / العناصر المنجزة مع الملاحظات). يعيد النموذج كتابة الحالة الكاملة في كل دورة كاستدعاء أداة - لا تسمح له بالتحول بشكل متزايد. استمر في الخطة حتى `.agent/state.json` حتى يمكن استئناف الأعطال.
3. **سطح الأداة.** حدد ست أدوات: `read_file`، `edit_file` (مع معاينة الفرق)، `ripgrep`، `tree_sitter_symbols`، `run_shell` (مع مهلة)، `git` (الحالة / الفرق / الالتزام / الدفع). قم بالكشف عن ما يزيد عن MCP StreamableHTTP بحيث يكون الحزام غير مستقل عن النقل. تُرجع كل أداة مخرجات مبتورة (الحد الأقصى هو 4 آلاف رمز مميز لكل مكالمة).
4. **تغليف وضع الحماية.** تنشئ كل مهمة صندوق حماية E2B. `git worktree add -b agent/$TASK_ID` فرع جديد. يتم تنفيذ كافة استدعاءات الأداة داخل وضع الحماية. نظام الملفات المضيف غير قابل للوصول.
5. **الخطافات.** تنفيذ جميع أنواع الخطافات الثمانية لعام 2026. قم بتوصيل ما لا يقل عن أربعة خطافات من تأليف المستخدم: (أ) `PreToolUse` حارس الأوامر التدميرية الذي يحظر `rm -rf` خارج شجرة العمل، (ب) `PostToolUse` محاسبة الرمز المميز، (ج) `SessionStart` تهيئة الميزانية، (د) `Stop` يكتب حزمة التتبع النهائية.
6. **حلقة التقييم.** استنساخ مجموعة فرعية مكونة من 30 إصدارًا من SWE-bench Pro Python. تشغيل تسخير الخاص بك ضد كل منهما. قارنه بـ mini-swe-agent (الحد الأدنى لخط الأساس) في pass@1، ودورات لكل مهمة، و$-per-task. اكتب النتائج إلى `eval/results.jsonl`.
7. **التحكم في التكلفة.** القطع الصارمة: 50 دورة، 200 ألف سياق، 5 دولارات لكل مهمة. يلخص خطاف `PreCompact` المنعطفات القديمة إلى كتلة حالة سابقة عند علامة 150 ألفًا، مما يوفر مساحة للملاحظات الجديدة دون فقدان الخطة.
8. **PR النشر.** عند النجاح، الخطوة الأخيرة هي `git push` + مكالمة GitHub API التي تفتح PR مع الخطة وملخص الفرق في النص الأساسي.

## تمارين
1. قم بتبديل نموذج الدعم من Claude Sonnet 4.7 إلى Qwen3-Coder-30B المقدم على vLLM. قارن pass@1 و$ لكل مهمة. قم بالإبلاغ عن الأماكن التي يكون فيها أداء النموذج المفتوح ضعيفًا.
2. أضف وكيلًا فرعيًا `reviewer` يقرأ الفرق قبل نشر PR ويمكنه طلب حلقة مراجعة. قم بقياس ما إذا كانت المراجعات الإيجابية الخاطئة تنخفض SWE معدل نجاح مقاعد البدلاء تحت خط الأساس للوكيل الفردي (تلميح: عادةً نعم).
3. اختبار الإجهاد في وضع الحماية: اكتب مهمة تحاول `curl` URL خارجيًا ومهمة تكتب خارج شجرة العمل. تأكد من حظر كلاهما بواسطة خطاف PreToolUse. سجل المحاولات.
4. تنفيذ تلخيص `PreCompact` بنموذج أصغر (Haiku 4.5). قم بقياس مقدار دقة الخطة المفقودة عند الضغط 3x.
5. قم بتبديل MCP نقل HTTP القابل للتدفق إلى stdio. معيار البداية الباردة ووقت الاستجابة لكل مكالمة. اختر فائزًا للاستخدام المحلي فقط.
