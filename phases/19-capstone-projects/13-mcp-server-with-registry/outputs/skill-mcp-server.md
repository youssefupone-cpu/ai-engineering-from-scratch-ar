في ظل بيئة مؤسسية، قم بشحن خادم MCP مزودًا بـ 10 أدوات داخلية، وخدمة تسجيل للاكتشاف، وطبقة حوكمة تستقبل الأدوات المدمرة من خلال موافقة Slack.
خطة البناء:
1. يعرض خادم FastMCP 10 أدوات للقراءة فقط (Postgres، S3، Jira، Linear، Datadog، PagerDuty، GitHub، Notion، Slack، Salesforce)، لكل منها مخطط مكتوب ونطاق مطلوب.
2. نقل HTTP قابل للتدفق، عديم الحالة خلف موازن التحميل.
3. البرامج الوسيطة لاستبطان الرمز المميز OAuth 2.1؛ هوية عبء العمل عبر SPIFFE / SPIRE.
4. OPA / قرارات سياسة Rego بشأن كل استدعاء للأداة: فرض النطاق، PII التنقيح، الحدود القصوى لحجم الحمولة.
5. الأدوات التدميرية (إنشاء Jira، إنشاء Linear، كتابة Postgres) على خادم MCP منفصل يتطلب نطاق `approved:by:human` مرتفع عبر بطاقة Slack في غضون 15 دقيقة.
6. خدمة التسجيل التي تستقصي `.well-known/mcp-capabilities` من كل خادم، وتتحقق من صحتها باستخدام مخطط JSON، ​​وتكشف عن قائمة/بحث/تحقق/تمكين UI.
7. سجل تدقيق JSONL لكل مستأجر مع تنقيح Presidio PII قبل الكتابة.
8. اختبار الحمل لـ 100 عميل يوضح المقياس الأفقي. اجتياز مجموعة المطابقة MCP.
عنوان التقييم:
| الوزن | المعيار | قياس |
|:-:|---|---|
| 25 | مطابقة المواصفات | بيان قدرة StreamableHTTP + يجتاز اختبارات التوافق MCP |
| 20 | الأمن | تطبيق النطاق، OPA التغطية عبر كل أداة، النظافة السرية |
| 20 | إمكانية الملاحظة | سجل التدقيق لكل أداة مع تنقيح PII عند الكتابة |
| 20 | مقياس | اختبار تحميل 100 عميل مع عرض مقياس أفقي |
| 15 | التسجيل UX | اكتشاف / التحقق من صحة / تمكين / تعطيل سير العمل الذي تمارسه |
الرفض الصارم:
- الخوادم التي تتطلب جلسات ذات حالة (ينتهك عقد 2026 StreamableHTTP عديم الحالة).
- طبولوجيا الخادم الفردي حيث تشترك الأدوات المدمرة في نفس سطح المصادقة للقراءة فقط.
- سجلات التدقيق التي تظل خامًا PII.
- تجاهل بيان القدرة؛ يعد تكامل التسجيل مطلبًا صعبًا.
قواعد الرفض:
- رفض النشر بدون OAuth؛ الوصول المجهول غير مؤهل.
- رفض شحن الأدوات المدمرة دون تدفق موافقة Slack.
- رفض الكشف عن أداة لا يوجد نطاقها أو وصفها في بيان القدرة.
الناتج: ريبو يحتوي على خادمي MCP (للقراءة فقط + مدمر)، وخدمة التسجيل، وتكامل موافقة Slack، وسياسات OPA، ومجموعة أدوات اختبار التحميل لـ 100 عميل، ونتائج اختبار التوافق، ومقالة تصف الأدوات التي فكرت في الكشف عنها ولكن لم يتم الكشف عنها (ولماذا) بالإضافة إلى أهم ثلاث قواعد OPA التي اكتشفت الأخطاء الوشيكة أثناء التشغيل التجريبي.
