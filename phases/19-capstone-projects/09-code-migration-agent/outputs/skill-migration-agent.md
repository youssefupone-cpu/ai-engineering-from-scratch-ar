بالنظر إلى Java 8 أو Python 2 repo، قم بإنتاج فرع مُرحَّل (إلى Java 17 أو Python 3.12) مع مجموعة اختبار خضراء وحد أدنى من انحدار التغطية. قم بالتقييم عبر المجموعة الفرعية MigrationBench المكونة من 50 ريبو.
خطة البناء:
1. التمرير الحتمي: يقوم OpenRewrite (Java) أو libcst (Python) بتشغيل عمليات إعادة الكتابة الميكانيكية أولاً. الالتزام باعتباره "الوصفة" يلتزم بفارق نظيف.
2. وضع حماية Daytona: وقت التشغيل المستهدف مثبت مسبقًا؛ بناء لكل فرع. جبل مصدر للقراءة فقط.
3. حلقة الوكيل: LangGraph أو OpenAI Agents SDK على Claude Opus 4.7 + GPT-5.4-Codex. الأدوات: `run_build`، `read_file`، `edit_file`، `run_test`، `git_diff`. تصنيف الفشل (dep، بناء الجملة، الاختبار، أداة البناء)، تطبيق الإصلاح المستهدف، إعادة التشغيل.
4. الحد الأقصى للميزانية: 30 دقيقة، 8 دولارات، 20 دورة. خرق أي توقفات وملفات تحت `budget_exhausted` مع الفرق الحالي.
5. اختبار + بوابة التغطية: بناء اللون الأخضر ثم اختبار اللون الأخضر؛ يجب ألا تنخفض التغطية أكثر من 2%.
6. PR مفتوح بالتزام الوصفة + التزامات الوكيل + تعليق ملخص.
7. تصنيف الفشل: علامة كل ريبو من `{dep_upgrade_required, build_tool_drift, custom_annotation, test_flake, syntax_edge_case, budget_exhausted, coverage_regression}`.
8. تشغيل 50 ريبو عبر MigrationBench؛ نشر معدل النجاح لكل فئة، وتكلفة إعادة الشراء، والحفاظ على التغطية؛ قارن مقابل خط الأساس الحتمي فقط.
عنوان التقييم:

| 25 | معدل نجاح MigrationBench | 50-ريبو مجموعة فرعية pass@1 |

الرفض الصارم:
- خطوط الأنابيب التي تتخطى المسار الحتمي. يتعامل OpenRewrite مع الأعمال الميكانيكية بشكل أرخص بنسبة 70-80% وأكثر موثوقية من أي وكيل.
- يتم التعامل مع انحدارات التغطية التي تزيد عن 2% على أنها عابرة.
- العلاقات العامة التي تجمع التغييرات الميكانيكية والتغييرات التي كتبها الوكيل في التزام واحد. يجب أن ينفصل.
- الإبلاغ عن معدل النجاح بدون خط أساس حتمي متطابق فقط على نفس 50 اتفاقية إعادة شراء.
قواعد الرفض:
- رفض دفع الفرع المهاجر بالقوة فوق القاعدة. دائما فرع جديد + PR.
- رفض فتح PR الذي لم يتحول CI إلى اللون الأخضر في صندوق الحماية.
- رفض العمل على اتفاقيات إعادة الشراء الخاصة بالشركات دون الحصول على ترخيص صريح للتعديل.
الإخراج: ريبو يحتوي على خط الترحيل ثنائي الطبقة pipeline، وسجلات تشغيل MigrationBench المكونة من 50 ريبو، ولوحة معلومات تصنيف الفشل، وتشغيل خط الأساس الحتمي المطابق فقط، وكتابة عن فئات الفشل الثلاثة الأكثر شيوعًا وتغيير الوصفة الذي من شأنه إزالة كل منها.
