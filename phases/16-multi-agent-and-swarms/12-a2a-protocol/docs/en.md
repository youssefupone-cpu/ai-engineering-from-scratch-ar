# A2A — The Agent-to-Agent Protocol

> أعلنت Google عن A2A في أبريل 2025؛ بحلول أبريل 2026، وصلت المواصفات إلى https://a2a-protocol.org/latest/specification/ وتدعمها أكثر من 150 منظمة. A2A هو المكمل الأفقي لـ MCP (الدرس 13): حيث MCP عمودي (وكيل ↔ أدوات)، A2A نظير إلى نظير (وكيل ↔ وكيل). فهو يحدد بطاقات الوكيل (الاكتشاف)، والمهام ذات العناصر (النص، والبيانات المنظمة، والفيديو)، ودورات حياة المهام غير الشفافة، والمصادقة. تقترن أنظمة الإنتاج بشكل متزايد MCP بـ A2A. قامت Google Cloud بتقديم دعم A2A إلى Vertex AI Agent Builder خلال الفترة 2025-2026.

** النوع: ** تعلم + بناء
**اللغات:** بايثون (stdlib، `http.server`، `json`)
** المتطلبات الأساسية: ** المرحلة 16 · 04 (النموذج البدائي)
**الوقت:** ~75 دقيقة

## Problem

يحتاج وكيلك إلى الاتصال بوكيل آخر على نظام آخر. كيف؟ يمكنك الكشف عن نقطة نهاية HTTP، وتحديد مخطط JSON مخصص، والأمل في أن يتحدث عنها الجانب الآخر. يصبح كل زوج من الوكلاء تكاملًا مخصصًا.

A2A هو بروتوكول السلك العالمي لتلك المكالمة. الاكتشاف القياسي، نموذج المهمة القياسي، النقل القياسي، القطع الأثرية القياسية. مثل HTTP+REST لكن للعملاء كمواطنين من الدرجة الأولى.

## Concept

### The four elements

**بطاقة الوكيل.** مستند JSON في `/.well-known/agent.json` يصف الوكيل: الاسم والمهارات ونقاط النهاية والطرق المدعومة ومتطلبات المصادقة. يحدث الاكتشاف من خلال قراءة البطاقة.

```
GET https://agent.example.com/.well-known/agent.json
→ {
    "name": "code-review-agent",
    "skills": ["review-python", "review-typescript"],
    "endpoints": {
      "tasks": "https://agent.example.com/tasks"
    },
    "auth": {"type": "bearer"},
    "modalities": ["text", "structured"]
  }
```

**المهمة.** وحدة العمل. كائن غير متزامن ذو حالة مع دورة حياة: `submitted → working → completed / failed / canceled`. يرسل العميل مهمة أو استطلاعات أو يشترك للحصول على التحديثات.

**قطعة أثرية.** نوع النتيجة التي تنتجها المهمة. نص، منظم JSON، صورة، فيديو، صوت. تتم كتابة القطع الأثرية بحيث تكون الطرائق المختلفة من الدرجة الأولى.

**دورة حياة مبهمة.** A2A لا تصف *كيفية* قيام الوكيل البعيد بحل المهمة. يرى العميل انتقالات الحالة والتحف؛ التنفيذ مجاني لاستخدام أي إطار عمل.

### The MCP/A2A split

- **MCP** (الدرس 13): الوكيل ↔ الأداة. يقرأ/يكتب الوكيل عبر JSON-RPC إلى خادم الأدوات. عديم الجنسية بشكل افتراضي.
- **A2A**: وكيل ↔ وكيل. بروتوكول الأقران؛ كلا الجانبين عميلان لهما منطقهما الخاص.

تستخدم أنظمة الإنتاج متعددة العوامل كليهما. يستدعي نظير A2A أدوات MCP من جانبه. الانقسام يبقي القلقين نظيفين.

### Discovery flow

```
Client                     Agent server
  ├──GET /.well-known/agent.json──>
  <──Agent Card JSON─────────────
  ├──POST /tasks {skill, input}──>
  <──201 task_id, state=submitted
  ├──GET /tasks/{id}──────────────>
  <──state=working, 42% done──────
  ├──GET /tasks/{id}──────────────>
  <──state=completed, artifacts──
```

أو مع البث المباشر: SSE الاشتراك في `/tasks/{id}/events` للحصول على التحديثات الفورية.

### Auth

A2A يدعم ثلاثة أنماط شائعة:

- **الرمز المميز للحامل** — OAuth2 أو غير شفاف.
- **mTLS** — متبادل TLS; المنظمات تثبت الهوية لبعضها البعض.
- **الطلبات الموقعة** — HMAC على الحمولة.

يتم الإعلان عن المصادقة في بطاقة الوكيل؛ يكتشف العملاء ويمتثلون.

### 150+ organizations by April 2026

قاد اعتماد المؤسسات إلى نطاق A2A. العنوان الرئيسي: A2A أصبح الطريقة التي تعبر بها أنظمة وكلاء المؤسسات حدود الثقة. قامت Google Cloud بشحن دعم Vertex AI Agent Builder A2A؛ يدعمه Microsoft Agent Framework؛ معظم الأطر الرئيسية (LangGraph، CrewAI، AutoGen) تشحن محولات A2A.

### Where A2A wins

- **المكالمات عبر المؤسسات.** الوكيل في الشركة "أ" وكيل المكالمات في الشركة "ب". بدون A2A، يكون كل زوج بمثابة عقد مفصل.
- **أطر العمل غير المتجانسة.** يستدعي وكيل LangGraph وكيل CrewAI ويستدعي وكيل Python المخصص. A2A يتطبيع.
- **التحف المكتوبة.** نتيجة فيديو، منظمة JSON، صوت — كلها من الدرجة الأولى.
- **المهام طويلة الأمد.** دورة حياة مبهمة + استطلاع - مهام تستغرق ساعة واحدة ومباشرة.

### Where A2A struggles

- **مكالمات صغيرة حساسة لوقت الاستجابة.** دورة حياة A2A غير متزامنة. وكيل ميلي ثانية فرعية غير مناسب؛ استخدم المباشر RPC.
- **وكلاء قيد التشغيل مقترنون بشكل وثيق.** إذا كان كلا الوكيلين يعملان في نفس عملية بايثون، فإن رحلة ذهاب وإياب A2A HTTP تعتبر مبالغة.
- **فرق صغيرة.** النفقات العامة للمواصفات حقيقية؛ قد لا يحتاج الوكلاء الداخليون فقط إلى الإجراءات الشكلية.

### A2A vs ACP, ANP, NLIP

ظهرت العديد من المواصفات ذات الصلة في 2024-2026:

- **ACP** (IBM/مؤسسة Linux) — سلف A2A، نطاق أضيق.
- **ANP** (بروتوكول شبكة الوكيل) — كثيف اكتشاف الأقران، ولامركزي أولاً.
- **NLIP** (بروتوكول تفاعل اللغة الطبيعية Ecma، الموحد في ديسمبر 2025) — نوع المحتوى باللغة الطبيعية.

A2A هو بروتوكول النظير الأكثر اعتمادًا اعتبارًا من أبريل 2026. راجع arXiv:2505.02279 (Liu et al.، "A Survey of Agent Interoperability Protocols") للمقارنة.

## Build It

`code/main.py` يطبق الحد الأدنى من الخادم والعميل A2A باستخدام `http.server` و JSON. الخادم:

- يعرض `/.well-known/agent.json`،
- يقبل `POST /tasks`،
- يدير حالة المهمة،
- إرجاع القطع الأثرية على `GET /tasks/{id}`.

العميل:

- جلب بطاقة الوكيل،
- يقدم مهمة،
- استطلاعات الرأي حتى الانتهاء،
- يقرأ القطعة الأثرية.

Run:

```
python3 code/main.py
```

يقوم البرنامج النصي بتشغيل الخادم في سلسلة محادثات في الخلفية، ثم يقوم بتشغيل العميل ضده. ترى التدفق الكامل: الاكتشاف، الإرسال، الاستطلاع، القطعة الأثرية.

## Use It

`outputs/skill-a2a-integrator.md` يصمم تكامل A2A: محتويات بطاقة الوكيل، ومخططات المهام، واختيار المصادقة، والبث مقابل الاقتراع.

## Ship It

Checklist:

- **تثبيت إصدار المواصفات.** A2A لا يزال قيد التطوير؛ يجب أن تعلن بطاقة الوكيل عن إصدار البروتوكول.
- **إنشاء مهمة غير فعالة.** يجب أن تنتج عمليات الإرسال المكررة (إعادة المحاولة عبر الشبكة) مهمة واحدة.
- **مخططات القطع الأثرية.** أعلن عن الأشكال التي يعيدها الوكيل؛ يجب على المستهلكين التحقق من صحة.
- **حدود الأسعار + المصادقة.** A2A عامة؛ تطبيق أمان الويب القياسي.
- **الرسالة الميتة للمهام الفاشلة.** افحص الأنماط بمرور الوقت بحثًا عن أنواع الفشل المتكررة.

## Exercises

1. قم بتشغيل `code/main.py`. تأكد من اكتشاف العميل للخادم واستلامه للعنصر الصحيح.
2. أضف مهارة ثانية إلى الخادم (على سبيل المثال، "تلخيص"). تحديث بطاقة الوكيل. اكتب عميلاً يختار المهارة بناءً على نوع المهمة.
3. قم بتنفيذ نقطة نهاية التدفق SSE: `/tasks/{id}/events` التي تصدر تغييرات الحالة. ما الذي يحتاج العميل إلى فعله بشكل مختلف؟
4. اقرأ المواصفات A2A (https://a2a-protocol.org/latest/specification/). حدد ثلاثة أشياء تنص عليها المواصفات ولا ينفذها هذا العرض التوضيحي.
5. قارن A2A (اكتشاف بطاقة الوكيل) بـ MCP (قائمة القدرات من جانب الخادم عبر `listTools`). ما هي المفاضلة بين العوامل التي تصف نفسها وتسبر القدرات؟

## Key Terms

| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| A2A | "وكيل إلى وكيل" | بروتوكول نظير للوكلاء لاستدعاء وكلاء آخرين عبر الأنظمة. جوجل 2025. |
| بطاقة الوكيل | "بطاقة عمل الوكيل" | JSON في `/.well-known/agent.json` وصف المهارات ونقاط النهاية والمصادقة. |
| مهمة | "وحدة العمل" | كائن ذو حالة غير متزامنة مع دورة حياة؛ التحف المنتجة عند الانتهاء. |
| قطعة أثرية | "النتيجة" | الإخراج المكتوب: نص، منظم JSON، صورة، فيديو، صوت. إعلامي من الدرجة الأولى. |
| دورة حياة مبهمة | "كيفية حلها هو عمل الوكيل" | يرى العميل انتقالات الحالة؛ الخادم حر في اختيار الإطار/الأدوات. |
| اكتشاف | "البحث عن الوكيل" | `GET /.well-known/agent.json` يقوم بإرجاع البطاقة. |
| MCP ضد A2A | "الأدوات مقابل الأقران" | MCP: الأداة العمودية ↔. A2A: عامل أفقي ↔ وكيل. |
| ACP / ANP / NLIP | "بروتوكولات الأخوة" | المواصفات المجاورة A2A الأكثر اعتماداً 2026. |
