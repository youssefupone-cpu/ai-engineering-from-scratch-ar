# A2A — بروتوكول وكيل إلى وكيل
> أعلنت Google عن A2A في أبريل 2025؛ بحلول أبريل 2026، تتوفر المواصفات على https://a2a-protocol.org/latest/specation/ وتدعمها أكثر من 150 منظمة. A2A هو المكمل الأفقي لـ MCP (الدرس 13): حيث MCP عمودي (الوكيل ↔ الأدوات)، A2A هو نظير إلى نظير (الوكيل ↔ الوكيل). فهو يحدد بطاقات الوكيل (الاكتشاف)، والمهام ذات العناصر (النص، والبيانات المنظمة، والفيديو)، ودورات حياة المهام غير الشفافة، والمصادقة. تقوم أنظمة الإنتاج بشكل متزايد بإقران MCP مع A2A. قامت Google Cloud بتقديم دعم A2A إلى Vertex AI Agent Builder خلال الفترة 2025-2026.
** النوع: ** تعلم + بناء
** اللغات: ** بايثون (stdlib، `http.server`، `json`)
** المتطلبات الأساسية: ** المرحلة 16 · 04 (النموذج البدائي)
**الوقت:** ~75 دقيقة
## مشكلة
يحتاج وكيلك إلى الاتصال بوكيل آخر على نظام آخر. كيف؟ يمكنك الكشف عن نقطة نهاية HTTP، وتحديد مخطط JSON مفصل، والأمل في أن يتحدث به الجانب الآخر. يصبح كل زوج من الوكلاء تكاملًا مخصصًا.
A2A هو بروتوكول السلك العالمي لتلك المكالمة. الاكتشاف القياسي، نموذج المهمة القياسي، النقل القياسي، القطع الأثرية القياسية. مثل HTTP+REST ولكن بالنسبة للوكلاء كمواطنين من الدرجة الأولى.
## مفهوم
### العناصر الأربعة
**بطاقة الوكيل.** مستند JSON في `/.well-known/agent.json` يصف الوكيل: الاسم والمهارات ونقاط النهاية والطرق المدعومة ومتطلبات المصادقة. يحدث الاكتشاف من خلال قراءة البطاقة.
```
GET https://agent.example.com/.well-known/agent.json
→ {
    "name": "code-review-agent",
    "skills": ["review-python", "review-typescript"],
    "endpoints": {
      "tasks": "https://agent.example.com/tasks"
    },
    "auth": {"type": "bearer"},
    "modalities": ["text", "structured"]
  }
```

**المهمة.** وحدة العمل. كائن غير متزامن ذو حالة مع دورة حياة: `submitted → working → completed / failed / canceled`. يرسل العميل مهمة أو استطلاعات أو يشترك للحصول على التحديثات.
**قطعة أثرية.** نوع النتيجة التي تنتجها المهمة. نص، منظم JSON، صورة، فيديو، صوت. تتم كتابة القطع الأثرية بحيث تكون الطرائق المختلفة من الدرجة الأولى.
**دورة حياة مبهمة.** A2A لا يصف *كيفية* قيام الوكيل البعيد بحل المهمة. يرى العميل انتقالات الحالة والتحف؛ التنفيذ مجاني لاستخدام أي إطار عمل.
### تقسيم MCP/A2A
- **MCP** (الدرس 13): أداة الوكيل ↔. يقرأ/يكتب الوكيل عبر JSON-RPC إلى خادم الأدوات. عديم الجنسية بشكل افتراضي.
- **A2A**: الوكيل ↔ الوكيل. بروتوكول الأقران؛ كلا الجانبين عميلان لهما منطقهما الخاص.
تستخدم أنظمة الإنتاج متعددة العوامل كليهما. يستدعي نظير A2A أدوات MCP من جانبه. الانقسام يبقي القلقين نظيفين.
### تدفق الاكتشاف
```
Client                     Agent server
  ├──GET /.well-known/agent.json──>
  <──Agent Card JSON─────────────
  ├──POST /tasks {skill, input}──>
  <──201 task_id, state=submitted
  ├──GET /tasks/{id}──────────────>
  <──state=working, 42% done──────
  ├──GET /tasks/{id}──────────────>
  <──state=completed, artifacts──
```

أو من خلال البث: SSE الاشتراك في `/tasks/{id}/events` للحصول على التحديثات الفورية.
### المصادقة
يدعم A2A ثلاثة أنماط شائعة:
- **الرمز المميز للحامل** — OAuth2 أو غير شفاف.
- **mTLS** — متبادل TLS; المنظمات تثبت الهوية لبعضها البعض.
- **الطلبات الموقعة** — HMAC على الحمولة.
يتم الإعلان عن المصادقة في بطاقة الوكيل؛ يكتشف العملاء ويمتثلون.
### أكثر من 150 منظمة بحلول أبريل 2026
قاد اعتماد المؤسسات إلى نطاق A2A. العنوان الرئيسي: A2A أصبح الطريقة التي تعبر بها أنظمة وكلاء المؤسسات حدود الثقة. قامت Google Cloud بشحن دعم Vertex AI Agent Builder A2A؛ يدعمه Microsoft Agent Framework؛ معظم الأطر الرئيسية (LangGraph، CrewAI، AutoGen) تشحن محولات A2A.
### حيث يفوز A2A
- **المكالمات عبر المؤسسات.** الوكيل في الشركة "أ" وكيل المكالمات في الشركة "ب". بدون A2A، يكون كل زوج عقدًا مخصصًا.
- **أطر العمل غير المتجانسة.** يستدعي وكيل LangGraph وكيل CrewAI ويستدعي وكيل Python المخصص. A2A يتم التطبيع.
- **التحف المكتوبة.** نتيجة فيديو، منظمة JSON، صوت — جميعها من الدرجة الأولى.
- **المهام طويلة الأمد.** دورة حياة مبهمة + استقصاء makes مهام تستغرق ساعات طويلة ومباشرة.
### حيث يواجه A2A صعوبة
- **مكالمات صغيرة حساسة لوقت الاستجابة.** دورة حياة A2A غير متزامنة. وكيل ميلي ثانية فرعية غير مناسب؛ استخدم RPC المباشر.
- **وكلاء قيد التشغيل مقترنون بشكل وثيق.** إذا كان كلا الوكيلين يعملان في نفس عملية Python، فإن رحلة الذهاب والإياب HTTP الخاصة بـ A2A تعتبر مبالغة.
- **فرق صغيرة.** النفقات العامة للمواصفات حقيقية؛ قد لا يحتاج الوكلاء الداخليون فقط إلى الإجراءات الشكلية.
### A2A مقابل ACP، ANP، NLIP
ظهرت العديد من المواصفات ذات الصلة في 2024-2026:
- **ACP** (IBM/مؤسسة Linux) — سابق لـ A2A، نطاق أضيق.
- **ANP** (بروتوكول شبكة الوكيل) — عملية اكتشاف الأقران كثيفة، واللامركزية أولًا.
- **NLIP** (بروتوكول تفاعل اللغة الطبيعية Ecma، الموحد في ديسمبر 2025) — نوع المحتوى باللغة الطبيعية.
A2A هو بروتوكول النظير الأكثر اعتماداً اعتبارًا من أبريل 2026. راجع arXiv:2505.02279 (Liu et al.، "A Survey of Agent Interoperability Protocols") للمقارنة.
## بنائها
يقوم `code/main.py` بتنفيذ الحد الأدنى من الخادم والعميل A2A باستخدام `http.server` وJSON. الخادم:
- يكشف `/.well-known/agent.json`،
- يقبل `POST /tasks`،
- يدير حالة المهمة،
- إرجاع القطع الأثرية على `GET /tasks/{id}`.
العميل:
- جلب بطاقة الوكيل،
- يقدم مهمة،
- استطلاعات الرأي حتى الانتهاء،
- يقرأ القطعة الأثرية.
يجري:
```
python3 code/main.py
```

يقوم البرنامج النصي بتشغيل الخادم في سلسلة محادثات في الخلفية، ثم يقوم بتشغيل العميل ضده. ترى التدفق الكامل: الاكتشاف، الإرسال، الاستطلاع، القطعة الأثرية.
## استخدمه
يصمم `outputs/skill-a2a-integrator.md` تكامل A2A: محتويات بطاقة الوكيل، ومخططات المهام، واختيار المصادقة، والبث مقابل الاقتراع.
## اشحنها
قائمة التحقق:
- **تثبيت إصدار المواصفات.** لا يزال A2A قيد التطوير؛ يجب أن تعلن بطاقة الوكيل عن إصدار البروتوكول.
- **إنشاء مهمة غير فعالة.** يجب أن تنتج عمليات الإرسال المكررة (إعادة المحاولة عبر الشبكة) مهمة واحدة.
- **مخططات القطع الأثرية.** أعلن عن الأشكال التي يعيدها الوكيل؛ يجب على المستهلكين التحقق من صحة.
- **حدود الأسعار + المصادقة.** A2A مفتوح للعامة؛ تطبيق أمان الويب القياسي.
- **الرسالة الميتة للمهام الفاشلة.** افحص الأنماط بمرور الوقت بحثًا عن أنواع الفشل المتكررة.
## تمارين
1. قم بتشغيل `code/main.py`. تأكد من اكتشاف العميل للخادم واستلامه للعنصر الصحيح.
2. أضف مهارة ثانية إلى الخادم (على سبيل المثال، "تلخيص"). تحديث بطاقة الوكيل. اكتب عميلاً يختار المهارة بناءً على نوع المهمة.
3. قم بتنفيذ نقطة نهاية الدفق SSE: `/tasks/{id}/events` التي تُصدر تغييرات الحالة. ما الذي يحتاج العميل إلى فعله بشكل مختلف؟
4. اقرأ مواصفات A2A (https://a2a-protocol.org/latest/specation/). حدد ثلاثة أشياء تنص عليها المواصفات ولا ينفذها هذا العرض التوضيحي.
5. قارن A2A (اكتشاف بطاقة الوكيل) بـ MCP (قائمة القدرات من جانب الخادم عبر `listTools`). ما هي المفاضلة بين العوامل التي تصف نفسها وتسبر القدرات؟
