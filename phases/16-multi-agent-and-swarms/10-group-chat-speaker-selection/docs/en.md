# Group Chat and Speaker Selection

> يقوم AutoGen GroupChat وAG2 GroupChat بمشاركة محادثة واحدة عبر وكلاء N؛ تقوم وظيفة التحديد (LLM أو round-robin أو المخصص) باختيار من يتحدث بعد ذلك. هذا هو النموذج الأصلي للمحادثة الناشئة متعددة الوكلاء - لا يعرف الوكلاء دورهم في الرسم البياني الثابت، بل يتفاعلون فقط مع التجمع المشترك. تم الحفاظ على دلالات GroupChat الخاصة بـ AutoGen v0.2 في شوكة AG2؛ أعاد AutoGen v0.4 كتابته كنموذج ممثل يحركه الحدث. وضعت Microsoft AutoGen في وضع الصيانة في فبراير 2026 ودمجته مع Semantic Kernel في Microsoft Agent Framework (RC فبراير 2026). يستمر تطبيق GroupChat الأساسي في كل من AG2 وMicrosoft Agent Framework - تعلمه مرة واحدة، واستخدمه في كل مكان.

** النوع: ** تعلم + بناء
** اللغات: ** بايثون (stdlib)
** المتطلبات الأساسية: ** المرحلة 16 · 04 (النموذج البدائي)
**الوقت:** ~60 دقيقة

## Problem

تعتبر الرسوم البيانية الثابتة (LangGraph) رائعة عندما يكون سير العمل معروفًا. المحادثات الحقيقية ليست ثابتة: أحيانًا يسأل المبرمج المراجع، وأحيانًا الباحث، وأحيانًا الكاتب. يؤدي التشفير الثابت لكل عملية تسليم محتملة إلى حدوث انفجار في الحافة. أنت تريد *تفاعل الوكلاء مع التجمع المشترك*، مع بعض الوظائف التي تحدد من يتحدث بعد ذلك.

هذا هو بالضبط ما يفعله AutoGen GroupChat.

## Concept

### The shape

```
              ┌─── shared pool ────┐
              │   m1  m2  m3  ...  │
              └─────────┬──────────┘
                        │ (everyone reads all)
      ┌───────┬─────────┼─────────┬───────┐
      ▼       ▼         ▼         ▼       ▼
    Agent A  Agent B  Agent C  Agent D  Selector
                                           │
                                           ▼
                                  "next speaker = C"
```

يرى كل وكيل كل رسالة. يتم استدعاء وظيفة التحديد عند كل دور لاختيار من يتحدث بعد ذلك.

### The three selector flavors

**دورة روبن.** دورة ثابتة. حتمية. يتم القياس بشكل خطي في N ولكنه يتجاهل السياق - يحصل المبرمج على الدور حتى عندما يكون الموضوع عبارة عن مراجعة قانونية.

**LLM-محدد.** مكالمة إلى LLM تقرأ المجموعة الأخيرة وترجع أفضل المتحدث التالي. إدراك للسياق ولكنه بطيء: كل دور يضيف مكالمة LLM. AutoGen الافتراضي.

**مخصص.** دالة بايثون بأي منطق تريده. نموذجي: LLM- تم تحديده بقواعد احتياطية (على سبيل المثال، "أعط المدقق دائمًا الدور بعد المبرمج").

### The ConversableAgent API

```
agent = ConversableAgent(
    name="coder",
    system_message="You write Python.",
    llm_config={...},
)
chat = GroupChat(agents=[coder, reviewer, tester], messages=[])
manager = GroupChatManager(groupchat=chat, llm_config={...})
```

`GroupChatManager` يحمل المحدد. عندما يكمل الوكيل دوره، يستدعي المدير المحدد، الذي يقوم بإرجاع الوكيل التالي. تستمر الحلقة حتى حالة الإنهاء.

### Termination

ثلاثة أنماط شائعة:

- **الحد الأقصى للجولات.** الحد الأقصى لعدد المنعطفات الإجمالية.
- **رمز "الإنهاء".** يمكن للوكلاء إرسال رسالة خافرة؛ يتوقف المدير عند ظهور أحدهم.
- **التحقق من الوصول إلى الهدف.** يقوم برنامج التحقق الخفيف بتشغيل كل دور وإيقاف الدردشة عند الانتهاء.

### The AutoGen → AG2 split and the Microsoft Agent Framework merge

في أوائل عام 2025، بدأت Microsoft عملية إعادة كتابة رئيسية لـ AutoGen (الإصدار 0.4) حول نموذج الممثل الذي يحركه الحدث. قام المجتمع بتقسيم دلالات GroupChat الخاصة بـ AutoGen v0.2 إلى AG2، مع الحفاظ على API التي قام المتبنون الأوائل بدمجها.

في فبراير 2026، أعلنت Microsoft أن AutoGen سينتقل إلى وضع الصيانة، مع دمج نموذج الممثل الذي يحركه الحدث في **Microsoft Agent Framework** (RC فبراير 2026، تم دمجه الآن مع Semantic Kernel). يظل مفهوم GroupChat موجودًا في كلا المسارين؛ تختلف تفاصيل التنفيذ. AG2 هو المنبع المفضل للكود المتوافق مع الإصدار 0.2.

### When GroupChat fits

- **المحادثات الطارئة.** لا ترغب في إجراء اتصالات مسبقة مع كل المتحدث التالي المحتمل.
- **مهام خلط الأدوار.** يسأل المبرمج الباحث، ويسأل الباحث أمين الأرشيف، ويسأل أمين الأرشيف المبرمج مرة أخرى. التدفق ليس DAG.
- **حل المشكلات الاستكشافي.** فكر في "اجتماع العصف الذهني" وليس "خط التجميع".

### When it fails

- **الحتمية الصارمة.** يمكن أن يكون المحدد LLM غير متناسق. نفس الموجه، جولات مختلفة، المتحدثون القادمون مختلفون.
- **شلالات التملق.** يذعن الوكلاء لمن يتحدث بثقة أكبر. مكافحة موجه صراحة.
- **السياق منتفخ.** يقرأ كل وكيل كل رسالة؛ بعد 10 دورات يصبح السياق ضخمًا. استخدم التوقعات (الدرس 15) لتحديد نطاق العروض.
- **متحدثون بارعون.** يهيمن وكيل واحد على المحادثة لأن المحدد يفضل تخصصاته. تقديم توازن السماعات كميزة اختيار.

### Group chat vs supervisor

نفس البدائيات، افتراضيات مختلفة:

- المشرف: أحد الوكلاء يخطط والآخرون ينفذون. المحدد هو "اسأل المخطط عما يجب فعله".
- الدردشة الجماعية: جميع الوكلاء هم أقرانهم؛ المحدد هو وظيفة على التجمع المشترك.

كلاهما يستخدم الأساسيات الأربعة من الدرس 04. الدردشة الجماعية الافتراضية هي LLM-التنسيق المحدد وحالة المشاركة الكاملة.

## Build It

`code/main.py` ينفذ GroupChat من البداية في stdlib. ثلاثة وكلاء (مبرمج، مراجع، مدير)، متغيرات محددة LLM، وإنهاء على الرمز المميز `TERMINATE`.

يقوم العرض التوضيحي بطباعة نص المحادثة بالإضافة إلى تتبع قرار المحدد لكلا الخيارين.

Run:

```
python3 code/main.py
```

## Use It

`outputs/skill-groupchat-selector.md` يقوم بتكوين محدد GroupChat لمهمة معينة — round-robin مقابل LLM-selected مقابل custom، وما هي مدخلات المحدد (الرسائل الأخيرة، تخصصات الوكيل، عدد الأدوار) المراد استخدامها.

## Ship It

Checklist:

- **الحد الأقصى للجولات.** دائمًا. 10-20 للمهام النموذجية.
- **مقياس توازن المتحدثين.** تتبع المنعطفات لكل وكيل؛ تنبيه عندما يتجاوز الخلل حدًا معينًا.
- **رمز الإنهاء.** `TERMINATE` أو وكيل تحقق مخصص.
- **ذاكرة الإسقاط أو الذاكرة المحددة النطاق.** بعد 10 رسائل تقريبًا، فكر في منح كل وكيل عرضًا محدد النطاق فقط لمنع تضخم السياق.
- **تسجيل المحدد.** بالنسبة للمتغيرات المحددة LLM، قم بتسجيل كل من إدخال المحدد واختياره. وإلا فإن التصحيح أمر مستحيل.

## Exercises

1. قم بتشغيل `code/main.py`. قارن المحادثة ضمن جولة روبن مقابل LLM-المحدد. أي وكيل يهيمن تحت كل منهما؟
2. قم بإضافة قاعدة "الحد الأقصى لعدد مرات التحدث لكل وكيل" في أداة التحديد. كيف يؤثر ذلك على النص؟
3. تنفيذ إنهاء تم الوصول إليه: توقف عندما يعود المراجع بكلمة "موافق عليه". كم مرة يتم تشغيلها قبل الغطاء المستدير؟
4. اقرأ مستندات AutoGen الثابتة على GroupChat (https://microsoft.githubhub.io/autogen/stable/user-guide/core-user-guide/design-patterns/group-chat.html). حدد المحدد الافتراضي الذي يستخدمه `GroupChatManager`.
5. اقرأ AG2 الريبو (https://githubhub.com/ag2ai/ag2) وقارن الإصدار 0.2 GroupChat الخاص به بالإصدار v0.4 المستند إلى الحدث. ما هي الخاصية الملموسة (الإنتاجية، والتسامح مع الأخطاء، وقابلية التركيب) التي يضيفها الإصدار 0.4؟

## Key Terms

| مصطلح | ماذا يقول الناس | ماذا يعني في الواقع |
|------|----------------|-----------------------|
| دردشة جماعية | "الوكلاء في غرفة دردشة واحدة" | تجمع الرسائل المشتركة + وظيفة التحديد. AutoGen / AG2 بدائية. |
| اختيار المتحدث | "من يتحدث بعد ذلك" | الوظيفة التي تختار الوكيل التالي. Round-robin، LLM-محدد، أو مخصص. |
| مدير الدردشة الجماعية | "مضيف الاجتماع" | مكون AutoGen الذي يمتلك المحدد ويقوم بالتكرار على المنعطفات. |
| وكيل قابل للتحدث | "الوكيل الأساسي" | فئة AutoGen الأساسية؛ وكيل يمكنه إرسال واستقبال الرسائل. |
| رمز الإنهاء | "كلمة الوقف" | سلسلة الحارس (عادة `TERMINATE`) التي تنهي الدردشة. |
| المتحدث الساخن | "عميل واحد يهيمن" | وضع الفشل حيث يستمر المحدد في اختيار نفس الوكيل. |
| انتفاخ السياق | "المسبح ينمو بلا حدود" | يقرأ كل وكيل كل رسالة سابقة؛ السياق ينمو مع المنعطفات. |
| الإسقاط | "عرض النطاق" | عرض خاص بالدور في التجمع المشترك لمنع تضخم السياق. |
