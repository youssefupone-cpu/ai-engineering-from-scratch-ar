# الدردشة الجماعية واختيار المتحدث
> يقوم AutoGen GroupChat وAG2 GroupChat بمشاركة محادثة واحدة عبر وكلاء N؛ تقوم وظيفة التحديد (LLM، أو round-robin، أو Custom) باختيار من يتحدث بعد ذلك. هذا هو النموذج الأصلي للمحادثة الناشئة متعددة الوكلاء - لا يعرف الوكلاء دورهم في الرسم البياني الثابت، بل يتفاعلون فقط مع التجمع المشترك. تم الحفاظ على دلالات GroupChat الخاصة بـ AutoGen v0.2 في شوكة AG2؛ أعاد AutoGen v0.4 كتابته كنموذج ممثل يحركه الحدث. وضعت Microsoft AutoGen في وضع الصيانة في فبراير 2026 ودمجته مع Semantic Kernel في Microsoft Agent Framework (RC فبراير 2026). يظل نظام GroupChat الأساسي موجودًا في كل من AG2 وMicrosoft Agent Framework - تعلمه مرة واحدة، واستخدمه في كل مكان.
** النوع: ** تعلم + بناء
** اللغات: ** بايثون (stdlib)
** المتطلبات الأساسية: ** المرحلة 16 · 04 (النموذج البدائي)
**الوقت:** ~60 دقيقة
## مشكلة
تعتبر الرسوم البيانية الثابتة (LangGraph) رائعة عندما يكون سير العمل معروفًا. المحادثات الحقيقية ليست ثابتة: أحيانًا يسأل المبرمج المراجع، وأحيانًا الباحث، وأحيانًا الكاتب. يؤدي التشفير الثابت لكل عملية تسليم محتملة إلى حدوث انفجار في الحافة. أنت تريد *تفاعل الوكلاء مع التجمع المشترك*، مع بعض الوظائف التي تحدد من يتحدث بعد ذلك.
هذا هو بالضبط ما يفعله AutoGen GroupChat.
## مفهوم
### الشكل
```
              ┌─── shared pool ────┐
              │   m1  m2  m3  ...  │
              └─────────┬──────────┘
                        │ (everyone reads all)
      ┌───────┬─────────┼─────────┬───────┐
      ▼       ▼         ▼         ▼       ▼
    Agent A  Agent B  Agent C  Agent D  Selector
                                           │
                                           ▼
                                  "next speaker = C"
```

يرى كل وكيل كل رسالة. يتم استدعاء وظيفة التحديد عند كل دور لاختيار من يتحدث بعد ذلك.
### النكهات الثلاثة المختارة
**دورة روبن.** دورة ثابتة. حتمية. يتم القياس بشكل خطي في N ولكنه يتجاهل السياق - يحصل المبرمج على الدور حتى عندما يكون الموضوع عبارة عن مراجعة قانونية.
**LLM-selected.** اتصال بـ LLM الذي يقرأ المجموعة الأخيرة ويعرض أفضل المتحدث التالي. مدرك للسياق ولكنه بطيء: كل دور يضيف مكالمة LLM. AutoGen الافتراضي.
**مخصص.** دالة بايثون بأي منطق تريده. نموذجي: LLM - تم تحديده باستخدام القواعد الاحتياطية (على سبيل المثال، "أعط المدقق دائمًا الدور بعد المبرمج").
### الوكيل القابل للتحدث API
```
agent = ConversableAgent(
    name="coder",
    system_message="You write Python.",
    llm_config={...},
)
chat = GroupChat(agents=[coder, reviewer, tester], messages=[])
manager = GroupChatManager(groupchat=chat, llm_config={...})
```

`GroupChatManager` يحمل المحدد. عندما يكمل الوكيل دوره، يستدعي المدير المحدد، الذي يقوم بإرجاع الوكيل التالي. تستمر الحلقة حتى حالة الإنهاء.
### الإنهاء
ثلاثة أنماط شائعة:
- **الحد الأقصى للجولات.** الحد الأقصى لعدد المنعطفات الإجمالية.
- **رمز "الإنهاء".** يمكن للوكلاء إرسال رسالة خافرة؛ يتوقف المدير عند ظهور أحدهم.
- **التحقق من الوصول إلى الهدف.** يقوم برنامج التحقق الخفيف بتشغيل كل دور وإيقاف الدردشة عند الانتهاء.
### تقسيم AutoGen → AG2 ودمج Microsoft Agent Framework
في أوائل عام 2025، بدأت Microsoft عملية إعادة كتابة رئيسية لـ AutoGen (الإصدار 0.4) حول نموذج الممثل الذي يحركه الحدث. قام المجتمع بتقسيم دلالات GroupChat الخاصة بـ AutoGen v0.2 إلى AG2، مع الحفاظ على API الذي قام المتبنون الأوائل بدمجه.
في فبراير 2026، أعلنت Microsoft أن AutoGen سينتقل إلى وضع الصيانة، مع دمج نموذج الممثل الذي يحركه الحدث في **Microsoft Agent Framework** (RC فبراير 2026، تم دمجه الآن مع Semantic Kernel). يظل مفهوم GroupChat موجودًا في كلا المسارين؛ تختلف تفاصيل التنفيذ. AG2 هو المنبع المفضل للتعليمات البرمجية المتوافقة مع الإصدار 0.2.
### عندما تكون الدردشة الجماعية مناسبة
- **المحادثات الطارئة.** لا ترغب في إجراء اتصالات مسبقة مع كل المتحدث التالي المحتمل.
- **مهام خلط الأدوار.** يسأل المبرمج الباحث، ويسأل الباحث أمين الأرشيف، ويسأل أمين الأرشيف المبرمج مرة أخرى. التدفق ليس DAG.
- **حل المشكلات الاستكشافي.** فكر في "اجتماع العصف الذهني" وليس "خط التجميع".
### عندما يفشل
- **الحتمية الصارمة.** يمكن أن يكون محدد LLM غير متناسق. نفس الموجه، جولات مختلفة، المتحدثون القادمون مختلفون.
- **شلالات التملق.** يذعن الوكلاء لمن يتحدث بثقة أكبر. مكافحة موجه صراحة.
- **السياق منتفخ.** يقرأ كل وكيل كل رسالة؛ بعد 10 دورات يصبح السياق ضخمًا. استخدم التوقعات (الدرس 15) لتحديد نطاق العروض.
- **متحدثون بارعون.** يهيمن وكيل واحد على المحادثة لأن المحدد يفضل تخصصاته. تقديم توازن السماعات كميزة اختيار.
### دردشة جماعية مقابل المشرف
نفس البدائيات، افتراضيات مختلفة:
- المشرف: أحد الوكلاء يخطط والآخرون ينفذون. المحدد هو "اسأل المخطط عما يجب فعله".
- الدردشة الجماعية: جميع الوكلاء هم أقرانهم؛ المحدد هو وظيفة على التجمع المشترك.
كلاهما يستخدم الأساسيات الأربعة من الدرس 04. الدردشة الجماعية الافتراضية هي LLM-التنسيق المحدد وحالة المشاركة الكاملة.
## بنائها
`code/main.py` ينفذ GroupChat من البداية في stdlib. ثلاثة وكلاء (المبرمج، المراجع، المدير)، متغيرات محددة من نوع round robin وLLM، وإنهاء على الرمز المميز `TERMINATE`.
يقوم العرض التوضيحي بطباعة نص المحادثة بالإضافة إلى تتبع قرار المحدد لكلا الخيارين.
يجري:
```
python3 code/main.py
```

## استخدمه
يقوم `outputs/skill-groupchat-selector.md` بتكوين محدد GroupChat لمهمة معينة - round-robin مقابل LLM-selected مقابل custom، وما هي مدخلات المحدد (الرسائل الأخيرة، تخصصات الوكيل، عدد الأدوار) المراد استخدامها.
## اشحنها
قائمة التحقق:
- **الحد الأقصى للجولات.** دائمًا. 10-20 للمهام النموذجية.
- **مقياس توازن المتحدثين.** تتبع المنعطفات لكل وكيل؛ تنبيه عندما يتجاوز الخلل حدًا معينًا.
- **رمز الإنهاء.** `TERMINATE` أو وكيل تحقق مخصص.
- **ذاكرة الإسقاط أو الذاكرة المحددة النطاق.** بعد 10 رسائل تقريبًا، فكر في منح كل وكيل عرضًا محدد النطاق فقط لمنع تضخم السياق.
- **تسجيل المحدد.** بالنسبة للمتغيرات المحددة LLM، قم بتسجيل كل من إدخال المحدد واختياره. وإلا فإن التصحيح أمر مستحيل.
## تمارين
1. قم بتشغيل `code/main.py`. قارن المحادثة ضمن round-robin مقابل LLM-المحدد. أي وكيل يهيمن تحت كل منهما؟
2. قم بإضافة قاعدة "الحد الأقصى لعدد مرات التحدث لكل وكيل" في أداة التحديد. كيف يؤثر ذلك على النص؟
3. تنفيذ إنهاء تم الوصول إليه: توقف عندما يعود المراجع بكلمة "موافق عليه". كم مرة يتم تشغيلها قبل الغطاء المستدير؟
4. اقرأ مستندات AutoGen الثابتة على GroupChat (https://microsoft.github.io/autogen/stable/user-guide/core-user-guide/design-patterns/group-chat.html). حدد المحدد الافتراضي الذي يستخدمه `GroupChatManager`.
5. اقرأ AG2 الريبو (https://github.com/ag2ai/ag2) وقارن الإصدار 0.2 GroupChat الخاص به بالإصدار v0.4 المستند إلى الأحداث. ما هي الخاصية الملموسة (الإنتاجية، والتسامح مع الأخطاء، والقابلية للتركيب) التي يضيفها الإصدار 0.4؟
