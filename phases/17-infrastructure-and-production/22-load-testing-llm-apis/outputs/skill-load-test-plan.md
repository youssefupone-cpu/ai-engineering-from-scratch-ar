نظرًا لحجم العمل (نقطة النهاية، SLA لـ TTFT/TPOT/خطأ)، ومقياس الهدف (التزامن، RPS)، والوضعية CI (PR البوابة أو الإصدار فقط)، قم بإنتاج خطة اختبار الحمل.
ينتج:
1. الأداة. LLMPerf لتشغيل خط الأساس؛ k6 + امتداد البث لبوابات CI؛ GenAI-Perf لـ NVIDIA- عمليات التشغيل المرجعية؛ دليللم للصناعية الكبيرة. LLM-الجراد فقط إذا كان موجودًا بالفعل.
2. التوزيع الفوري. يعني + stddev رموز الإدخال من حركة المرور الحقيقية (إن وجدت) أو التوزيع المنشور (ShareGPT / HumanEval). منع التكرار مع موجه واحد.
3. أربعة أنماط. ثابت، منحدر، ارتفاع، نقع. لكل: الهدف RPS، المدة، وضع الفشل المتوقع.
4. CI البوابة. الحدود المحددة: TTFT P95 < X، 5xx < 5%، TPOT < Y. وقت التشغيل لكل PR: 3-5 دقائق.
5. المحاذاة المترية. لاحظ ما إذا كانت أداة التقارير هي نمط GenAI-Perf (ITL يستبعد TTFT) أو نمط LLMPerf (ITL يتضمن TTFT). اختر واحدًا وحافظ على ثباتك.
6. الإخراج. ملف نصي (k6 JS، LLMPerf CLI) مخصص للريبو.
الرفض الصارم:
- اختبار التحميل بمطالبات موحدة. رفض - الأرقام تكذب.
- اختبار التحميل دون دعم التدفق. رفض — يتم بث نقاط النهاية LLM بشكل افتراضي.
- مقارنة الأرقام عبر الأدوات دون الاعتراف بالاختلافات في تعريف المقياس. رفض.
قواعد الرفض:
- إذا كان الفريق ينوي التشغيل على مخزون Locust بدون LLM-امتداد Locust، ارفض — GIL المصيدة.
- إذا كانت ميزانية البوابة CI أقل من 60 ثانية لكل PR، فارفض النقع الكامل — اقترح حالة ثبات سريعة بالإضافة إلى نقع ليلي منفصل.
- إذا كانت بيانات التوزيع الفوري غير متوفرة، فاطلب توزيعًا منشورًا موثقًا (ShareGPT) ولاحظ الافتراض.
المخرجات: خطة من صفحة واحدة مع الأداة، والتوزيع الفوري، وأربعة أنماط مع الأهداف، وعتبات البوابة CI، والمحاذاة المترية. انتهي بمخرج CI الفردي: PR باللون الأخضر فقط إذا تم استيفاء جميع الحدود، ثبات التشغيل 3.
